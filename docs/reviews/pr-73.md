## Suggestions

**S1 · `queries.ts` — `extractDecisionLogItems`의 `items` 분기는 도달 불가 코드**

`src/features/decision-log/queries.ts`에서:

```typescript
type DecisionLogListData = DecisionLogDto[] | { items: DecisionLogDto[] }

function extractDecisionLogItems(data: DecisionLogListData): DecisionLogDto[] {
  return Array.isArray(data) ? data : data.items
}
```

`apiGet('/decision-logs')`는 응답 envelope의 `data` 필드를 추출해 반환하므로, 쿼리 함수에서 구조분해 `const { data } = await apiGet<...>(...)` 후 `data`는 이미 `DecisionLogDto[]` 배열이다. 어댑터 테스트 fixture도 `{ data: [...], meta: {...} }` 형태를 목업해 이를 확인한다. `{ items: DecisionLogDto[] }` 분기는 현행 패턴에서 도달하지 않는다. 함수 전체를 제거하고 `data.map(adaptDecisionLog)`로 직접 인라인하는 편이 명확하다. 가령 향후 BE가 페이지네이션 래퍼 형태를 바꾸면 어차피 `apiGet` 레이어에서 처리해야 하므로 이 함수에서 보호할 이유가 없다.

**S2 · `DecisionLogPage.test.tsx` — 오류 상태 렌더 테스트 누락**

빈 목록 EmptyState 테스트는 추가됐으나(`'renders empty state when the server returns no decision logs'`), 오류 상태 분기(`decisionLogsQuery.isError ? <ErrorState ...>`)에 대응하는 테스트가 없다. 이번 PR이 오류 상태 위치를 페이지 최상단에서 테이블 카드 내부로 이동시켰으므로 회귀 방지를 위한 단언이 필요하다. 아래 형태로 추가를 권장한다:

```typescript
it('renders error state when the query fails', async () => {
  decisionLogsState = {
    data: [],
    error: new Error('서버 오류'),
    isError: true,
    isLoading: false,
  }
  renderDecisionLog()
  expect(
    await screen.findByText('판단 기록 API를 불러오지 못했습니다'),
  ).toBeVisible()
  expect(screen.queryByRole('table')).not.toBeInTheDocument()
})
```

로딩 상태(Skeleton 렌더) 테스트도 동일하게 없으나, 오류 상태가 더 중요하므로 최소한 그것부터 추가한다.

## Questions

**Q1 · "메모 (선택)" 폼 필드 처리**

`DecisionLogPage.tsx`의 `note` 필드(이전 "메모 (선택)" textarea)가 폼에서 완전히 제거됐고 `DecisionFormState`에서도 사라졌다. 설계 문서 `49-decision-log-activation.md` §7 open question 2("생성 폼의 `note` 필드 — BE `summary`로 보낼지, 미전송할지")가 "제거"로 묵시적으로 해결됐다. 이것이 의도한 최종 결정이라면 설계 문서의 해당 open question을 "MVP에서 제거, 후속 PATCH 라이프사이클 시 `summary` 연동 검토" 등으로 닫아두면 좋겠다.

**Q2 · `mockDecisionLogs`의 구조 유지 계획**

`src/shared/mock/domain.ts`의 `mockDecisionLogs`는 DashboardPage가 여전히 소비하고 있으며(→ `DashboardPage.test.tsx` 단언 변경이 이를 보여준다), 이 mock의 `decisionType` 필드가 이제 BE 10종 enum 라벨과 정렬됐다. 그러나 이 mock 객체의 나머지 형태(`id: 'decision-nvda-001'`(string), `decision`, `outcome`, `reviewDate` 등)는 `DecisionLog` 도메인 타입과 다른 별도 형태다. Dashboard의 판단 기록 섹션이 실제 API로 전환될 시점에 이 mock의 잔여 필드들이 타입 불일치를 일으킬 수 있으니, 전환 전에 타입 명시를 정리해두는 것을 권장한다.
