# PR #42 Local Review — Loading/Empty/Error 상태 컴포넌트 (이슈 18)

## Review Summary

이슈 18. 공통 상태 컴포넌트 `Skeleton`/`EmptyState`/`ErrorState`(재시도 포함)를
`src/shared/ui`에 추가하고, 페이지마다 산재하던 ad-hoc 빈 상태를 공통 `EmptyState`로 수렴했다.
설계 `docs/designs/18-status-components.md`와 일치. 마일스톤 3 두 번째 라운드이자 #17(API client)
의 토대다.

검토 항목:

- **컴포넌트 API·컨벤션 일관성**: 3종 모두 기존 `app-*` 토큰·`Button`/`Card`/`classNames` 컨벤션
  준수. barrel(`shared/ui/index.ts`) re-export(add-only). 공통 컴포넌트 우선 원칙 부합, 네이티브
  다이얼로그 없이 인앱 UI.
- **결정성**: `Skeleton`은 `animate-pulse` CSS만 사용(JS 애니메이션 없음 → jsdom 결정성).
  `TZ=UTC pnpm test` 71/71 통과.
- **접근성**: `Skeleton` 장식 `aria-hidden`, `EmptyState` `role="status"`(비긴급), `ErrorState`
  `role="alert"`(즉시 안내) + `onRetry` 지정 시에만 재시도 `Button` 렌더. 의미 역할 분리 적절(#20 사전 정렬).
- **빈 상태 수렴 완전성**: Research `EmptyResearchState`·Watchlist/Signals 인라인 "없습니다" 텍스트가
  공통 `EmptyState`로 치환. 표시 텍스트 의미 동등 유지. `Table.emptyMessage`(ReactNode)는 하위 호환
  유지로 강제 치환 안 함 — 설계대로.
- **범위 분리 준수**: 로딩/에러 실제 트리거 연결은 #17로 분리, 가짜 async 미도입. `Skeleton`/
  `ErrorState`는 완성·단위 테스트된 채 제공. 도메인/Mock 무변경.
- **테스트**: 신규 5건(Skeleton 2: 기본 블록/`lines` 분기, EmptyState 1: title/desc/icon/action/role,
  ErrorState 2: 기본 alert+버튼 없음/`onRetry` 버튼+클릭 콜백). 66 → 71.

## Suggestions

- **Research 빈 상태 헤딩 시각 축소(경미)**: 기존 `EmptyResearchState`는 `<h1>`(text-3xl)였으나
  공통 `EmptyState`는 `<h2>`(text-lg)로 표준화됐다. 의미·테스트(레벨 무관 heading 조회)상 문제 없고
  표준화가 바람직하나, 전체화면 빈 상태에서 제목이 작아진 시각 변화가 있다. 의도된 표준화로 보이며
  비차단. 필요 시 `EmptyState`에 크기 변형(예: `size`)을 후속 도입할 여지(이월).
- **`Skeleton`/`ErrorState` 미적용(설계대로 이월)**: 두 컴포넌트는 아직 페이지에 연결되지 않았다.
  현재 동기 mock에 로딩/에러 흐름이 없어 #17에서 쿼리 상태에 연결하는 것이 맞다(비차단, 의도된 분리).
