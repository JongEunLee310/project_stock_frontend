## Review Summary

BE #322에서 리서치 요약이 mock 템플릿에서 LLM 실생성·저장 구조로 전환되면서, `GET
/assets/{id}/research-summary`가 저장본이 없으면 `404 RESEARCH_SUMMARY_NOT_FOUND`를 반환하도록
바뀌었습니다. 이 PR은 그 계약 변경에 FE 세 지점을 맞춥니다.

`queries.ts`에 신설된 `fetchResearchSummary`는 기존 `fetchLatestThesis`와 동일한 패턴으로
`apiGet` 호출을 try/catch로 감싸고, `error.code === 'RESEARCH_SUMMARY_NOT_FOUND'`일 때만 `null`을
반환하며 그 외 에러는 그대로 재던집니다. `useResearchView`의 `Promise.all`에서 기존
`apiGet(...).then(...)` 호출을 이 함수로 교체해, 저장본이 없는 종목에서도 `Promise.all` 전체가
reject되지 않고 나머지 세 조회(detail·buy-checklist·thesis)가 정상 진행됩니다.

`adapters.ts`의 `adaptResearchDetail`은 `summary` 인자를 `ResearchSummaryDto | null`로 받도록
시그니처가 바뀌었고, `stance`·`stanceConfidence`·`stanceComment`·`confidenceBasis`·
`counterPoints`·`keyRisks` 여섯 필드의 접근이 모두 `summary?.field ?? default`로 보정됐습니다.
`briefing`은 별도 `ResearchBriefing` 인터페이스로 분리되어 `ResearchView.briefing: ResearchBriefing
| null` 타입이 되었고, `summary`가 `null`이면 `briefing` 필드 자체가 `null`이 됩니다(과거처럼 `headline:
'리서치 요약 없음'` 같은 placeholder 객체를 만들지 않음).

`ResearchPage.tsx`는 `research.briefing`이 `null`인지로 분기해, 있으면 기존 헤드라인·본문·세
그룹(긍정 요인/주의 요인/다음 확인 사항) 렌더를 그대로 유지하고, 없으면 `EmptyState` + "AI briefing
생성" 버튼을 렌더합니다. 버튼은 신설된 `useRefreshResearchSummary(symbol, assetId)` mutation의
`mutate`를 호출하며, `isPending`이면 "생성 중..."으로 비활성화되고 `isError`면 `role="alert"` 에러
문구를 보여줍니다. mutation은 성공 시 `queryClient.invalidateQueries({ queryKey: ['research',
normalizedSymbol] })`로 `useResearchView`와 정확히 같은 쿼리 키를 무효화해 재조회를 트리거합니다.
`갱신 {createdAt}` 표기도 `research.briefing`이 있을 때만 렌더하도록 감싸져 `null` 접근이
제거됐습니다.

리서치 큐(`toResearchQueueView`)는 이번 diff에서 손대지 않았습니다. 설계 문서(§1.3)가 이미 "큐는
방어적이므로 확인·회귀 테스트 보강만 한다"고 명시한 대로, `ResearchListPage.test.tsx`에 nullable
stance/headline 행이 예외 없이 렌더되는 회귀 테스트만 추가됐습니다.

## 검증 포인트별 확인

- **404 흡수 정확성** — `fetchResearchSummary`의 catch 조건은 `error instanceof ApiError &&
  error.code === 'RESEARCH_SUMMARY_NOT_FOUND'`로 코드 문자열까지 좁혀져 있어 과잉 흡수가 없습니다.
  `queries.test.tsx`의 두 테스트가 이를 직접 대조합니다. "keeps the research view available when no
  saved summary exists"는 `RESEARCH_SUMMARY_NOT_FOUND`를 던졌을 때 `data?.briefing`이 `null`이고
  `data?.price`·`data?.buyChecklist` 등 다른 필드는 정상 값으로 채워짐을 확인하고, "does not absorb
  other research summary errors"는 같은 엔드포인트가 `ASSET_NOT_FOUND`를 던지면 흡수하지 않고
  `result.current.error`가 `ApiError`이자 `code === 'ASSET_NOT_FOUND'`로 그대로 전파됨을 확인합니다.
  설계 §1.1·핸드오프 요구 사항 1과 정확히 일치합니다.
- **어댑터 nullable 보정 누락 여부** — `adapters.ts` diff를 필드 단위로 대조한 결과 `stance`·
  `stanceConfidence`·`stanceComment`·`confidenceBasis`·`counterPoints`·`keyRisks` 여섯 곳 모두
  `summary?.field` 형태로 일괄 보정되어 있고 누락이 없습니다. `adapters.test.ts`에 추가된 "returns
  summary-derived fallbacks when no saved summary exists" 테스트가 `summary=null`일 때 `briefing`이
  `null`, `stance`가 `'판단 보류'`, 나머지 파생 필드가 `null`/`[]`로 떨어지는지, 그리고
  `buyChecklist`(요약과 무관한 필드)는 영향받지 않는지까지 확인합니다.
- **저장본 있는 기존 종목 회귀** — `research.briefing`에 대한 접근은 `ResearchPage.tsx` 전체에서
  1697·1699·1703·1706·1709·1714·1718·1722행 여덟 곳뿐이며, 모두 `research.briefing ? ... : ...`
  분기 안쪽에 있어 가드되지 않은 접근이 없습니다. `renders all structured briefing groups as bullet
  lists`(기존 통과 테스트)가 저장본 있는 종목 렌더가 그대로 유지됨을 재확인합니다.
- **refresh mutation 쿼리 키 일치** — `useRefreshResearchSummary`의 `onSuccess` 무효화 키
  (`queries.ts:392`)와 `useResearchView`의 쿼리 키(`queries.ts:401`)가 둘 다 `['research',
  normalizedSymbol]`이고, 두 훅 모두 동일한 `symbol.trim().toUpperCase()` 정규화를 거칩니다.
  `ResearchPage.tsx`에서도 두 훅에 같은 `displaySymbol`이 전달되어 키가 정확히 일치합니다.
  `refreshes the summary and invalidates the normalized research query` 테스트가 `' nvda '` 같은
  비정규화 입력에도 `apiPost`가 정확한 경로로 호출되고 `invalidateQueries`가 `['research',
  'NVDA']`로 호출됨을 확인합니다. 다른 파생 쿼리(`['research', 'analyst-opinions', assetId]` 등)는
  키 접두어가 달라 함께 무효화되지 않는데, 이는 설계 §5.1이 명시한 범위(research 상세만 재조회)와
  일치합니다.
- **빈 상태 UI·로딩·에러** — `EmptyState` + 버튼 렌더, `isPending` 시 "생성 중..." 비활성화,
  `isError` 시 `role="alert"` 문구가 `renders the empty briefing state and starts summary
  generation`·`shows an inline error when summary generation fails` 두 테스트로 각각 고정됩니다.
  `갱신 {createdAt}`도 같은 테스트에서 `queryByText(/^갱신 /)`가 없음을 확인해 `null` 접근 제거를
  검증합니다.
- **스코프 통제** — 변경 12개 파일 중 프로덕션 코드는 `queries.ts`·`adapters.ts`·
  `ResearchPage.tsx`·`mock/domain.ts`·`model/domain.ts` 5개로 핸드오프 Implementation Scope와
  정확히 일치합니다. `App.test.tsx`·`WatchlistPage.test.tsx`는 `@/features/research/queries` 모듈을
  통째로 mock하는 기존 방식이라 신설 export `useRefreshResearchSummary`의 스텁 추가가 불가피한
  변경이고, briefing 카드 레이아웃·헤더 재생성 버튼 등 Out of Scope 항목은 diff에 없습니다.
- **설계 이탈 2건** — PR 본문에 기록된 두 이탈 모두 근거가 확인됩니다. 큐 `headline` 컬럼
  미추가는 설계 §1.3이 애초에 "큐는 방어적이므로 확인만 한다"고 명시해 이탈이라기보다 설계
  범위를 그대로 따른 것에 가깝습니다. structured briefing 배열의 `?? []` 방어(`positiveFactors`
  등)는 `dto.ts`의 `ResearchSummaryDto.positive_factors?: string[] | null`가 원래 optional/nullable
  이라 이번 PR 이전부터 있던 방어 코드이며, 제거하지 않고 유지한 판단은 합리적입니다.

## Final Recommendation

**Blocking 없음 — 머지 가능.** 404 흡수가 `RESEARCH_SUMMARY_NOT_FOUND`로 정확히 좁혀져
`ASSET_NOT_FOUND`는 과잉 흡수 없이 전파되고, 어댑터의 nullable 보정이 여섯 필드 모두 누락 없이
적용됐으며, `research.briefing` 접근이 전부 가드되어 저장본이 있는 기존 종목 렌더에 회귀가
없습니다. refresh mutation의 무효화 쿼리 키가 상세 쿼리 키와 정확히 일치함을 정규화 입력
테스트로 확인했고, 빈 상태·로딩·에러 UI와 큐 nullable 회귀까지 핸드오프 Test Requirements 4개
항목이 모두 실제 테스트로 대응됩니다. 설계 이탈 2건도 근거가 확인되고 PR 본문에 기록되어
있습니다.

**최종 머지 권한은 개발자에게 있습니다.**
