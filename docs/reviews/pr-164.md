## Review Summary

이슈 #163의 구현입니다. BE 과거 이벤트 이력 계약(`GET /assets/{asset_id}/events?range=`)을
소비해 리서치 상세 가격 차트에 실적 발표 마커를 표시하는 변경으로 구성됩니다.
변경 범위는 13개 파일이며, 신규 파일 없이 기존 파일만 갱신합니다.

구현 흐름은 다음과 같습니다. `dto.ts`에 `AssetEventDto`·`AssetEventHistoryDto`를 추가하고,
`adapters.ts`에 `adaptAssetEvents`(parseDecimal 적용·라벨 구성)와
`snapEventsToChartPoints`(event_date 이하 최근접 거래일 스냅)를 추가합니다.
`queries.ts`의 `useAssetEvents`는 adapter를 직접 호출해 `AssetEventItem[]`을 반환합니다.
`LineChart.tsx`에 additive `markers?` prop을 추가하여 `ReferenceDot` custom shape로 렌더하며,
`ResearchPage.tsx` 가격 모드에서만 마커를 전달하고 벤치마크 모드에서는 전달하지 않습니다.

## Suggestions

**S1. 1D 모드에서 "실적 발표" 범례가 계속 노출됩니다**

`ResearchPage.tsx` 338~344행의 "실적 발표" 범례 항목은 가격 차트 div 안에
항상 포함되어, range='1D'일 때 이벤트 쿼리가 disabled임에도 범례에 마커 항목이
표시됩니다. 설계 문서가 이 경우 범례 표시 여부를 명시하지 않으므로 기능 버그는
아니지만, 마커가 전혀 없는 상태에서 "실적 발표" 범례가 보이면 사용자 혼란을 줄 수
있습니다. `range !== '1D'` 조건을 추가해 범례와 쿼리 enabled 조건을 일치시키는 것을
후속 개선으로 검토하시기 바랍니다. 심각도: 비차단·후속 개선 권장.

**S2. `formatEps`에 `toLocaleString('en-US')` 로케일 고정 의존이 있습니다**

`adapters.ts` 359행의 `formatEps`는 `toLocaleString('en-US', { maximumFractionDigits: 2 })`를
사용합니다. 테스트 환경에서 Node.js ICU 데이터가 전체 로케일을 지원하지 않으면
서프라이즈 포맷이 깨질 수 있습니다. 현재 테스트는 통과하므로 실제 문제는 없지만,
`toFixed(2)` 기반 순수 포맷 함수로 교체하면 로케일 의존을 제거할 수 있습니다.
심각도: 비차단·선택적 개선.

## Coverage

설계 Test 절 대비 커버리지를 확인했습니다.

어댑터 단위 테스트(`adapters.test.ts`)는 전부 null 라벨·estimate만 null·
eps_actual 있고 estimate null·surprise 음수·전체 조합의 라벨 구성을 검증합니다.
parseDecimal 적용 여부는 eps 픽스처가 `string | null`로 작성되어 있어 암묵적으로
확인됩니다. 스냅 경계 케이스는 발표일=거래일(`event_date='2026-07-06'` → 포인트
그대로 스냅), 비거래일→직전 거래일(`event_date='2026-07-05'` → `'2026-07-03'`),
범위 이전 제외(`event_date='2026-07-01'` → null, 마커 없음), 겹침 유지(동일
event_date 2개 → 마커 2개) 모두 커버됩니다.

`LineChart.test.tsx`는 markers prop 전달 시 `aria-label` 노출과 `tabindex="0"`,
`<title>` 텍스트를, 미전달 시 기존 렌더 불변을 확인합니다.

`ResearchPage.test.tsx`는 가격 모드에서 `aria-label` 마커 존재, 범례 "실적 발표"
텍스트 존재, 벤치마크 모드 전환 후 마커 부재 및 쿼리 `enabled=false` 전달,
이벤트 쿼리 실패 시 가격 차트 정상 렌더를 검증합니다.

픽스처는 eps 3종이 `"1.52"`, `"1.48"`, `"2.70"` 등 BE 실계약 Decimal 문자열
형태이고, `event_type: "EARNINGS"` 영문 enum, event_date 오름차순을 준수합니다.
수치 단언에 `# BE #282의 Decimal 문자열 픽스처를 number로 변환한 기대값이다`
주석이 있어 출처가 명확합니다. `asset_id`는 `detail.id` 참조를 사용해 리터럴
단언을 피하고 있습니다.
