## Review Summary

이슈 14. `/portfolio` 플레이스홀더를 실제 포트폴리오 화면으로 교체하고, 이를 위해 `Portfolio`/`Holding`
도메인 타입과 `mockPortfolio`를 확장했다. 설계 `docs/designs/14-portfolio-page.md`와 대체로 일치한다.
마일스톤 3 세 번째 라운드.

검토 항목:

- **도메인·불변식**: `Holding`에 `name`/`sector`/`dailyChangePercent`, `Portfolio`에 `cash`/`dayChangeValue`/
  `dayChangePercent`/`aiBriefing`/`riskExposures` 추가, `PortfolioRiskExposure` 신규(`RiskLevel` 재사용).
  `totalValue == Σ holdings.currentValue`(= 99,510,000) 불변식 유지 — 기존 `domain.test` 단언 보존 + 신규
  필드 단언 보강. 현금은 `cash`로 분리, 총 자산 = `totalValue + cash`.
- **파생값 위치**: 종목 비중·섹터 익스포저 합산·집중도·현금 비중을 모두 페이지(`getHoldingWeights`/
  `getSectorExposure`)에서 파생. mock에 계산값을 굽지 않은 설계 원칙 준수.
- **공통 컴포넌트 재사용**: `DonutChart`(자산 배분, #19에서 이월된 포트폴리오 도넛 배치)·`BarChart`(섹터)·
  `LineChart`·`Table<Holding>`·`Badge riskLevel`·`EmptyState`(빈 보유)·`Card`. 신규 프레젠테이션 컴포넌트
  없음(페이지 로컬 헬퍼만). `cockpit-*` 토큰으로 자매 셸 페이지와 일관.
- **결정성**: 모든 차트 명시 `width`/`height`(jsdom), `ResponsiveContainer` 미사용·`isAnimationActive=false`
  유지. 금액/퍼센트는 `Intl.NumberFormat('ko-KR')`(타임존 비의존). `TZ=UTC pnpm test` 76/76.
- **테스트성**: `PortfolioPageView({ portfolio })`를 분리 export해 props 주입으로 테스트(빈 보유 케이스 포함).
- **테스트**: 신규 5건(헤딩·요약 카드, 배분·섹터·집중도 라벨, 리스크 뱃지·브리핑, 보유 테이블 비중·research
  링크, 빈 상태). domain.test 단언 보강. 71 → 76.

## Suggestions

- **리스크 노출 목록 중복 렌더(권장)**: `portfolio.riskExposures`가 "리스크 노출 분석" 카드와 "포트폴리오
  AI 브리핑" 패널 양쪽에 동일한 4개 article로 2회 렌더된다(`PortfolioPage.tsx` L507·L578). 같은 화면에서
  동일 목록 반복이라 정보 밀도가 떨어진다. 브리핑 패널은 상위 1~2건 또는 요약 형태로 줄이는 것을 권장(이월).
- **설계 대비 범위 추가(비차단)**: 설계의 요약 카드 3종 대비 4번째 "리스크 집중도" 카드와 "성과 추이" 패널이
  추가됐다. 운영 화면 충실화로 합당하나 설계 문서·이슈 완료 조건엔 없던 항목이다. `performanceTrend`(30포인트)와
  `riskScore` 휴리스틱(`38 + highRiskCount*12 + topThreeShare/3 - cashRatio/4`, L135)은 페이지 로컬 합성값/
  매직넘버로 실데이터·근거가 없다. 후속에서 mock 파생으로 옮기거나 산식 근거를 문서화하는 것을 권장.
- **요약 도넛 하드코딩(경미)**: "현금 비중" 요약 카드의 장식 `DonutChart` 데이터가 `22.7`/`77.3` 하드코딩
  (L176, `aria-hidden` 장식). 현재 mock의 실제 현금 비중 22.7%와 우연히 일치하나 mock 변경 시 드리프트
  가능 — 파생 `cashRatio` 사용을 권장(이월).
