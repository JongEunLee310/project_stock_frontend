# PR #116 — 환율 표시와 원화 병기 (feat/115-fx-display)

리뷰어: value-for-fable:itsvff (Sonnet, VFF 위임). 구현: Codex. 브랜치: feat/115-fx-display → main. 관련: FE #115, 핸드오프 task-043. 리뷰 대상 커밋: 19fb035 하나 (`git diff origin/main...feat/115-fx-display`).

## Review Summary

PR #116은 이슈 #115에서 요청된 두 가지 기능을 구현합니다. 첫째, 사이드바 `<MarketSummary />` 위에 USD/KRW 환율 스트립(`FxRateStrip`)을 삽입해 전 페이지에서 환율을 상시 표시합니다. 둘째, 관심종목 테이블의 현재가 셀에서 `currency === "USD"`인 행에만 원화 환산을 병기합니다.

변경된 파일은 17개이며 신규 코드 580줄로 구성됩니다. `src/features/fx/`를 새로 신설해 `ExchangeRateDto`, `FxRate` 어댑터(`adaptFxRates`, `findFxRateByPair`), `useFxRates` 쿼리를 추가합니다. Decimal 파싱은 `parseDecimal`을 그대로 사용하며, 쿼리 구조는 기존 `market-indices` 패턴(`apiGet` + `adaptFxRates`, staleTime 미설정)을 그대로 따릅니다. `FxRateStrip.tsx`는 `useFxRates`를 직접 호출하며 로딩·오류·정상의 세 상태를 모두 처리합니다. `WatchlistPage.tsx`도 동일한 `useFxRates`를 호출하므로 쿼리 키 `['market', 'fx']`를 공유하고 React Query의 중복 제거가 적용됩니다. `watchlist/dto.ts`에 `currency?: string | null`, `watchlist/adapters.ts`에 `currency` 필드 전달이 추가되고, `WatchlistPage.tsx`의 현재가 셀 렌더링이 `<span>` 래퍼 구조로 재구성되어 병기 텍스트를 수용합니다.

원화 환산은 `Math.round(usdPrice × usdKrwRate)` 후 `ko-KR` 로케일 `Intl.NumberFormat`(maximumFractionDigits: 0)을 적용해 `≈ ₩180,208` 형태로 표시합니다. 환율 오류 시에는 `usdKrwRate`를 `undefined`로 처리해 병기를 생략하고 달러 가격만 유지합니다.

## Suggestions

**S1: `currency: null` 행에 대한 WatchlistPage 원화 병기 억제 테스트가 없습니다**

`WatchlistPage.test.tsx`의 fixture에는 Tesla(`currency: null`, price: 182.64)가 포함되어 있습니다. "shows converted KRW only for USD current prices" 테스트는 NVIDIA(USD → 병기 표시)와 Apple(KRW → `≈ ₩300,020` 미표시)만 명시적으로 단언하고, Tesla(null → 미표시)에 대한 단언은 없습니다. 코드 로직 자체는 정확합니다(`null === 'USD'`는 false). 그러나 Test Requirements는 "비USD(KRW) 행 병기 없음"으로 KRW 케이스만 명시하고 있어 currency null 케이스의 테스트 커버리지가 작게 남습니다. 후속 이슈로 Tesla 행에 대한 `queryByText('≈ ₩…')` 단언을 추가하면 회귀 감지가 더 견고해집니다.

위치: `src/pages/ui/WatchlistPage.test.tsx` — "shows converted KRW only for USD current prices" 테스트 (Tesla 행 단언 추가)

**S2: `formatChangePercent` 함수가 `FxRateStrip.tsx`와 `MarketSummary.tsx` 두 파일에 동일하게 중복됩니다**

두 파일 모두 `formatPercent(changePercent / 100, 2)` 후 양수일 때 `+`를 앞에 붙이는 완전히 동일한 함수를 각자 정의합니다. 현 PR 스코프를 초과하므로 즉시 수정할 필요는 없으나, 향후 `src/shared/lib/format/decimal.ts`로 추출하면 표기 일관성을 코드 수준에서 보장할 수 있습니다. 후속 이슈로 처리를 권장합니다.

위치: `src/widgets/FxRateStrip.tsx:12-15`, `src/widgets/MarketSummary.tsx:10-13`

**N1: 변동률 색상 임계값(`>= 0`)과 `+` 부호 임계값(`> 0`) 사이에 미세한 불일치가 있습니다**

`changePercent === 0`일 때 색상은 emerald green(`>= 0`)이지만 부호는 `+`가 없이 `"0.00%"`로 표시됩니다. `MarketSummary.tsx`가 동일한 패턴(`isPositive = item.changePercent >= 0`)을 사용하므로 의도적 설계 선택으로 보입니다. 기능 정확성에 영향이 없으므로 Nit으로 기록합니다.

위치: `src/widgets/FxRateStrip.tsx:40-44`

## Final Recommendation

**현 상태로 머지를 권장합니다.**

핸드오프 Requirements 5개 항목이 모두 충족됩니다. 환율 조회 실패가 관심종목 테이블을 깨뜨리지 않으며(`usdKrwRate`를 undefined로 처리해 병기를 생략), 원화 표기는 `ko-KR` 로케일 천 단위 구분에 소수점 없음이 적용됩니다. `FxRateStrip`과 `WatchlistPage`가 동일한 `useFxRates` 쿼리를 공유하므로 중복 호출이 없고, 비USD·currency null 행에는 병기가 없습니다. Decimal 파싱은 market-indices 패턴과 일치합니다. Test Requirements 5개 항목이 테스트로 커버되고 검증 4종이 315개 통과했습니다. S1(currency null 테스트 보강)·S2(formatChangePercent 중복)·N1(색상/부호 임계값)은 기능 정확성에 영향을 주지 않으므로 후속 이슈로 처리해도 무방합니다.
