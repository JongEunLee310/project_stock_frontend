# PR #97 — 시그널 카드 스파크라인 활성화 (feat/signals-sparkline-wiring)

리뷰어: Claude Code (Opus, 오케스트레이터). 구현: Codex. 브랜치: feat/signals-sparkline-wiring → main. 관련: FE #90, 설계 78, Pair BE #159·PR #160(머지됨).

## Review Summary

설계 78대로 `SignalsPage`의 카드 스파크라인을 실 가격 시계열(`GET /stocks/{symbol}/prices`)로
활성화했습니다. BE #160으로 노출된 `asset.market`을 도메인에 매핑하고, 비활성 상태였던
`useSignalSparkline`을 `symbol`·`market`을 받아 활성화했으며, 각 시그널 카드가 컴포넌트
레벨에서 자신의 시계열을 조회하도록(per-row) 조정했습니다.

`useSignalSparkline(symbol, market)`은 `enabled: Boolean(symbol && market)`으로 market이 없으면
호출하지 않고, `GET /stocks/{symbol}/prices?market={market}&range=1M&interval=1d`를 호출해
`PriceSeriesDto.bars`의 `close`를 `parseDecimal`로 변환·`null` 필터하여 `number[]`로 반환합니다.
queryKey `['signals','sparkline',symbol,market]`로 동일 종목 중복 렌더 시 요청이 dedup됩니다.

설계의 결정이 모두 반영됐습니다: (1) 기존 signals 슬라이스 확장, (2) `SignalDto.asset.market`·
`PriceSeriesDto{bars}` 정렬(bare array 가정 제거), (3) `Signal.market` 추가·`sparkline` 도메인
필드 제거, (4) `adaptSignal`/`adaptSignalDetail` sparkline 인자 제거, (5) per-row 활성화·range `1M`
고정, (6) 행 단위 degradation(loading→Skeleton, market 없음·error·빈 데이터→placeholder 유지,
데이터→Sparkline).

## Blocking

None.

## Suggestions

**S1 · per-row 요청(N+1, 비차단, 설계상 수용)**

표시된 카드 수(N)만큼 `useSignalSparkline` 호출이 발생합니다. React Query가 동일 queryKey를
dedup하므로 동일 종목은 요청 1회로 수렴하고, 지연·캐시·행 단위 degradation의 이점이 있습니다.
BE에 배치 시계열 엔드포인트가 없어 per-row가 실용적 선택이며, 배치 엔드포인트 추가 시 재검토
대상입니다. 설계 §4에 명시된 수용된 트레이드오프로 비차단입니다.
