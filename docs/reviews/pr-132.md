## Review Summary

시그널 페이지를 디자인(signal.png)에 맞추는 4단계 로드맵의 1단계입니다. 기존
`useSignals`·`useSignalSparkline`과 `Signal` 뷰 모델을 그대로 쓰면서 화면 구조만 재설계하고,
BE 신규 계약이 필요한 요소는 "준비 중" 자리표시로 처리해 후속 phase 연결 지점을 남깁니다.

핵심 신설은 `src/features/signals/signalCategories.ts`입니다. `SignalCategory` 타입,
`SIGNAL_CATEGORY_MAP`(6개 signal_type → 4개 카테고리), `CATEGORY_META`(라벨·색상 토큰·아이콘),
`categoryOf` 헬퍼를 한 파일에 모아 KPI·필터·카드·레일이 단일 소스를 참조합니다. 매핑은
설계 표(관망유지←WATCH / 리스크증가←RISK_ALERT+THESIS_BROKEN / 매수검토가능←BUY_CANDIDATE /
추가리서치필요←SELL_REVIEW+OVERHEATED)와 리터럴이 일치하며 6개 enum을 모두 커버합니다.
매핑에 없는 값은 `categoryOf`가 `undefined`를 반환하고 카드·레일에서 배지를 생략합니다.

`SignalsPage.tsx`는 KPI 5카드(총 시그널 + 4카테고리 카운트·비율), 필터 4축(카테고리·신뢰도
구간·시장·검색 + 초기화), 카드 재구성(카테고리 배지·`ConfidenceRing`·1M 등락률·버튼 3개),
우선순위 레일(상위 6·순위·심볼·배지·신뢰도), 최근 변경 placeholder로 재구성됐습니다.
`ScoreRing`은 `ConfidenceRing`으로 개명되어 색상 결정을 `risk_level`에서 카테고리 기준으로
바꾸면서 `role="meter"`와 aria 속성은 보존했습니다. 시장 목록은 `Signal.market`에서 동적으로
파생하고(`flatMap(... ?? [])`로 null 제거), 신뢰도 구간 경계값(high≥70/mid40–69/low<40)은
코드 주석으로 명시했습니다.

## Suggestions

**S1. 검색 대상에서 `reason`이 빠져 카드 본문 텍스트로는 검색되지 않습니다**

기존 구현은 `symbol`·`signalTypeLabel`·`reason`을 검색 대상으로 삼았는데, 이번 변경은
`symbol`·`companyName`으로 좁혔습니다. 설계 문서 §Filter State Model이 명시한 규칙과
일치하므로 의도된 변경이며, 회사명 검색이 추가된 만큼 실사용 편의는 유지됩니다. 다만
근거 문구로 찾던 사용 흐름이 있었다면 사라지므로, 후속에서 근거 불릿 구조화(phase 3)를
연결할 때 검색 대상 확장을 함께 검토하면 좋겠습니다. 심각도: 비차단·후속 검토.

**S2. 카드에서 만료 시각 표시가 제거되었습니다**

기존 카드 하단의 "만료 {expiresAt}" 블록이 디자인 레이아웃 정렬 과정에서 제거되고 1M
등락률 영역으로 대체됐습니다. `Signal.expiresAt` 필드 자체는 유지되고 디자인에도 만료
표시가 없어 정합하지만, 만료가 임박한 시그널을 구분하던 정보가 화면에서 사라집니다.
디자인 기준으로는 정상이며, 만약 만료 강조가 제품상 필요하면 별도 요소(예: 배지)로
후속 검토할 수 있습니다. 심각도: 비차단·정보성.

토큰은 설계 문서와 컴포넌트 테스트로 확인했으나, 실제 렌더링을 디자인과 픽셀 단위로
대조하지는 않았습니다. 머지 전 시각 확인이 필요하면 전체 스택 기동 후 대조할 수 있습니다.

## Review Summary

  칩으로 보여주는 것은 구조 접근이 필요하므로 후속(근거 불릿, 로드맵 3단계)으로 이월합니다.

나머지 3가지는 이 PR 범위 밖으로 분리했습니다 — 비구조 근거 문장은 로드맵 3단계(BE 근거
