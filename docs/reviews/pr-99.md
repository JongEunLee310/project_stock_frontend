# PR #99 — 관심 종목 요약 스파크라인 실데이터 연동 (feat/watchlist-summary-sparkline-wiring)

리뷰어: Claude Code (Opus, 오케스트레이터). 구현: Codex. 브랜치: feat/watchlist-summary-sparkline-wiring → main. 관련: FE #96, 설계 80, 미러 선례 77(대시보드 추이)·78(시그널 스파크라인), BE 계약 #161.

## Review Summary

설계 80대로 `WatchlistPage` 요약 카드의 하드코딩 상수 `summaryLineSeries`를 제거하고 신규 BE
계약 `GET /watchlists/{watchlist_id}/summary/trends`에 실데이터로 연동했습니다. 응답 와이어
형태가 동형인 대시보드 추이 슬라이스의 dto·adapter·query 패턴을 watchlist 도메인에 독립
이식했으며, 대시보드 코드를 import하지 않습니다.

`dto.ts`에 추이 타입 3종을 독립 선언하고, `adapters.ts`의 `getWatchlistTrendCounts`는 대시보드
`getTrendCounts`를 그대로 미러해 계열별 count 배열을 추출합니다(키 부재·빈 계열 모두 빈 배열).
`adaptWatchlistSummaryTrends`는 `watchlist_total`·`risk_increasing` 두 계열을 뷰의 각 필드로
매핑합니다.

`useWatchlistSummaryTrends`는 기존 `useWatchlistSummary`의 방어 패턴을 동일하게 따라 첫
watchlist를 조회한 뒤 그 id로 `summary/trends?days=14`를 요청하고, 목록이 비었거나 API 오류이면
try/catch로 빈값(`{ watchlistTotal: [], riskIncreasing: [] }`)을 반환합니다. 첫 watchlist 조회가
`useWatchlistSummary`와 중복되지만 React Query가 동일 URL을 dedup하므로 네트워크 요청은 1회로
수렴합니다.

`SummaryVisual`은 훅 데이터를 소비하도록 재작성됐고, index 0 카드는 `watchlistTotal`, index 1
카드는 `riskIncreasing` 계열을 사용합니다. 열화는 슬롯 단위로 처리됩니다.

## Suggestions

**S1 · 첫 watchlist 조회 중복(비차단, 설계 근거)**

`useWatchlistSummaryTrends`와 `useWatchlistSummary`가 각각 `GET /watchlists?page=1&size=20`를
독립 호출합니다. React Query 캐시 dedup으로 실제 네트워크는 1회이며, 설계 §4에서 공유 훅 분리
리팩터를 명시적으로 비범위로 두었습니다. 후속 여지가 있는 비차단 사항입니다.
