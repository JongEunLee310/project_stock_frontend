# PR #291 로컬 리뷰 — 뉴스 인사이트 개요 패널 배치 설계 정합 (#285·#286)

## Review Summary

3차까지 모든 패널이 실제 데이터로 채워진 뒤 설계 이미지(`news-instight.png`)와 화면을 대조해
개요 화면(`/news`)의 배치를 맞춘 PR입니다. 커밋은 두 건입니다. Codex 구현
(`61b5721 뉴스 인사이트 개요 패널 배치 정렬`)과 리뷰 과정에서 리뷰어가 보탠 정리
(`38a2f03 개요 하단 4열 비율과 수치 줄바꿈을 정리한다`)입니다. 데이터 계약과 쿼리는 건드리지
않았고 배치와 노출 방식만 바뀌었습니다.

**Part A — AI Agent 브리핑 상시 패널화(#285).** `AgentBriefing`은 그동안
`fixed bottom-6 right-6`의 플로팅 버튼이었고 기본 상태가 닫힘이었습니다. 페이지 최하단에서
`<section>` 바깥에 렌더돼 관제탑 화면의 1차 정보가 클릭 한 단계 뒤에 있었습니다. 이번에
플로팅 래퍼, `useState(open)` 토글, 하이라이트 개수 배지, 닫기 버튼(`FiX`), `role="dialog"`를
걷어내고 다른 패널과 같은 `Card`로 바꿨습니다. 상단은
`RealtimeEventFeed | AgentBriefing | TopicMap` 3열이며 폭은
`xl:grid-cols-[minmax(0,1.6fr)_minmax(0,1fr)_minmax(0,1fr)]`입니다. 근거 건수 배지
(`근거 N건`)와 `PanelFreshness`, 패널 단위 로딩·오류·빈 상태는 모두 살아 있습니다.

**Part B — 하단 4패널 한 행 재배치(#286).** 기존에는 `투자자 동향`(전폭) →
`예상 자금 흐름`(전폭) → `이벤트 타임라인 | 에이전트 파이프라인`(2열)으로 3행에 걸쳐
있었습니다. 이번에 네 패널을 한 행에 놓았고, 반응형은 `xl` 2열, 그 미만 1열입니다. `2xl`
폭 비율은 설계 이미지의 패널 폭을 그대로 옮긴 `1:1:1:1.8`이라 에이전트 파이프라인이 더
넓습니다. 좁아진 폭에 맞춰 네 패널의 내부 그리드를 조정했고, `min-w-0`을 카드와 헤더
컨테이너에 넣어 긴 문자열이 열을 밀어내지 않게 했습니다.

이번 리뷰는 계약·수치 불변 여부, 부분 실패 격리 유지, 접근성 속성 정리의 타당성, 좁아진
열에서의 렌더 안정성을 축으로 봤습니다.

## Suggestions

**S1. `InvestorFlowPanel`의 `spanFullRow` prop — 임시 조치, #287에서 제거 예정.** 이 위젯은
원래 `xl:col-span-3`을 클래스에 직접 들고 있었습니다. 개요에서는 부모가 flex라 이 클래스가
무시됐지만, 이번에 부모가 grid가 되면서 실제로 3열을 먹게 됐습니다. Codex는 `spanFullRow`
prop을 열어 개요에서만 끄는 방식으로 처리했습니다. 위젯이 자기 배치를 알고 있다는 점에서
바람직한 형태는 아니지만, 지금 클래스를 걷어내면 토픽 상세 화면의 현재 배치가 함께 깨집니다.
토픽 상세를 명시적 3열로 재구성하는 #287에서 `xl:col-span-3`과 이 prop을 같이 없애는 것이
맞습니다. 병합을 막지 않습니다.

**S2. 상세 링크는 이벤트 타임라인에만 — 라우트 부재에 따른 의도적 생략.** 설계에는 하단 네
패널 모두에 상세 링크가 있습니다. 이번에는 이벤트 타임라인의 토픽 링크만 유지했고, 그마저
문자열 조립을 `generatePath(appRoutePaths.newsTopicDetail, { topicId })`로 바꿨습니다. 투자자
동향·예상 자금 흐름·에이전트 파이프라인은 대응하는 전용 라우트가 `appRoutePaths`에 없어
생략했습니다. 없는 경로를 만들어 붙이면 빈 화면으로 보내게 되므로 생략이 맞습니다. 해당 상세
화면이 생기면 그때 링크를 답니다.

**S3. 파이프라인 단계 카드의 다열 복원 — 리뷰어가 직접 수정.** Codex는 좁은 열을 고려해
`AgentPipelinePanel`의 집계 3열과 단계 7열을 모두 단일 열로 낮췄습니다. 그대로 두면 집계 3건과
단계 7건이 세로로 쌓여 이 패널만 다른 세 패널보다 크게 높아지고, grid 행 전체가 그 높이를
따라갑니다. 설계에서 이 패널이 더 넓고 단계가 가로로 놓이는 이유도 같습니다. 열 비율을
`1:1:1:1.8`로 바꾸면서 집계는 `sm:grid-cols-3 2xl:grid-cols-2`, 단계는
`sm:grid-cols-2 md:grid-cols-4 xl:grid-cols-2 2xl:grid-cols-3`으로 복원했습니다.

**S4. 수급 금액의 `break-all` 제거 — 리뷰어가 직접 수정.** Codex가 좁은 열 대응으로 넣은
`break-all`은 `formatNetValue`가 만드는 `4,812,000,000원` 같은 공백 없는 문자열을 숫자 중간에서
끊습니다. 부모가 이미 `flex-wrap`이라 금액은 필요하면 통째로 다음 줄로 내려갑니다.
`whitespace-nowrap`으로 바꿔 숫자가 쪼개지지 않게 했습니다.

## Questions

**Q1. 브리핑이 다이얼로그에서 패널로 바뀌면서 접근성이 후퇴하지 않았는가.** 확인해 해소했습니다.
제거된 것은 다이얼로그 성격의 속성(`role="dialog"`, `aria-labelledby`가 가리키던 다이얼로그
제목, 토글 버튼의 `aria-expanded`)이고, 이는 더 이상 다이얼로그가 아니므로 남아 있으면 오히려
잘못된 정보입니다. 패널로서 필요한 `aria-labelledby`는 유지되고, 로딩 상태의 `role="status"`와
`sr-only` 안내, 오류 상태의 재시도 버튼도 그대로입니다. 상시 노출로 바뀌었으므로 토글 없이
읽히는지를 검증하도록 `AgentBriefing` 테스트를 갱신했습니다.

**Q2. 부분 실패 격리가 유지되는가.** 확인해 해소했습니다. 브리핑은 `overviewQuery`를 요약
카드와 공유하므로 실패 시 두 영역이 함께 오류 상태가 되지만, 이는 이번 PR이 만든 결합이 아니라
`GET /news-insights/overview`가 요약과 브리핑을 한 응답으로 주는 기존 계약에서 옵니다. 피드
(`eventsQuery`)와 토픽 맵(`topicMapQuery`)은 별도 쿼리라 브리핑 실패와 무관하게 렌더되고, 각
패널이 자기 재시도 버튼을 갖습니다.

**Q3. 브라우저에서 실제로 어떻게 보이는지.** 해소하지 못했습니다. 이 환경에는 렌더링을 확인할
수단이 없어 열 비율과 내부 밀도는 설계 이미지의 패널 폭과 마크업 근거로 판단했습니다. `2xl`
폭에서 하단 네 패널의 높이 균형은 개발자가 화면에서 한 번 확인해 주시는 편이 확실합니다.

머지 가능합니다. 핸드오프의 요구를 항목별로 확인했습니다. 브리핑은 `/news` 진입 즉시 클릭 없이

범위는 지켜졌습니다. `src/features/news-insights/queries.ts`는 변경되지 않아 API 호출·쿼리
키·폴링 주기가 그대로이고, 패널이 표시하는 값의 계산과 포맷도 손대지 않았습니다. 4열로 좁아졌다는
이유로 수치를 반올림하거나 단위를 바꾼 곳은 없습니다. 토픽 상세 페이지와 전용 위젯, 헤더 액션,
면책 푸터, `PlannedPanelCard` 제거는 후속 이슈(#287~#290)로 남겨 이 PR에 섞이지 않았습니다.
Protected Files는 없으며 diff는 개요 페이지, `AgentBriefing`, 하단 네 패널과 각 테스트에
한정됩니다.

테스트는 브리핑이 토글 없이 바로 읽히는지, 로딩·오류·빈 상태가 유지되는지를 덮습니다. 개요
페이지 테스트도 새 배치에 맞춰 갱신됐고, 셀렉터가 깨졌다는 이유로 삭제된 단언은 없습니다.

Blocking은 없습니다. S1은 #287에서 함께 정리할 후속 사항이고, S2는 라우트 부재에 따른 의도적
생략이며, S3·S4는 리뷰 중 리뷰어가 직접 수정했습니다. Q1·Q2는 확인해 해소했고, Q3은 렌더
확인 수단이 없어 개발자 확인이 필요한 항목으로 남깁니다.
