## Review Summary

`git diff main...HEAD` 기준 4개 파일이 바뀝니다: `docs/designs/180-selected-state-tone.md`(신규),
`src/shared/ui/Button.tsx`(+3/-1), `src/shared/ui/Button.test.tsx`(신규),
`src/pages/ui/ResearchPage.tsx`(+7/-7). 설계 문서(`docs/designs/180-selected-state-tone.md`)에
기술된 범위와 정확히 일치합니다.

`Button.tsx`는 `ButtonVariant`에 `selected`를 추가하고
`border-app-accent/40 bg-app-accent/15 text-app-accent hover:bg-app-accent/25
focus-visible:outline-app-accent` 클래스를 부여합니다. 기존 `primary`
(`bg-app-accent-strong` 원색 면 채움)와 별개 variant이므로 다른 화면의
`primary` 사용처에는 영향이 없습니다. `ResearchPage.tsx`에서 `primary` →
`selected` 교체는 설계 문서가 명시한 7곳(기간 버튼, 벤치마크 토글, 차트 탭
3종, 뉴스/공시 탭 2종)과 정확히 일치하며, 이외 `primary` 사용처(774행,
관심종목 즐겨찾기 토글 `isFavorite ? 'primary' : 'secondary'`)는 변경되지
않았습니다. `docs/designs/180-selected-state-tone.md`가 명시한 "CTA용
primary는 값·사용처 모두 유지" 원칙이 diff에서 실제로 지켜졌습니다.

아리아 속성은 variant 문자열만 바뀌고 손대지 않았습니다. `aria-pressed`
(기간 버튼·벤치마크 토글), `aria-selected`(차트 탭·뉴스/공시 탭) 관련
기존 테스트(`ResearchPage.test.tsx` 788·926·931·946·1195·1214·1215·1223·
1381·1382·1407행)는 클래스가 아닌 속성값을 단언하므로 이번 변경과 무관하게
그대로 통과합니다.

대비(contrast) 검토: `--color-app-accent: #38bdf8`, 버튼이 놓이는
`Card`의 배경은 `--color-app-surface: #111827`(`Card.tsx` 12행)입니다.
`bg-app-accent/15`를 이 배경에 합성하면 실효 배경은 대략 `rgb(23, 49, 70)`이고,
텍스트 `text-app-accent(#38bdf8)`와의 대비비는 약 6.27:1로 계산됩니다.
WCAG AA 일반 텍스트 기준(4.5:1)을 여유 있게 충족합니다. hover
(`bg-app-accent/25`) 상태의 실효 배경 `rgb(27, 65, 91)`에서도 대비비는
약 5.02:1로 기준을 유지합니다. 다만 `border-app-accent/40`을 카드 배경에
합성한 테두리 색은 카드 배경 대비 약 2.4:1로, WCAG 1.4.11(비텍스트 UI
컴포넌트 경계, 3:1 권장) 기준에는 못 미칩니다. 다만 이 패턴은 이번 PR이
새로 만든 것이 아니라 기존 accent 배지(`src/shared/ui/stockStatus.ts`
46행 `border-app-accent/40 bg-app-accent/15 text-app-accent`)와 동일
계열이며, 선택 상태를 인지시키는 주 신호는 텍스트·배경의 색 대비(6.27:1,
충분)이고 테두리는 보조 신호이므로 blocking으로 보지 않습니다.

선택/비선택 위계: `ghost`(비선택)는 `text-app-text-muted`(중립 회색)에
투명 배경이고, `selected`는 accent 톤 배경 + accent 텍스트이므로 색상
계열 자체가 달라 위계가 유지됩니다. `ghost`의 hover 상태
(`bg-app-surface-muted/60`, 중립 회색)와도 색조가 구분되어 hover 중인
비선택 탭과 선택된 탭이 혼동되지 않습니다.

`Button.test.tsx`는 `selected` variant 렌더 시 5개 클래스
(`border-app-accent/40`, `bg-app-accent/15`, `text-app-accent`,
`hover:bg-app-accent/25`, `focus-visible:outline-app-accent`)를 정확히
검증하는 단일 테스트입니다. 클래스 문자열 오탈자나 variant 매핑 누락을
잡아낼 수 있는 실질적인 회귀 테스트입니다.

## Suggestions

`border-app-accent/40`의 카드 배경 대비 대비비가 약 2.4:1로 WCAG
1.4.11 권장치(3:1)에 못 미치는 점을 위 Review Summary에 기록했습니다.
다만 이는 기존 accent 배지에서도 동일하게 쓰이는 확립된 패턴이고 텍스트
대비는 충분하므로, 이번 PR 범위에서 별도 수정을 요구하지는 않습니다.
후속으로 accent 계열 테두리 불투명도를 전반적으로 조정할 계획이 있다면
그때 함께 다루는 편이 일관성 있어 보입니다.
