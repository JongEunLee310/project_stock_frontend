# PR #101 — BE↔FE 응답 계약 정렬 (research stance 표시 정정, FE #101)

리뷰어: Claude Code (Opus, 오케스트레이터). 구현: Codex. 브랜치: feat/fe-101-contract-alignment → main. 관련: FE #101, BE #163(PR #165 병합), 설계 82, 핸드오프 task-039.

## Review Summary

BE #163(PR #165) 병합으로 BE 응답이 FE DTO 목표 형태에 맞춰진 뒤, FE를 재검증해 남은
research-summary 표시 버그 2건을 정정했습니다. DTO 형태 정렬(MeDto·AssetDetailDto·
BuyChecklistDto·ReportDto·ThesisDto·AlertDto)은 FE가 이미 목표 형태를 갖고 있어 BE 병합만으로
정합 상태가 되었고, 본 PR은 표시 계층에 남은 두 건만 다룹니다. 신규 BE 계약 변경은 없습니다.

- **stance 라벨 매핑**: BE가 내려주는 `BUY_CANDIDATE`·`WATCH` 와이어 값을 `researchStanceLabels`로
  `매수 후보`·`관찰`에 매핑합니다. 표기는 기존 `alertTypeLabels`와 일관됩니다.
- **stance_confidence 정규화**: BE가 계약으로 확정한 0~1 분수(`"0.72"`)를 adapter의
  `normalizeStanceConfidence`에서 0~100(`72`)으로 정규화합니다. `ResearchPage`의
  `Math.round(x)%` 렌더는 그대로 두어 `1%`로 잘못 표시되던 값이 `72%`로 정정됩니다.

## 범위 확인

설계 82 §4의 변경 파일 목록과 일치합니다. 스코프를 벗어난 변경(다른 도메인 adapter, BE 응답,
`ResearchPage` 레이아웃, 방어 fallback 일괄 제거)은 없습니다.

- `src/features/research/adapters.test.ts`·`enumLabel.test.ts` — 실제 와이어 값 기준 갱신

테스트가 약화되지 않았습니다. `매수 후보`/`72` 매핑 단언, null stance→`판단 보류`,
invalid confidence→`null` fallback 2경로, `researchStanceLabels` 단언이 추가되어 정정 동작을
직접 검증합니다. 기존 fixture의 `stance: 'Constructive'`·`stance_confidence: '65'`는 실제 BE
값(`BUY_CANDIDATE`·`"0.72"`)으로 교체되어, 이전에 불일치를 가리던 fixture가 제거되었습니다.

## 관찰 사항 (비차단)

1. **fallback 처리 방식**: null·unknown stance는 `toLabel(..., '판단 보류')`로, 파싱 실패
   confidence는 `null`로 유지됩니다. BE mock이 현재 2종만 반환하므로 unknown 경로는 방어용이며,
   BE가 stance enum을 확장하면 `researchStanceLabels` 항목 추가가 필요합니다.
2. **정규화 위치**: `stance_confidence` ×100을 adapter로 한정하고 표시 계층은 건드리지
   않았습니다. 계약(0~1 분수)이 바뀌지 않는 한 표시 계층 회귀 위험이 없습니다.

## ADR / 실패 기록

- ADR 불필요: 기존 enum 라벨 매핑·adapter 정규화 관례를 따르는 표시 정정입니다. 계약 기준
  결정(BE 확정)은 BE 설계 064에 기록되어 있습니다.
- 실패 기록 불필요.
