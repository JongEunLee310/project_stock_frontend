# PR #272 로컬 리뷰 — 뉴스·공시 개요 계약 연동 (#200)

## Review Summary

뉴스·공시 인텔리전스(에픽 #198) FE 1차의 계약 연동으로, 개요 셸(#199)의 로컬 mock을 BE `GET /overview`·`/events`(cursor) 실연동으로 교체합니다. 브랜치는 #199(#271) 위에 스택돼 있으나 PR base는 main이며 커밋은 1건입니다.

`src/features/news-insights/`에 `dto.ts`(와이어 타입)·`adapters.ts`(Dto→View 매핑)·`queries.ts`(react-query 훅)를 기존 `features/research` 패턴대로 추가했습니다. `useNewsOverviewQuery`는 `useQuery`로 KPI 4종·브리핑을, `useNewsEventsQuery`는 `useInfiniteQuery`로 이벤트 피드를 cursor pagination(fetchNextPage·hasNextPage)으로 가져옵니다. 페이지는 패널별 독립 query를 배선하고, 각 위젯(`InsightSummaryCards`·`AgentBriefing`·`RealtimeEventFeed`)에 `isLoading`·`isError`·`onRetry`를 개별 전달해 한 패널 오류가 다른 패널을 깨지 않게 합니다. cursor 지원을 위해 `shared/api`의 `envelope`·`client`·`paging`을 하위호환 제네릭으로 확장했습니다.

이번 리뷰는 계약 연동의 정확성, 패널별 부분 실패 격리, 공용 `shared/api` 확장의 하위호환성을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 공용 `shared/api`(envelope·client·paging) 확장 — 하위호환 제네릭, 회귀 없음 확인.** cursor 메타를 위해 `ApiEnvelope`·`unwrapEnvelope`·`apiRequest`·`apiGet`를 `TMeta extends ApiResponseMeta = ApiMeta` 제네릭으로 바꾸고, `paging`에 `buildCursorSearchParams`·`toCursorPageInfo`를 추가했습니다. `TMeta` 기본값이 `ApiMeta`라 기존 `apiGet<T>()`·`unwrapEnvelope()` 호출은 시그니처가 보존되고, paging 추가분은 순수 additive입니다. 다른 feature의 회귀는 전체 테스트(721)·typecheck 통과로 확인했습니다. BE의 cursor 지원 core 확장과 대칭이며 후속 조치는 불필요합니다.

**S2. 이벤트 피드 `useInfiniteQuery` 채택 — cursor 계약에 부합.** offset 대신 cursor를 쓰는 BE 계약에 맞춰 `useInfiniteQuery` + `next_cursor`/`has_more`로 load-more를 구성했습니다. 설계의 "offset 금지" 요구에 부합합니다.

## Questions
