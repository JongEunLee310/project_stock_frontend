## Review Summary

시그널 재설계 로드맵(전략 A)의 마지막 단계로, 1단계가 "준비 중"으로 남긴
자리 4곳을 BE 실계약으로 연결합니다. 설계 문서
(`docs/designs/135-signal-redesign-phase4.md`)의 계약을 충실히 따랐습니다.

- **view=current 전환** — `useSignals`에 view 파라미터(기본 'all')가 추가되고
  queryKey에 포함됩니다. SignalsPage만 'current'를 사용하므로
  DashboardPage는 동작이 변하지 않으며, 해당 테스트가 수정 없이 통과합니다.
- **KPI** — `SignalKpiRow`가 클라이언트 집계 대신 `/signals/summary` 응답을
  사용합니다(페이지네이션 절단에 안전). delta는 `+n`/`-n`/`±0`, summary
  로딩·오류 시 `—` 폴백이 테스트로 고정됐습니다. 총 시그널의 전일 대비는
  BE에 없는 값이라 카테고리 delta 합으로 파생하는데, 6개 signal_type이 모두
  4축에 매핑되므로 타당한 파생입니다.
- **변화 컬럼·최근 변경 레일** — direction 6값의 표기·색상이 설계 매핑 표와
  일치합니다(ESCALATED `▲ +n` 적색, DEESCALATED `▼ -n` 녹색, `change: null`
  → `—`). 타임라인 행은 심볼 링크·direction 라벨·dominant 카테고리
  배지·snapshot 날짜로 구성되고, CLEARED(`dominant: null`)와 빈 상태 문구도
  커버됩니다.
- **근거 불릿** — 카드 본문이 `keyPoints` 불릿 목록으로 렌더되고 빈 배열이면
  `reason` 문단으로 폴백하며, 동시 표시가 없음을 테스트가 단언합니다. BE
  리뷰(pr-261.md) S2에서 예고한 폴백 규칙이 이 PR로 확정됐습니다.

변경 불가 파일(`signalCategories.ts`, `DashboardPage.tsx`)은 손대지
않았습니다.

## Suggestions

**S1. `Signal.keyPoints`·`change`의 optional 타입이 계약보다 느슨합니다**

`adaptSignal`이 두 필드를 항상 채우는데(`key_points` 누락 → `[]`, `change`
누락 → `null`) 뷰 모델 타입은 `keyPoints?: string[]`·`change?: SignalChange |
null`로 선언되어 있습니다. 이 때문에 카드 렌더에 불필요한 `signal.keyPoints
&&` 가드가 생겼습니다. 필수 필드(`keyPoints: string[]`, `change: SignalChange
| null`)로 조이면 소비처 가드가 사라지고 어댑터 계약이 타입에 드러납니다.
심각도: 비차단·저비용 개선.

**S2. msw 핸들러 항목은 저장소 구조상 적용되지 않았습니다**

설계·핸드오프가 지시한 msw 핸들러 갱신은 이 저장소에 msw 계층이 없어 적용
대상이 없었고, 테스트는 기존 관례대로 `apiGet` mock 수준에서 신규 계약을
커버합니다. 구현 판단이 옳았으며 조치는 불필요합니다. 실제 BE와의 통합
확인은 화면 검증(스냅샷 job 실행 후)으로 대체합니다. 심각도: 비차단·정보성.
