## 1. 계약 필드 매핑 정확성

**합격.** 전 도메인에 걸쳐 snake_case DTO → camelCase 도메인 변환이 BE 계약과 1:1로 정확하다.

- **Signal**: `asset_id→assetId`, `signal_type→signalType`, `risk_level→riskLevel(string|null)`, `is_expired→isExpired`, `expires_at→expiresAt`, `created_at→createdAt`. BE `SignalResponse`의 모든 필드 대응 완료.
- **AssetBrief**: `change_percent→changePercent`, `sector` 옵셔널 → `null` 정규화. `AssetDetailDto`와 분리 구현 확인.
- **StockViewModel**: `AssetDetailDto.id→assetId`, G7 nullable 펀더멘털 6개 필드 모두 `parseNullableDecimal`로 처리. `as_of→asOf`.
- **Alert/AlertCandidate**: 모든 enum 와이어 값이 BE와 일치. `candidate_type→candidateType`, `asset_id→assetId`.
- **PortfolioSummary**: `cash_weight→cashWeight` BE 계산값 직접 수용 확인. 클라이언트 파생 로직 없음. `sector_weights→sectorWeights`.
- **PriceSeries**: `adjusted_close→adjustedClose`, `last_updated_at→lastUpdatedAt` 정확.

한 가지 주목할 점: `Signal.symbol` 필드 할당이 `dto.symbol ?? dto.asset?.symbol ?? ''`로 되어 있다. BE `SignalResponse`에는 `symbol` 필드가 없으므로 `dto.symbol`은 항상 `undefined`이고, expand 없이는 `dto.asset`도 null이어서 결과는 항상 `''`이다. 이는 의도된 동작(빈 문자열 → cold-start fallback이 처리)이지만, `Signal` 도메인 타입에서 `symbol: string`이 필수 필드로 선언되어 있어 빈 문자열이 "값 있음"으로 오해될 수 있다. 경미 — 기능에 영향 없음.

## 2. date 오프바이원 차단

**합격, 완벽하게 구현.**

`priceSeriesAdapter.ts` 9번 줄: `date: dto.date` — 문자열 그대로 통과. `new Date()` / `Date.parse()` 호출 없음. `src/shared/` 전체에 `new Date` / `Date.parse` 사용 없음(grep 확인).

`lastUpdatedAt: dto.last_updated_at`으로 UTC Z 문자열을 그대로 보존한다. KST 변환은 표시 계층 몫으로 남겨두어 설계 의도에 부합한다.

`vite.config.ts`에 `test.env.TZ: 'UTC'` 추가 확인. 날짜 단언 테스트가 TZ=UTC 환경에서 실행된다.

테스트(`priceSeriesAdapter.test.ts`)에서 `date: '2026-06-24'`가 변환 없이 그대로 반환되는지 직접 단언하고 있다.

## 3. cold-start fallback

**합격, 3단계 fallback 완전 구현.**

`signal.ts`의 `getSignalDisplaySymbol` 함수 (65–84번 줄):

1. `signal.asset?.symbol` 있으면 반환 (expand 지원 시)
2. `assetSymbolsById.get(signal.assetId)` 있으면 반환 (기존 로드 목록 활용)
3. `signal.symbol` 있으면 반환 (BE가 직접 symbol 내려준 경우)
4. `signal.assetId > 0`이면 `String(assetId)` 반환, 아니면 `'-'` 반환

cold-start 진입 시(asset 목록 없음, expand 없음) `assetId`를 문자열로 표시하거나 `'-'`를 반환하는 동작이 확인됐다. 설계 요건 충족.

테스트에서 세 케이스(asset 있음 → 'TSLA', fallback 맵 → 'NVDA', cold-start → '-')를 모두 단언하고 있다.

## 4. 범위 완결성

**의도된 분리로 판정 — #47 완결.**

pages/entities/features/widgets 네 레이어는 현재 README.md 파일만 있고 실제 화면 컴포넌트가 존재하지 않는다. 구 모델(`kind/confidence/trendSeries`, `AlertRule`, 한글 enum `StockStatus` 등)을 참조하는 화면 코드 자체가 없으므로 "구 모델이 고아로 남아 화면에서 여전히 참조"되는 상황이 발생하지 않는다.

`docs/designs/6-domain-types-and-mock-data.md` 상단에 "Superseded by FE#47" 문구 추가 확인.

구 도메인 타입 파일(`shared/model/domain.ts` 등)이 존재하지 않는다 — task-004(이슈 6)에서 정의된 구 타입이 어디 있는지 확인이 필요한데, 현재 `src/shared/model/` 내에는 신규 5개 파일만 존재하고 구 타입 파일이 없다. 이는 task-004가 워킹트리에 실제 파일을 생성하지 않은 상태였거나, Codex가 없는 파일을 삭제하지 않고 신규로만 생성했음을 의미한다. 어느 쪽이든 결과는 동일하다 — 구 모델 잔존 없음, 신 모델만 존재.

화면 연결(entities/features 내 실제 컴포넌트가 신 도메인 타입을 임포트하는 단계)은 #48 범위이며, 이는 설계에서 명시한 의도된 분리다.

## 5. AssetBrief 공용 설계 / parseDecimal nullable 처리

**합격.**

`AssetBriefDto`와 `AssetBrief`는 `stock.ts`에 정의되고, `adaptAssetBrief`는 `assetAdapter.ts`에서 `adaptAssetDetail`과 같은 파일에 분리된 함수로 존재한다. `signalAdapter.ts`가 `adaptAssetBrief`를 직접 임포트해 재사용하고 있어 watchlist·signals expand 공용 설계가 구현됐다.

`parseNullableDecimal`이 `decimal.ts`에 정의되어 있고 G7 nullable 펀더멘털 6개 필드 모두 적용됐다. `parseDecimal`은 `Number.isFinite` 검사로 잘못된 Decimal 문자열을 즉시 throw한다 — 경계 방어 적절.

## 발견된 갭 / 수정 권장 사항

### 경미 (기능 영향 없음)

**G1 — `Signal.symbol` 필수 타입 vs 빈 문자열 의미론**
위치: `src/shared/model/signal.ts` 42번 줄 `symbol: string`

BE `SignalResponse`에 `symbol` 필드가 없고 expand 없이는 항상 빈 문자열이 할당된다. `symbol: string`이 필수 필드이면 뷰레이어 개발자가 `.symbol`을 직접 사용해도 타입 오류가 나지 않아 cold-start 시 빈 문자열이 그대로 렌더될 위험이 있다. `getSignalDisplaySymbol`을 통해서만 symbol을 표시하도록 강제하는 네이밍 컨벤션 또는 `symbol` 필드를 `string | undefined`로 변경하고 `getSignalDisplaySymbol`을 필수 경로로 만드는 것을 #48 화면 연결 시 검토할 것.

**G2 — `parseDecimal`에 `undefined` 입력 방어 없음**
위치: `src/shared/lib/format/decimal.ts`

`Number(undefined)`는 `NaN`이고 `Number.isFinite(NaN)`은 false이므로 throw가 발생한다. 이 경우 에러 메시지가 `"Invalid decimal value: undefined"`로 나와 디버깅에 혼란을 줄 수 있다. DTO 타입이 `string`으로 엄격하게 정의되어 있으므로 런타임 도달 가능성은 낮지만, 향후 `adaptAssetBrief`에 불완전한 BE 응답이 들어올 때를 위해 메시지를 명확히 하거나 `undefined` 케이스를 별도 처리하는 것을 검토.

### 정보 (조치 불필요)

**I1 — `SignalDto.score` 타입이 `string | number`**
BE `SignalResponse`의 `score`는 `int`이므로 와이어에서 항상 `number`다. 그러나 `signalAdapter`에서 `typeof dto.score === 'number' ? dto.score : Number(dto.score)`로 방어적 처리를 했다. 불필요한 방어이지만 해롭지 않다. 타입을 `number`로 좁히는 것은 #48 이후 BE 계약이 안정됐을 때 정리.

**I2 — Alert/AlertCandidate KST 표시 변환 없음**
`adaptAlert`·`adaptAlertCandidate`는 `createdAt: dto.created_at`으로 UTC Z 문자열을 그대로 통과시킨다. 설계 의도대로 KST 변환은 표시 계층 몫이므로 문제 없음. #48에서 화면 컴포넌트 작성 시 KST 포맷 helper 사용 여부를 확인할 것.
