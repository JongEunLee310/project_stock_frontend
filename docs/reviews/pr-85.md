# PR #85 — AI 브리핑 카드 BE 연동 (feat/ai-briefing-wiring)

리뷰어: Claude Code (Opus, FE 트랙). 구현: Codex. 브랜치: feat/ai-briefing-wiring → main.

## Review Summary

설계 74 범위대로 대시보드·포트폴리오 페이지의 AI 브리핑 카드를 mock에서 BE 브리핑 API 실데이터로 교체했습니다. 공통 `src/features/briefing/` 슬라이스를 신설해 `AiBriefingDto`(headline·body·risk_headline·risk_checks?·generated_at)를 `adaptAiBriefing`으로 매핑합니다. 어댑터는 snake→camel 변환, `risk_checks ?? []` 방어, falsy `risk_headline` 생략, `generated_at` 폐기를 수행하는 순수 함수입니다. `useDashboardBriefing`은 `/dashboard/briefing`을, `usePortfolioBriefing`은 `/portfolios?page=1&size=20`로 첫 포트폴리오를 해소한 뒤(없으면 `null`) `/portfolios/{id}/briefing`을 호출합니다. 포트폴리오 id 해소 순서는 기존 `usePortfolioSummary`와 동일합니다. DashboardPage는 `mockAiBriefing`을, PortfolioPage는 `mockPortfolio.aiBriefing`을 제거하고 각각 쿼리에 연동했으며, PortfolioPage는 브리핑 UI를 `PortfolioBriefingPanel`로 분리했습니다. 두 페이지 모두 로딩 시 `Skeleton`, 에러/미배포 시 `EmptyState`(mock 복귀 없이 안내), 빈 `riskChecks` 시 리스크 섹션 생략, 포트폴리오 없음 시 패널 비노출로 degradation합니다. mock 정의는 `shared/mock`에 유지하고 "BE 출처 없어 mock 유지" 주석을 제거했습니다.

## Blocking

None.

## Suggestions

**S1 · 브리핑 패널 prop 타입**

`PortfolioBriefingPanel`이 `UseQueryResult`를 직접 받지 않고 구조적 `BriefingPanelState` 인터페이스(data·error·isError·isLoading·refetch)를 받도록 분리했습니다. 뷰가 React Query 구현에 덜 결합되고 페이지 테스트에서 mocking이 쉬워집니다. 비차단(설계 판단으로 수용).

**S2 · degradation 카피**

에러 상태 문구를 "브리핑 API가 준비되면 다시 표시됩니다."로 통일했습니다. BE 미배포와 일시 에러를 구분하지 않으나 현 단계에서 과한 분기는 불필요합니다. 비차단.
