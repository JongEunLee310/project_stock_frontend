# PR #98 — 리서치 가격 라인차트 활성화 (feat/research-price-chart-wiring)

리뷰어: Claude Code (Opus, 오케스트레이터). 구현: Codex. 브랜치: feat/research-price-chart-wiring → main. 관련: FE #95, 설계 79, Pair BE #159·PR #160·FE #90·PR #97(모두 머지됨).

## Review Summary

설계 79대로 `ResearchPage`의 `PriceSparkline` 라인차트를 실 가격 시계열(`GET /stocks/{symbol}/prices`)로
활성화했습니다. FE #90(signals)에서 확립된 패턴을 research 슬라이스에 동형으로 적용해 전용
쿼리 `useResearchPriceSeries(symbol, market)`를 추가하고, `useResearchView`의 하드코딩 빈 배열
sparkline과 `ResearchView.priceSparkline` 필드를 제거했습니다.

`useResearchPriceSeries`는 `enabled: Boolean(symbol && market)`으로 market이 없으면 호출하지
않고, `GET /stocks/{symbol}/prices?market={market}&range=3M&interval=1d`를 호출해
`PriceSeriesDto.bars`의 `close`를 `parseDecimal`로 변환·`null` 필터하여 `number[]`로 반환합니다.
research는 단일 종목 상세라 N+1이 없어 최대 1회 호출됩니다.

설계의 결정이 모두 반영됐습니다: (1) research 슬라이스 확장, (2) `PriceSeriesDto{bars}` 추가,
(3) `ResearchView.priceSparkline` 제거·`adaptResearchDetail` sparkline 인자 제거(market 매핑 유지),
(4) 전용 쿼리·range `3M`(research 라인차트 특성상 넓은 구간), (5) 차트 슬롯 degradation
(loading→Skeleton, market 없음·error·빈 데이터→placeholder 유지, 데이터→LineChart).

## Blocking

None.

## Suggestions

**S1 · range 3M 고정(비차단, 설계 근거)**

signals(#90)는 `1M`, research는 `3M`을 사용합니다. research 상세의 주 시각화라 넓은 구간이
맥락상 유의미하다는 설계 §4 근거에 따른 선택으로, range 선택 UI가 추가되면 상태로 교체할
여지가 있습니다. 현 단계 비차단입니다.
