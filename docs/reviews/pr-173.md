## Review Summary

이슈 #167(에픽 #152)에 따라 `src/pages/ui/ResearchPage.tsx`의 `HeaderCard`
내부 구성만 바꾼 변경입니다. `git diff main...HEAD --stat` 기준으로도
`docs/designs/167-research-header-density.md`와 `ResearchPage.tsx` 두 파일만
바뀌었고, `ResearchPage.tsx` 안에서도 diff hunk가 모두 `HeaderCard` 함수
범위(727~835행) 안에 머물러 있어 카드 밖 변경은 없습니다.

설계 문서의 변경 항목과 diff를 하나씩 대조했습니다. 현재가 블록은 타일
박스(`border bg-app-surface-muted`)를 제거하고 `text-3xl` 큰 숫자 +
색상 등락 텍스트로 바뀌었고, `aria-label="현재가"`·`aria-label="등락"`은
그대로 유지되어 있습니다. 지표 5종(시가총액·섹터·52주 범위·다음 실적
발표·평균 목표주가)도 타일 카드가 사라지고 `dt`/`dd` 텍스트 그리드
(`sm:grid-cols-3`)로 바뀌었으며, `metricTiles` 배열의 5개 항목은 diff
전후로 동일해 데이터 필드 누락은 없습니다. AI 투자 스탠스 박스는 유일하게
박스 형태를 유지하고, 이전에는 `Badge`가 신뢰도를 담고 스탠스는 별도
문단이었던 구성이 이번 PR에서 `Badge`가 스탠스를, 인접한 `span`이 신뢰도
텍스트를 담는 구성으로 뒤바뀌었습니다. 이는 이슈 #167의 수용 기준
"AI 투자 스탠스만 작은 박스(스탠스 배지 + 신뢰도)로 유지"와 정확히
일치합니다. `confidenceBasis`·`stanceComment`도 조건부 렌더링 그대로
유지됩니다. `Badge` 컴포넌트(`src/shared/ui/Badge.tsx`)는 순수 `span`이고
별도 ARIA role을 부여하지 않으므로, 스탠스 텍스트가 배지 안으로 들어가도
스크린리더가 읽는 내용(스탠스 텍스트, 신뢰도 텍스트)은 이전과 동일하게
전달되어 접근성 회귀는 없다고 판단합니다. 버튼 3종도 `min-h-8 px-3 py-1
text-xs`로 축소되었을 뿐 동작·핸들러는 그대로입니다.

다만 diff에는 설계 문서에 명시되지 않은 변경이 하나 있습니다. `HeaderCard`
내부 4열 grid의 마지막 열 폭이 `minmax(19rem,1.4fr)`에서
`minmax(24rem,1.6fr)`로 넓어졌습니다. 설계 문서 3절(변경)에는 타일 제거·
배지 승격·버튼 축소만 기술되어 있고 이 grid 폭 조정은 언급이 없습니다.
아래 Blocking 항목에서 이 변경이 xl 브레이크포인트 부근에서 실제로
오버플로를 유발하는지 코드 상수 기반으로 계산했습니다.

## Blocking

**B1. xl 브레이크포인트(1280px) 직후 구간에서 헤더 grid가 가로로
넘칠 가능성이 있습니다**

`AppShell.tsx`(11행)의 사이드바는 `lg:grid-cols-[16rem_minmax(0,1fr)]`로
1024px 이상에서 256px 고정폭을 차지하고, `main`(16행)은
`lg:px-5`(좌우 20px)를 더합니다. `HeaderCard`를 감싼 `Card`는
`p-panel`(`--spacing-panel: 1rem`, 좌우 32px)을 씁니다. 이 프로젝트는
Tailwind v4를 `@theme`로만 커스터마이즈하고(`src/index.css`) 브레이크포인트
재정의가 없어 `xl`은 기본값 1280px, `gap-5`는 1.25rem(20px)입니다.

viewport 1280px(=xl 브레이크포인트가 막 켜지는 지점) 기준으로 grid가 실제
쓸 수 있는 폭을 역산하면 `1280 - 256(사이드바) - 40(main 좌우 패딩) -
32(Card 좌우 패딩) = 952px`입니다. 반면 바뀐 4열 grid의 최소 폭 합은
`12rem + 10rem + 12rem + 24rem = 58rem = 928px`이고 열 사이 gap 3개
(`gap-5 × 3 = 60px`)를 더하면 `988px`이 필요합니다. `minmax(min, max)`의
`min`은 하드 플로어라 컨테이너가 좁아도 그 아래로 줄지 않으므로, 952px
공간에 988px가 필요한 이 구간(약 36px 부족)에서는 grid가 `Card`와
콘텐츠 영역 밖으로 넘치게 됩니다. 오버플로가 사라지는 지점은
`988 + 32 + 40 + 256 = 1316px`로, 결국 **viewport 약 1280~1316px
구간에서 헤더 grid가 넘칩니다**. 이 구간은 1280×800(구형 13인치 노트북),
1280px 전후로 리사이즈된 브라우저 창 등 실사용에서 드물지 않은 폭입니다.

같은 방식으로 계산하면 변경 전 값(`minmax(19rem,1.4fr)`)은 최소 폭 합이
`53rem=848px`+gap 60px=908px로 952px 안에 여유(44px)가 있어 오버플로가
없었습니다. 즉 이번 PR의 24rem 확장이 새로 오버플로를 만든 변경입니다.

이 계산은 저장소에 정의된 실제 Tailwind 클래스·spacing 토큰·기본
브레이크포인트 값을 근거로 한 것이며, 이 저장소에는 Playwright 등 브라우저
렌더링 검증 도구가 없어 실제 화면으로 직접 재현하지는 못했습니다.
머지 전에 1280~1300px 폭에서 브라우저(또는 DevTools 반응형 모드)로 직접
확인해 주시길 권합니다. 확인되면 `minmax(24rem,1.6fr)`을 조금 낮추거나
(예: 20~21rem), 지표 grid를 xl에서도 2열로 유지하는 등으로 폭을 좁히는
조정이 필요합니다.

## Final Recommendation

Blocking(B1)이 있어 이 상태로는 머지를 권하지 않습니다. 1280~1316px
viewport 구간에서 헤더 grid가 넘칠 수 있다는 계산이 근거이며, 이는
Tailwind 기본 브레이크포인트·spacing 토큰·`AppShell`의 실제 레이아웃
수치로 도출한 것입니다. 브라우저에서 직접 확인 후 폭을 조정하거나
문제가 없음이 확인되면 해소되는 사안입니다. 나머지 부분(타일 제거·
지표 텍스트 그리드·스탠스 배지 승격·필드 유지·접근성·버튼 축소)은
설계·이슈 수용 기준과 정확히 일치하고 CI·로컬 검증 4종도 모두
통과했습니다.

Q1은 B1의 수정 방향을 정할 때 참고할 비차단 확인 사항입니다.

최종 머지 권한은 개발자에게 있습니다.
