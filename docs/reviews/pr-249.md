# PR #249 로컬 리뷰 — 판단 기록(Decision Log) 재설계 FE 1차 (#243·#244·#245·#246)

## Review Summary

판단 기록 화면을 신규 BE 계약(`project_stock` PR #355, ADR-016)에 맞춰 구조적 저널로 재구성하는 FE 1차입니다. 네 커밋이 계약·훅 교체부터 카드·테이블·작성 패널·상세까지를 순서대로 쌓습니다.

**Part A — 계약·셸(#243).** `features/decision-log`의 `dto.ts`·`adapters.ts`·`queries.ts`를 구 계약(`ticker`·`decision_status`·`/stats`)에서 신규 계약으로 전면 교체했습니다. react-query 훅 7종(`useDecisionOverview`·`useDecisionLogs`·`useDecisionLog`·`useCreateDecisionLog`·`useUpdateDecisionDraft`·`useActivateDecision`·`useReviewQueue`)을 두고, `shared/model`에 판단 유형 9종과 target·status·confidence·evidence relationship·risk severity·risk type 라벨 매핑 파일을 추가했습니다. 구 `cognitiveRisk` 매핑은 제거하고 대시보드 소비부를 함께 갱신했습니다. `/decision-log` 셸과 `/decision-log/:id` 상세 라우트 골격을 추가했습니다.

**Part B — 화면(#244·#245·#246).** 상단 요약 카드(전체·이번 주·재검토 예정·진행 중 + 판단 유형 분포)와 판단 기록 테이블을 `widgets/decision-summary-cards`·`widgets/decision-log-table`로 만들어 셸에 배치했습니다(행 클릭 시 상세 이동). 작성 패널(`widgets/decision-form-panel`)은 대상·판단 유형·긍정/반대 근거 분리·인지 위험 태그 복수 선택·확신 수준·재검토 날짜를 받아 `create`(DRAFT) 후 `activate`로 확정하며, 반대 근거가 비면 경고합니다. 상세(`widgets/decision-detail`)는 당시 판단 → 연결된 근거(관계별 구분) → 당시 데이터 스냅샷 → 재검토 조건 순으로 렌더하고 타임라인·복기는 2차 자리만 예약합니다.

이번 리뷰는 신규 BE 계약 준수, enum 라벨화(영문 노출 금지), 설계 순서 원칙(결과보다 근거 우선), 스코프 통제를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. create+activate 2단계에서 activate 실패 시 orphan DRAFT 잔존 — MVP 허용, 인지 필요.** 작성 패널이 `createDecision.mutateAsync` 성공 후 `activateDecision.mutateAsync`를 호출합니다(`DecisionFormPanel.tsx`). activate만 실패하면 서버에 DRAFT가 남습니다. 현재 UI는 오류를 표시하고 입력값을 보존해 사용자가 재시도할 수 있습니다. DRAFT는 계약상 유효 상태이고 목록·재확정 흐름이 2차에서 정리되므로 1차에서는 허용 가능합니다. 후속에서 재확정 진입점 또는 실패 시 정리 전략을 다루면 됩니다.

**S2. 목록 필터·review-queue 소비 UI 미포함 — 1차 셸 범위대로.** BE는 6종 필터와 `review-queue`를 제공하지만 FE 1차는 기본 목록·요약 카드까지만 노출합니다. 필터 UI와 재검토 큐 화면은 핸드오프에서 2차(#247)로 명시한 범위라 정상입니다. `useReviewQueue` 훅은 #243에서 미리 준비돼 있습니다.

## Questions

**Q1. `entities/` 레이어 없이 `features`+`shared/model`로 구성한 것이 맞는가.** 에픽 초안은 FSD `entities/decision-log`를 언급했지만, 이 저장소는 실제로 `features/<domain>` + `shared/model` 관례만 쓰고 `entities/`는 비어 있습니다. 핸드오프에서 기존 관례를 따르고 빈 레이어를 신설하지 않도록 지시했고, 구현이 그대로 따랐습니다. 관례 일치가 확인돼 해소됐습니다.

## Final Recommendation

머지 가능합니다. 네 커밋이 계약·훅 교체 → 요약 카드·테이블 → 작성 패널 → 상세 순으로 신규 BE 계약과 설계 원칙을 항목별로 구현했음을 확인했습니다. 판단 유형·상태·위험은 `shared/model` 라벨로만 표시해 영문 enum이 화면에 새지 않고, 상세는 당시 판단→근거→스냅샷→재검토 순서로 결과보다 근거를 앞세우며, 스냅샷은 immutable로 표시합니다. 스코프는 1차 경계를 지켜 필터 UI·복기·버전·자동 근거 연결·AI 보조는 들어오지 않았습니다. Protected Files는 없으며 라우트/네비게이션은 경로 추가에 그쳤습니다. 추가된 테스트는 어댑터 변환·셸 상태·카드/테이블 렌더·행 이동·폼 검증과 create→activate 순서·상세 순서와 404/403을 덮습니다. Blocking은 없고, Suggestions S1(orphan DRAFT)·S2(필터 UI 2차)는 각각 MVP 허용·2차 범위로 정리됐으며 Question Q1은 리뷰 중 확인해 해소했습니다.
