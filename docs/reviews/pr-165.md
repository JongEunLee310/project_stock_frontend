# PR #165 로컬 리뷰 — fix: 리서치 차트 카드가 aside 높이만큼 늘어나는 문제 수정

리뷰어: Claude (value-for-fable / Sonnet)

구현자: Codex(gpt-5.6-sol), 커밋 `4d8a985`

## Review Summary

리서치 상세 페이지에서 사용자가 보고한 레이아웃 버그를 고치는 변경입니다.
`ResearchPage.tsx`의 2열 grid 컨테이너(`grid gap-6 xl:grid-cols-[minmax(0,2fr)_minmax(18rem,1fr)]`)는
CSS grid의 기본값인 `align-items: stretch` 때문에, 왼쪽 `PriceChartCard`가 오른쪽
aside(AI 브리핑·반대 관점·핵심 리스크·데이터 커버리지 카드 4장)의 높이만큼 늘어났습니다.
차트 콘텐츠 자체는 고정 높이(176px)이므로 늘어난 카드 하단에 빈 여백이 과도하게
남는 것이 버그였습니다. 수정은 해당 grid 컨테이너에 `xl:items-start`를 추가하는
한 줄로, 각 grid item이 컨테이너 높이에 맞춰 늘어나지 않고 자기 콘텐츠 높이만큼만
차지하도록 정렬 기준을 바꿉니다.

`xl:` 접두사가 붙은 이유도 diff와 일치합니다. 컨테이너의 열 정의 자체가
`xl:grid-cols-...`로 xl 브레이크포인트에서만 2열이 되고, 그 미만에서는
`grid-auto-flow`가 기본값인 단일 열로 동작해 `PriceChartCard`와 `aside`가 세로로
쌓입니다. 단일 열 상태에서는 grid item이 서로 다른 행에 위치해 `align-items`가
시각적으로 영향을 주지 않으므로, `xl:items-start`로 범위를 한정한 것이 적절합니다.

부작용 여부도 코드로 확인했습니다. `Card` 컴포넌트(`src/shared/ui/Card.tsx`)는
기본 클래스에 높이 유틸리티를 포함하지 않고, aside 내부의 브리핑 `Card`와
`CounterViewPanel`·`RiskPanel`·`ResearchCoveragePanel`, 그리고 `PriceChartCard`의
`Card` 모두 `h-full`을 사용하지 않습니다. `h-full`이 쓰인 곳은 같은 파일의
1451행(`내 메모` 카드)과 970·1067·1131행(체크리스트·뉴스·촉매 타임라인 패널)인데,
이들은 1444행에서 시작하는 별도의 4열 grid(`grid gap-6 md:grid-cols-2 xl:grid-cols-4`)
소속으로, 이번 diff가 건드린 grid와 무관합니다. 밸류에이션·실적 탭처럼 왼쪽
`PriceChartCard`가 aside보다 길어지는 경우도 확인했습니다. `items-start`는
정렬 기준이므로 어느 쪽이 더 길든 짧은 쪽을 긴 쪽 높이로 늘리지 않습니다. 즉
반대 방향(오른쪽이 짧아 늘어나는 경우)에서도 동일한 종류의 여백 버그가 재발하지
않으며, 이 점에서 `items-start`는 두 방향 모두에 대해 대칭적으로 올바른 수정입니다.
