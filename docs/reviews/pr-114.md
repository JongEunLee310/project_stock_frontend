# PR #114 — 종목 추가 모달 개편 (feat/112-asset-lookup-modal)

리뷰어: value-for-fable:itsvff (Sonnet, VFF 위임). 구현: Codex. 브랜치: feat/112-asset-lookup-modal → feat/108-add-stock-flow (stacked). 관련: FE #112, 핸드오프 task-042. 리뷰 대상 커밋: 64b3905 하나 (`git diff origin/feat/108-add-stock-flow...feat/112-asset-lookup-modal`).

## Review Summary

PR #114는 이슈 #112에서 요청된 종목 추가 모달 전면 개편을 구현합니다. 기존의 "기존 종목 선택 / 신규 종목 등록" 탭 구분과 수동 입력 폼을 제거하고, 시장 select + 심볼/종목명 입력에서 `GET /assets/lookup` API를 debounce 호출해 드롭다운을 표시하며, 드롭다운에서 선택한 항목만으로 추가가 진행되도록 재구성합니다.

변경된 파일은 10개입니다. `dto.ts`는 `CreateAssetBody`를 `{ symbol, market }` 2필드로 줄이고 `AssetLookupItemDto`·`AssetLookupResponseDto`를 추가합니다. `queries.ts`는 `useAssetLookup(query, market, enabled)` 훅을 신설하고, `fetchAssetsBySymbol`을 인라인에서 named export 함수로 추출하며, `useAddAssetToFirstWatchlist`의 관심목록 없음 처리를 에러 throw에서 `POST /watchlists`로 자동 생성 후 계속 진행하는 방식으로 변경합니다. `AddWatchlistAssetModal.tsx`는 탭·수동 폼을 모두 제거하고 두 입력 필드가 단일 debounced query를 공유하는 `useAssetLookup` 기반 UI로 재구성합니다. `errorCodes.ts`에는 `ASSET_NOT_IN_MARKET`·`ASSET_DUPLICATE` 두 코드가 추가됩니다.

추가 흐름의 핵심 분기는 선택 항목의 `registered` 값입니다. `registered: true`이면 `resolveRegisteredAssetId`로 `GET /assets?symbol=`을 호출해 심볼·market 양쪽이 일치하는 항목의 id를 구하고, `registered: false`이면 `POST /assets { symbol, market }`으로 서버 검증 등록 후 반환된 id를 사용합니다. 관심목록 자동 생성은 `useAddAssetToFirstWatchlist` 내부에서 `mutateAsync` 실행 시점에만 발생하므로, 모달 열림만으로는 생성되지 않습니다.

## Suggestions

**S1: `listbox` role이 조건부로 적용되어 `aria-controls` 대상의 역할이 소멸하는 상황이 발생합니다**

드롭다운 컨테이너는 `role={lookupItems.length > 0 ? 'listbox' : undefined}`로 선언되어 있습니다. 심볼·종목명 입력 양쪽에는 `aria-controls={listboxId}`가 항상 붙어 있어, lookup 결과가 없거나 로딩·오류 상태일 때 `aria-controls`가 가리키는 요소에 `listbox` role이 없는 상태가 됩니다. 기술적으로 `aria-controls`의 대상은 예고된 role을 가져야 합니다. 기능 동작에는 영향이 없으나 스크린 리더가 관계를 해석하지 못할 수 있습니다.

개선 방향은 컨테이너에 항상 `role="listbox"`를 부여하되, 결과가 없는 경우에는 안내 텍스트를 `role="option"` 대신 일반 `<p>`로 두어 listbox 내부에 option이 없는 빈 listbox로 두는 것입니다. 또는 로딩·오류·빈 상태일 때 `aria-controls`를 조건부로 제거하는 방법도 있습니다. 현 상태가 핸드오프 요구사항("드롭다운에도 적절한 role 적용")의 범위를 벗어나지는 않지만, 접근성 견고성 관점에서 후속 이슈로 처리를 권장합니다.

위치: `src/features/watchlist/AddWatchlistAssetModal.tsx` — `listboxId` 컨테이너 div의 `role` prop (358번째 줄 근방)

**S2: 시장 select 변경 시 선택 해제·재조회 동작을 검증하는 테스트가 없습니다**

핸드오프 Requirements는 "시장 select 변경 시 진행 중이던 선택은 해제하고 lookup을 다시 조회한다"고 명시합니다. 구현은 `onChange`에서 `setMarket` + `clearSelection()`을 호출하고 query key에 `market`이 포함되어 있어 동작이 정확합니다. 그러나 이 경로에 대한 테스트가 없어 향후 시장 필터 처리를 변경할 때 회귀를 감지하지 못합니다. Test Requirements에는 이 항목이 명시되지 않았으므로 현 PR 범위를 초과하지 않으나, 후속 이슈로 추가를 권장합니다.

위치: `src/pages/ui/WatchlistPage.test.tsx` (시장 select 변경 시나리오 추가)

**S3: `onFocus` 핸들러가 포커스 이동만으로 lookup 대상 필드를 전환합니다**

심볼 입력에 값이 있는 상태에서 종목명 입력으로 포커스를 옮기면, `onFocus`에서 `setActiveLookupInput('name')`이 호출됩니다. 종목명 입력이 비어 있으면 `canLookup`이 false가 되어 드롭다운이 사라지고, 종목명 입력에 값이 있으면 그 값으로 즉시 재조회가 시작됩니다. 사용자가 타이핑하지 않고 포커스만 이동해도 조회 대상과 드롭다운 상태가 바뀌므로 UX가 다소 예측하기 어렵습니다.

이 동작은 codex 보고의 잔여 위험("단일 debounced query 공유")의 직접적인 발현입니다. `onFocus` 대신 `onChange` 호출 시에만 `activeLookupInput`을 전환하는 방식으로 변경하면, 포커스 이동에 의한 의도치 않은 재조회를 방지할 수 있습니다. 기능 요구사항 충족에는 영향이 없으므로 후속 이슈로 처리해도 무방합니다.

위치: `src/features/watchlist/AddWatchlistAssetModal.tsx` — 심볼/종목명 `Input`의 `onFocus` prop (325번째 줄, 342번째 줄 근방)

**N1: 닫기 버튼 텍스트가 `×`(U+00D7)에서 ASCII `x`로 변경되었습니다**

`aria-label="종목 추가 닫기"`가 있어 스크린 리더 접근성에는 영향이 없습니다. 다만 시각적으로 `×`가 닫기 버튼임을 더 명확히 전달했던 측면이 있습니다. 기능과 접근성에 문제는 없으므로 Nit으로 기록합니다.

위치: `src/features/watchlist/AddWatchlistAssetModal.tsx` — 닫기 버튼 텍스트 (284번째 줄 근방)

**N2: `aria-expanded={canLookup}`이 결과 없는 상태에서도 `true`가 됩니다**

`canLookup`은 입력값 존재 여부(`trimmedLookupValue.length > 0`)이므로, 로딩·오류·빈 결과 상태에서도 `aria-expanded=true`입니다. ARIA 명세상 `aria-expanded`는 popup이 표시되고 사용자가 선택할 수 있는 상태일 때 `true`여야 합니다. 실제 드롭다운 표시 조건(`lookupItems.length > 0`)과 불일치합니다. 스크린 리더 동작에 실질적 영향은 제한적이지만, 향후 combobox 패턴 강화 시 혼동의 여지가 있습니다.

위치: `src/features/watchlist/AddWatchlistAssetModal.tsx` — 심볼·종목명 `Input`의 `aria-expanded` prop (325번째 줄, 343번째 줄 근방)
