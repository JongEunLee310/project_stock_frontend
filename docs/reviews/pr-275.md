# PR #275 로컬 리뷰 — 토픽 인사이트 상세 화면 (#203)

## Review Summary

에픽 #198 1차의 마지막 화면인 토픽 인사이트 상세(`/news/topics/:topicId`, 분석 현미경)를 구현한 PR입니다. 커밋은 구현 본체(`feat: 토픽 인사이트 상세 화면 구현`)와 핸드오프 문서(`docs: #203 토픽 상세 핸드오프 태스크`) 두 건입니다. 개요(관제탑)에서 토픽을 클릭해 들어와 근거·영향·반대 관점을 검증하는 상·하위 관계의 하위 화면입니다.

기존 자산을 폭넓게 재사용합니다. HTTP·envelope·cursor 페이징은 `@/shared/api`(`apiGet`·`ApiCursorMeta`·`buildCursorSearchParams`·`toCursorPageInfo`)를, 차트는 `@/shared/ui/charts`의 `chartTheme`·`useMeasuredChartWidth`·`DonutChart`를, enum 라벨·톤 매핑은 `features/news-insights/adapters.ts`의 기존 presentation 맵(`sentimentPresentations`·`documentTypePresentations`) 컨벤션을 그대로 확장했습니다. 라우트 `appRoutePaths.newsTopicDetail`은 이미 정의돼 있어 `router.tsx`에 페이지만 배선했습니다.

새로 추가된 것은 features의 상세 3종 query(`useNewsTopicDetailQuery`·`useNewsTopicTrendQuery`·`useNewsTopicEvidenceQuery`)와 dto·adapter, 위젯 4종(`TopicSummaryHeader`·`TopicTrendChart`·`TopicEvidenceList`·`CounterViewPanel`), 페이지 `TopicInsightDetailPage`입니다. 세 패널은 각각 독립 query로 연동하며 한 API 오류가 페이지 전체를 깨지 않도록 부분 실패를 격리합니다. 계약 변경은 없고 BE의 dev 머지 계약(`GET /topics/{id}`·`/trend`·`/evidence`)을 소비만 합니다.

이번 리뷰는 설계 원칙 준수(점수 오인 방지·반대 관점 대칭·사실/분석 분리·수치 창작 금지)와 부분 실패 격리, 범위 통제를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 추이 window·interval 하드코딩 — 현재 범위에서 허용, 후속 확장 여지.** `useNewsTopicTrendQuery`가 `window=7d&interval=1d`를 고정하고 queryKey에도 `'7d'·'1d'`를 리터럴로 담습니다. 1차 범위는 기본 7일·일간 단일 뷰이므로 문제가 없으나, 기간 토글이 추가되는 시점에 파라미터화가 필요합니다. 병합을 막지 않으며 후속 이슈에서 다루면 됩니다.

**S2. 원문 URL 부재의 정직한 노출 — 계약 한계에 대한 적절한 처리.** 근거 항목의 '원문 보기'는 API가 원문 URL·본문을 제공하지 않아 출처 메타데이터(출처·발행 시각·문서 번호)만 표시하고 그 사실을 문구로 밝힙니다. 없는 정보를 만들지 않는다는 프로젝트 원칙에 부합합니다. 원문 링크 계약이 생기면 이 영역을 연결하면 됩니다.

## Questions

**Q1. `key_evidence` 항목 구조의 안정성.** BE `TopicInsightResponse.key_evidence`는 `list[dict[str, Any]]`로 스키마가 느슨합니다. adapter의 `adaptKeyEvidence`가 `title`·`summary`·`quote`·`text`를 순서대로 탐색하고 모두 없으면 `이벤트 #{event_id}` 또는 인덱스 라벨로 폴백하도록 방어적으로 처리해 해소했습니다. 실제 시드·수집 데이터의 dict 키가 확정되면 라벨 우선순위를 재확인하면 됩니다.

## Final Recommendation

머지 가능합니다. 핸드오프 요구사항을 항목별로 확인했습니다. 세 패널 독립 query와 부분 실패 격리(`TopicSummaryHeader`·`TopicTrendChart`·`TopicEvidenceList`가 각각 loading·error·empty를 자체 처리), 점수 오인 방지 안내('관찰 우선순위'·감성 방향 안내 문구), 반대 관점 상시 노출(`CounterViewPanel`이 빈 배열에도 동일 비중 EmptyState 렌더), 사실/분석 분리(원문 정보 대 AI 요약 시각 구분), 영향 종목 → `/research/:symbol` 이동, BE 계산값 그대로 렌더가 모두 확인됩니다.

범위는 지켜졌습니다. 2·3차 패널(종목 민감도·키워드 관계망·시나리오·Agent 설명·액션 연결)과 이벤트 상세(#204)에는 손대지 않았습니다. Protected Files는 없으며 diff는 features·widgets·pages·router 신규 추가와 페이지 export에 한정됩니다. 신규 npm 의존성 추가도 없습니다. 추가된 테스트는 상세 3종 query·adapter(성공·오류·빈 데이터), 위젯 4종, 페이지의 패널 조합·부분 실패를 덮습니다.

Blocking은 없습니다. S1·S2는 후속·계약 한계 사항으로 병합을 막지 않으며, Q1은 리뷰 중 adapter 방어 처리로 해소했습니다.
