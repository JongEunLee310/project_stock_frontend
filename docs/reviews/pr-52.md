# PR #52 Local Review — 인증 흐름 신설 (이슈 #46, G1/Q8/N2)

## Review Summary

이슈 #46. ADR-004 결정 4(401 lazy refresh) 위에서 FE에 전무하던 인증을 신설했다. 단일 fetch client +
access/refresh 토큰 스토어 + 로그인/보호 라우팅. 설계 `docs/designs/46-auth-flow.md`와 일치한다. BE
`project_stock#96`(PR #109)과 페어. 파이프라인: Opus 설계 → Sonnet 구현 → Opus 검증·PR.

검토 항목:

- **단일 client(C1·C9·C10)**: `apiRequest`가 `VITE_API_BASE_URL` 결합·`Authorization: Bearer` 주입·#45
  `unwrapEnvelope`/`messageForErrorCode` 재사용. 화면·쿼리는 envelope·토큰을 직접 보지 않는다.
- **401 lazy refresh(C3·Q8·N2)**: single-flight(`pendingRefresh` 공유 + `finally` 해제)로 동시 401에서
  refresh 1회. 성공 시 새 access로 **원요청 1회만** 재시도, refresh 실패/토큰 부재 시 `clearTokens`+
  `emitAuthExpired` 후 `ApiError` throw. **재시도는 최초 1회로 한정**(재시도 응답이 다시 401이어도 재귀 없음)
  → 무한루프 없음. 단위 테스트로 성공/실패/무한루프-없음/single-flight 모두 단언.
- **토큰 스토어 = 순수 모듈**: `tokenStore`(localStorage + 만료 이벤트 발행/구독)를 client와 `AuthProvider`가
  공유. React 비의존이라 **client↔컨텍스트 순환 의존을 끊음**(설계 결정 2·4 준수).
- **인증 상태·라우팅**: `AuthProvider`/`useAuth`/`RequireAuth` + `LoginPage`. 미인증 시 `/login` 리다이렉트
  (복귀 경로 보존), 만료 이벤트→로그아웃 + 인앱 통지(네이티브 `alert`/`confirm` 미사용,
  [[frontend-reusable-component-rule]] 준수).
- **스코프 통제**: TanStack Query 미도입(#48), 도메인 모델 교체·`assetId`(#47), 기존 화면 mock 제거·연동(#48)
  손대지 않음. 신규 런타임 의존 없음(순수 fetch + React Context). 기존 페이지 테스트는 `AuthProvider` 래핑·
  async(`findBy*`) 전환으로 회귀 0.

## 통합 검증 중 수정 (Opus, 차단 → 해소)

- **비회전 refresh 토큰 손실(차단, 수정 완료)**: BE#109는 비회전 정책으로 refresh 응답의 `refresh_token`을
  **빈 문자열**로 내려보낸다(`assert not data.get("refresh_token")`로 BE 테스트가 명시). FE 초안은
  `dto.refresh_token ?? tokens.refreshToken`(nullish)이라 **빈 문자열을 그대로 저장** → 다음 refresh가 빈
  토큰으로 실패하는 버그였다. `||`(falsy fallback)로 수정해 빈/누락 시 기존 refresh를 유지하도록 BE 비회전
  정책과 정합시켰다. 회귀 테스트(빈 `refresh_token` → 기존 유지) 추가. 페어 병렬 통합에서 잡힌 갭.
- **일본어 주석 1건 → 한국어화**(코드 컨벤션 일관성).

## Blocking

- 없음(위 통합 버그는 수정·재검증 완료).

## Suggestions

- **`VITE_API_BASE_URL` 부재 시 동작(비차단)**: 미설정 시 base URL이 빈 문자열로 상대경로 호출된다. 프로덕션
  빌드에 `.env`(`VITE_API_BASE_URL`) 필수 — #48 연동 시 `.env.example`/README에 명시 권장. 테스트는
  `src/test-utils/authTestSetup.ts`에서 주입.
- **서버 에러 메시지 fallback(비차단, #45 이월)**: client가 `error.code`만 매핑하고 서버 `error.message`를
  버린다. #48 실제 에러 연동 시 `messageForErrorCode(code, serverMessage)` 우선순위 검토(pr-51 후속).
- **`me` 부팅 동기화(비차단)**: 새로고침 시 토큰만으로 `authenticated`로 보고 `GET /auth/me`를 즉시 조회하지
  않으면, 만료 토큰이 첫 보호요청 401까지 노출될 수 있다. 현재 lazy refresh로 흡수되나 #48에서 부팅 시 `me`
  prefetch로 사용자 정보 채우는 흐름 검토.

## Final Recommendation

**머지 적합(Blocking 없음).** 401 lazy refresh를 single-flight·1회 재시도·무한루프 방지로 구현하고, 토큰
스토어를 순수 모듈로 분리해 순환 의존을 끊었다. 페어 병렬에서 드러난 비회전 refresh 손실 버그를 BE 정책과
정합시켜 수정·회귀 테스트했다. 전 게이트(159) 통과. **BE #109와 함께 머지**해야 실 연동이 성립한다. 머지는
사람이 수행.
