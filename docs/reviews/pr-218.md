# PR #218 — 리서치 헤더 목표주가 최저·최고 기관 귀속 표기 (feat/217-target-price-attribution)

리뷰어: Claude Code (Sonnet, VFF). 구현: Codex. 브랜치: feat/217-target-price-attribution →
main. 관련: 이슈 #217, 핸드오프 `.codex/tasks/task-082-target-price-attribution.md`,
BE JongEunLee310/project_stock#318(PR #321, dev 머지 완료).

## Review Summary

이슈 #217대로 리서치 헤더의 목표주가 최저·최고 행 출처를 '애널리스트
N명 컨센서스' 고정 문구에서 실제 기관명으로 승격했습니다. `dto.ts`에
`AnalystOpinionDto`/`AnalystOpinionsDto`를 BE `GET
/assets/{asset_id}/analyst-opinions` 계약과 필드 단위로 그대로
매핑했고(`firm`·`action`은 non-null 문자열, `to_grade`·`from_grade`·
`price_target`·`prior_price_target`·`price_target_action`은 nullable),
`adapters.ts`의 `adaptAnalystOpinions`가 기존 `parseDecimal`을 그대로
재사용해 `price_target`류 Decimal 문자열을 숫자로 변환합니다.

귀속 로직은 `deriveTargetPriceAttribution` → `findLatestMatchingFirm`
순수 함수로 분리되어 있습니다. 목표가가 `null`이면 즉시 귀속하지
않고, 그 외에는 `opinions` 배열에서 `priceTarget === targetPrice`이고
`firm`이 공백이 아닌 첫 번째 항목의 기관명을 반환합니다. BE 계약이
`limit` 쿼리를 "최근 발표순"으로 명시하므로, 배열의 첫 매치를 쓰는 것이
곧 핸드오프가 요구한 "복수 일치 시 최근 발표 기관 우선"과 동일합니다.

`ResearchPage.tsx`의 `useAnalystOpinions(research?.assetId)`는 다른
파생 쿼리(`useNewsDisclosure`, `useCatalystTimeline` 등)와 동일하게
`queryKey: ['research', 'analyst-opinions', assetId]`·`enabled: assetId
!= null` 관례를 따르고, 헤더 렌더링 시 `analystOpinionsQuery.data ??
[]`로 소비합니다. 따라서 로딩 중이거나 조회가 실패해도 `opinions`가
빈 배열로 취급되어 귀속이 `null`로 떨어지고, `TargetPriceSourceSuffix`가
기존 컨센서스 문구로 자연히 폴백합니다. 별도의 에러 상태 분기나
에러 메시지 렌더링이 없어 헤더가 의견 조회 실패에 블로킹되지도, 에러
UI를 노출하지도 않습니다.

None.

## Suggestions

**S1 · 최근 우선 판정이 BE 정렬 계약에 전적으로 의존합니다**

`findLatestMatchingFirm`은 `published_at`을 직접 비교하지 않고,
`opinions` 배열에서 먼저 나오는 매치를 그대로 채택합니다. 이는 BE
계약(`limit: int = 20 (1–50, 최근 발표순)`)이 항상 최신순 정렬을
보장한다는 전제 위에서만 "최근 우선"이 됩니다. 현재는 계약과
`adapters.test.ts`의 "uses the first recent opinion when multiple
firms match a target" 테스트로 이 전제가 명시돼 있어 동작상 문제는
없지만, 정렬 필드(`published_at`)를 코드가 직접 비교하지 않으므로
향후 BE가 정렬 기준을 바꾸거나 캐싱 계층이 순서를 흔들면 조용히
틀린 기관명을 표기할 수 있습니다. 스코프 안 필수 수정은 아니지만,
`opinions.slice().sort((a, b) => b.publishedAt.localeCompare(a.publishedAt))`
같은 방어적 정렬을 어댑터 단계에 추가하는 후속 개선을 제안합니다.

## Final Recommendation

**Blocking 없음 — 머지 가능.**

dto가 BE `analyst-opinions` 계약과 필드·nullable 단위로 정확히

최근 우선, 귀속 불가(불일치·목표가 null), 의견 조회 실패, 국내 종목

통합 테스트로 커버됩니다. 헤더 로딩은 의견 조회에 블로킹되지 않고,
조회 실패 시에도 에러 UI 없이 컨센서스 폴백으로 정상 표기됩니다.
#206에서 확정된 목표주가 목록 표기 구조(인라인 출처 접미사)는
`firm` prop 추가만으로 확장되어 회귀가 없습니다. S1은 현재 BE 계약
아래에서는 실질적 위험이 아닌 방어적 개선 제안이라 머지를 막을
이유가 아닙니다.

## R2 — 최근 의견 기준 재정의 리뷰 (2026-07-15)

리뷰어: Claude Code (Sonnet, VFF). 구현: Codex. 대상 커밋: `a503351`
(`git diff e01e64a..HEAD -- src/`). 정책 변경 배경: 이슈 #217의
2026-07-15 코멘트에서 NVDA 실측 결과 컨센서스 극단값이 약 200건 전
과거 의견에서 와 정확 일치 귀속이 대부분 폴백으로 빠지는 문제가
확인되어, R1의 "컨센서스 값 + 정확 일치 귀속" 정책을 "최저·최고 행
값 자체를 최근 의견(limit 20) 기준 min/max로 재정의"하는 정책으로
교체했습니다. 핸드오프는 `.codex/tasks/task-083-target-price-recent-range.md`입니다.

### Review Summary

`deriveTargetPriceAttribution`이 목표가와 귀속 기관명을 별도로 찾던
R1 구조(`findLatestMatchingFirm` 정확 일치)에서, `opinions` 배열
자체의 min/max를 값과 기관명 쌍(`AttributedTargetPrice`)으로 직접
파생하는 구조로 교체됐습니다. R1의 방어적 재정렬
(`opinions.sort((a, b) => b.publishedAt.localeCompare(a.publishedAt))`)은
그대로 유지되고, `priceTarget !== null && firm.trim().length > 0`
필터로 목표가 없는 의견을 min/max 계산에서 제외합니다. 정렬된
배열의 첫 항목을 `low`·`high` 초기값으로 삼고, 나머지 항목을
`reduce`로 순회하면서 엄격 부등호(`<`, `>`)로만 갱신하기 때문에
동률일 때는 정렬 순서상 먼저 오는(=더 최근에 발표된) 항목이
유지됩니다. `ResearchPage.tsx`는 `targetPriceAttribution.low?.price ??
research.targetPriceLow` 형태로 파생 값이 있으면 그것을, 없으면
기존 컨센서스 값을 최저·최고 행에 쓰고, 평균 행(`research.targetPrice`,
`research.targetUpsidePercent`)과 `TargetPriceSourceSuffix`의 폴백
문구(`· 애널리스트 N명 컨센서스`)는 이번 diff에서 손대지 않아 그대로
유지됩니다.

### 검증 포인트별 확인

- **min/max 파생 정확성** — `price_target: null`인 의견은
  `pricedOpinions` 필터에서 제외되어 min/max 후보에 들지 않습니다
  (`returns no range for empty opinions or opinions without target
  prices` 테스트로 고정). 동률 시 최근 우선은 `uses the most recent
  opinion when multiple firms tie at a bound` 테스트가 직접
  검증합니다 — 같은 값 900을 가진 두 의견(`Older Securities`
  07-01, `KGI Securities` 07-15)을 섞고 배열 순서를 발표순과
  어긋나게 배치한 뒤, 최저 행 귀속이 더 최근인 `KGI Securities`로
  떨어지는지 확인합니다. R1에서 추가된 방어적 재정렬 코드는
  그대로 남아 있고 이 테스트가 재정렬이 실제로 작동함을 함께
  검증합니다.
- **최저·최고 행 교체, 평균 행 불변** — `ResearchPage.tsx`의
  `displayedTargetPriceLow`/`displayedTargetPriceHigh`만 파생 값
  우선으로 바뀌었고, 평균 행 렌더 코드(`평균 ${formatCurrency(research.targetPrice, ...)}
  (${formatPercent(research.targetUpsidePercent)})`)는 diff에
  포함되지 않아 그대로입니다. NVDA 통합 테스트가 최저 $1,000.00·
  KGI Securities, 최고 $1,200.00· JPMorgan으로 값 자체가 바뀌었음을
  확인합니다.
- **폴백 3종** — ①빈 목록/로딩(`data: undefined, isLoading: true`)과
  ②조회 실패(`isError: true`)는 R1부터 있던 기존 테스트가 그대로
  통과해 회귀가 없음을 보여주고, ③전부 null인 경우는 이번에 추가된
  `uses the consensus fallback when all analyst target prices are
  null` 테스트가 새로 고정합니다. 세 경우 모두
  `deriveTargetPriceAttribution`이 `{ low: null, high: null }`을
  반환해 `displayedTargetPriceLow/High`가 `research.targetPriceLow/High`로
  떨어지고 `TargetPriceSourceSuffix`가 기존 컨센서스 문구를 그대로
  표기합니다. 추가로 `renders the recent opinion range when
  consensus bounds are absent` 테스트는 반대 방향(컨센서스 자체가
  없는 종목에 의견은 있는 경우) 최근 의견 값이 정상적으로 주 표기가
  됨을 확인해, 두 원천 중 하나만 있어도 표기가 끊기지 않음을
  보강합니다.
- **로딩·실패 비블로킹** — 호출부의
  `analystOpinions={analystOpinionsQuery.data ?? []}` (line 1678)는
  이번 diff에 포함되지 않았고, 별도 에러 상태 분기도 여전히 없어
  R1의 비블로킹 특성이 유지됩니다.
- **범위 통제** — 변경 파일은 `adapters.ts`·`adapters.test.ts`·
  `ResearchPage.tsx`·`ResearchPage.test.tsx` 4개로, 핸드오프
  Implementation Scope와 정확히 일치합니다. BE 수정이나 `limit`
  값 변경은 없고, 목표주가 목록 구조(#206)도 건드리지 않았습니다.
