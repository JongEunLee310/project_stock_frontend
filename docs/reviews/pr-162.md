## Review Summary

이슈 #151의 구현입니다. 리서치 상세 "내 메모" 카드에 "템플릿 적용" 버튼을 추가하고,
헤더의 "판단 기록" 버튼이 `?symbol=` 쿼리를 포함한 딥링크로 이동하도록 변경하며,
`DecisionLogPage`에서 해당 쿼리를 읽어 종목 필드에 프리필하는 세 가지 변경으로 구성됩니다.
변경은 4개 파일, 228줄입니다(구현 2, 테스트 2).

**메모 템플릿**은 6개 섹션(`[투자 가설]`, `[긍정 근거]`, `[반대 근거]`, `[매수 조건]`,
`[철회 조건]`, `[다음 확인 날짜]\nYYYY-MM-DD`)을 모듈 상수 `MEMO_TEMPLATE`으로 선언합니다.
버튼 클릭 시 `setMemoDraft({ assetId, value: MEMO_TEMPLATE, isDirty: true })`와
`setMemoSaveStatus('idle')`을 호출하여 기존 debounce·저장 상태 흐름을 그대로 탑니다.
별도 저장 경로는 신설되지 않았습니다. 메모가 비어 있을 때(공백 포함, `trim().length > 0`
역조건)만 버튼이 활성화되며, 내용이 있으면 실제 `disabled` 속성과 `title` 안내 문구가
함께 설정됩니다.

**판단 기록 딥링크**는 `navigate`에 `encodeURIComponent(research.symbol)`을 포함한
경로를 넘기는 단순 변경입니다. `DecisionLogPage`에서는 `useSearchParams`를 추가하고
`useState` 초기값을 함수형 이니셜라이저(`() => ({ ...initialFormState, symbol: ... })`)로
변경하여 마운트 1회만 쿼리 파라미터를 읽습니다. 이후 사용자가 수정해도 덮어쓰지 않습니다.
폼 제출 시 `symbol.trim().toUpperCase()`를 적용하는 기존 유효성 로직은 변경 없이 그대로
사용됩니다.

## Suggestions

**S1. `memoSaveStatus`를 `'idle'`로 리셋하는 위치가 명세보다 좁을 수 있습니다**

템플릿 클릭 핸들러(`ResearchPage.tsx` 1450~1455행)에서 `setMemoSaveStatus('idle')`을
명시적으로 호출하고 있습니다. 이 자체는 문제가 없으나, `setMemoDraft`가 호출되어
`isDirty: true`로 설정되면 debounce effect가 실행 중인 저장 사이클의 타이머를
클리어하고 새 타이머를 시작합니다. 이 흐름에서 기존에 `'saved'` 또는 `'error'` 상태가
표시 중이던 경우 템플릿 클릭 직후 곧바로 `'idle'`로 전환되므로 저장 상태 표시가
순간적으로 사라졌다가 1초 뒤 다시 나타납니다. 기능상 문제는 없고 테스트도 통과하나,
사용자 경험상 저장 표시 깜박임이 생길 수 있습니다. 향후 저장 상태 UX 개선 시 참고하시기
바랍니다. 심각도: 비차단·향후 보완 대상.

**S2. `?symbol=` 쿼리 파라미터를 화면 이동 후 URL에서 제거하는 처리가 없습니다**

현재 구현은 `DecisionLogPage`가 마운트될 때 `searchParams.get('symbol')`로 프리필하고
이후 URL을 건드리지 않습니다. 따라서 사용자가 폼을 초기화(`resetForm`)하거나 제출
성공 후에도 `?symbol=NVDA`가 URL에 남아 있어, 수동 새로고침 시 종목 필드가 다시
프리필됩니다. 설계 문서는 "마운트 시 1회"라고만 명시하고 있어 이번 범위에서는
허용되지만, 제출 성공 후 `resetForm`이 호출될 때 URL도 `/decision-log`로 교체하는
것이 더 자연스러운 동작입니다. 심각도: 비차단·후속 개선 권장.

## Questions

**Q1. `memoValue`가 비어 있는지 판단하는 기준과 `assetId` 불일치 시 동작을 확인해 주시면 좋겠습니다**

`disabled={memoValue.trim().length > 0}` 조건에서 `memoValue`는 `memoDraft?.assetId ===
research.assetId`가 아닐 때 `research.checklistMemo ?? ''`로 폴백합니다
(`ResearchPage.tsx` 1251~1254행). 즉 자산 전환 직후 `memoDraft`가 이전 자산 id를 담고
있는 짧은 시점에는 서버 값을 기준으로 버튼 활성 여부를 판단합니다. 이는 대부분의 경우
올바른 동작이나, 서버 메모가 비어 있고 이전 자산 draft가 남아 있는 전환 순간에
버튼이 순간 활성화될 수 있는지 구현자가 한 번 확인해 주시면 기록이 명확해집니다.
현재 테스트 범위에서는 이 경계 케이스를 다루지 않습니다.

테스트가 회귀 없이 482개 전원 통과했습니다.
