# PR #118 — 관심 종목 페이지 Phase 1 (feat/117-watchlist-phase1)

리뷰어: Claude Code (Sonnet / Value-for-Fable). 구현: Codex (GPT-5, medium). 브랜치: feat/117-watchlist-phase1 → main. 관련: FE #117, 설계 docs/designs/117-watchlist-phase1.md, 핸드오프 .codex/tasks/task-044-watchlist-phase1.md.

## Review Summary

설계 117대로 `WatchlistPage`의 즐겨찾기(★) 컬럼·알림 현황 카드를 제거하고, `useWatchlistAssets`에 `page`/`size` 파라미터를 추가해 서버 페이지네이션을 연동했습니다. 행 메뉴에는 `DELETE /watchlists/{id}/items/{item_id}` 호출과 결정 기록 이동이 실제로 동작하며, 시장 필터 드롭다운이 현재 로드된 페이지 내에서 클라이언트 필터링을 수행합니다. `MarketSummary`·`FxRateStrip`은 `Sidebar`에서 분리되어 `FloatingMarketCard`(`position: fixed`, 왼쪽 하단)로 이전되었고, `AppShell` 최상위 `div` 안에 그리드 바깥 형제로 배치됩니다.

훅 시그니처 변경의 파급으로 `DashboardPage.tsx`가 함께 수정됐습니다. 이전에는 20개를 가져와 클라이언트에서 4개로 자르는 방식이었으나, 이제 서버에 `size=4`를 직접 요청합니다. 설계 문서에 명시된 파일 목록에는 없지만 훅 시그니처 변경의 정당한 파급이며, 불필요한 네트워크 전송을 줄이는 개선입니다.

핵심 BE 계약(DELETE 200/data:null, meta 구조, market 필드 존재)은 설계 Verified Facts에 출처가 명시되어 있고 구현에도 그대로 반영됐습니다. 쿼리 키는 `[...watchlistQueryKey, 'assets', page, size]`로 구성되어 각 (page, size) 조합이 독립 캐시 엔트리가 되며, `useRemoveWatchlistItem`의 `onSuccess`는 `watchlistQueryKey` 전체를 invalidate해 모든 하위 캐시를 일괄 무효화합니다.

## Suggestions

**S1 · `FloatingMarketCard` wrapper의 중복 aria-label (비차단, 접근성)**

`FloatingMarketCard`의 `<aside aria-label="시장 요약">` 안에 `MarketSummary` 컴포넌트가 자체적으로 `aria-label="시장 요약"`을 선언합니다(`MarketSummary.tsx:22` 확인). 결과적으로 동일한 이름의 ARIA 랜드마크 두 개가 DOM에 공존하게 됩니다. `App.test.tsx`가 기존 `getByLabelText('시장 요약')` 단일 셀렉터에서 `getAllByLabelText('시장 요약').length`로 변경된 점이 이를 명확히 뒷받침합니다. 스크린리더 사용자가 랜드마크 탐색 모드에서 "시장 요약"을 두 번 만나게 되어 혼란을 야기할 수 있습니다. `FloatingMarketCard` wrapper `<aside>`에서 `aria-label`을 제거하거나 `<div>`로 태그를 교체하면 됩니다. `MarketSummary`가 이미 역할을 충분히 선언하므로 wrapper의 중복 레이블은 필요 없습니다.

**S2 · `isRemoving`이 모든 행에 공유됨 (비차단, UX)**

`removeWatchlistItem.isPending`이 모든 행의 `RowMenu`에 동일하게 전달됩니다. 종목 A 삭제가 진행 중이면 종목 B, C의 "관심 해제"도 함께 비활성화됩니다. 핸드오프 §Requirements에는 "진행 중에는 해당 버튼을 `disabled` 처리한다"라고 명시되어 있는데, 현재 구현은 삭제 중인 항목 외에도 다른 모든 행을 비활성화합니다. 기능 정확성에는 영향이 없고 현재 단계에서 허용 범위 내이지만, 이후 `mutationKey` 기반으로 항목별 pending 상태를 분리하면 UX가 개선됩니다.

**S3 · 시장 필터 적용 중 count 표기 혼란 (비차단, 설계 범위 내)**

`totalRows`는 `meta.total`(서버 전체 합계)을 사용합니다. 시장 필터로 3개만 보이는 상태에서 "전체 100개 중 1-3 표시"가 노출됩니다. 설계 §3에서 시장 필터를 클라이언트 필터로 명시적으로 결정했고, 필터와 page/size가 독립적으로 동작한다는 점도 알려진 제약 사항입니다. 현재 Phase 1 범위 내에서 허용되며, Phase 2 이후 필터 적용 중임을 표기하는 UI 힌트를 추가하면 혼란을 줄일 수 있습니다.

**S4 · 시장 필터 변경 시 page 미초기화 (비차단, UX)**

표시 개수 select 변경 시에는 `setPage(1)` 초기화 로직이 있으나, 시장 필터 변경 시에는 page가 초기화되지 않습니다. 페이지 3에서 시장 필터를 변경하면 페이지 3 결과 중 해당 시장만 클라이언트 필터링하여 예상보다 적은 항목이 보일 수 있습니다. 설계 문서에 명시적 요구는 없으나 `setMarketFilter` 변경 핸들러에 `setPage(1)` 한 줄을 추가하면 직관적 동작이 됩니다.
