## Review Summary

리서치 상세 화면의 '뉴스 및 공시 요약' 카드에서 더 보기를 눌러 카드가 그대로
펼쳐지던 기존 방식을, 종목별 뉴스·공시 전체를 보여주는 별도 페이지
(`/research/:symbol/news`)로 전환하는 변경입니다. 핵심 메커니즘은 세 가지입니다.

첫째, `NewsDisclosurePanel`의 `isExpanded` 상태와 펼침 토글을 제거하고 항상
compact 3건만 표시하도록 단순화했으며, 더 보기 버튼을 `Button`에서
`Link(react-router)`로 바꿔 `/research/{symbol}/news`로 이동시킵니다. 노출
조건은 현재 탭 항목이 1건 이상이면 항상 노출하는 방식으로, 기존의 "3건 초과일
때만 노출" 조건보다 넓어졌습니다. 이는 설계 문서 3절에 명시된 의도적 변경입니다.

둘째, 두 페이지(`ResearchPage`, 신규 `ResearchNewsPage`)가 공유해야 하는 코드를
추출했습니다. `NewsDisclosureList`(compact/full variant 렌더 컴포넌트)는
`src/widgets/NewsDisclosureList/`로, 카테고리 톤 헬퍼(`categoryToneClassNames`,
`getCategoryToneClassNames`)는 `src/features/research/categoryTone.ts`로
옮겼습니다. diff 대조 결과 두 추출 모두 원본 JSX·클래스명·조건 분기가 문자
그대로 보존되어 있어 렌더 결과 동일성이 지켜집니다.

셋째, 신규 `ResearchNewsPage`는 `useParams`로 symbol을 얻고 기존
`useAssetIdBySymbol` 훅(이번 PR에서 쿼리 키만 `['assets', 'by-symbol', symbol]`
→ `['asset-id', normalizedSymbol]`로 변경, 정규화된 symbol을
`fetchAssetIdBySymbol`에 전달하도록 수정됨)으로 assetId를 얻은 뒤, 기존
`useNewsDisclosure(assetId)`를 그대로 재사용합니다. `useNewsDisclosure`는
이미 `enabled: assetId != null`로 게이팅되어 있어 두 쿼리의 순차 로딩이
안전하게 연결됩니다.

## Blocking Issues

차단 이슈는 없습니다. 라우트 매칭, 추출 컴포넌트의 렌더 동일성, 쿼리
enabled 체이닝, 뒤로 가기 링크, 접근성(tablist/tab/aria-selected/
aria-controls) 모두 코드와 테스트로 확인했고 문제를 찾지 못했습니다.

라우트 매칭 관련해서는 설계 문서가 "`:symbol`보다 먼저 매칭되도록 배치"라고
명시했지만, 실제로는 `researchDetail`(`/research/:symbol`, 세그먼트 2개)이
`/research/AAPL/news`(세그먼트 3개) 경로 자체와 매칭되지 않으므로 선언 순서와
무관하게 충돌 여지가 없습니다. React Router v6는 등록 순서가 아니라 세그먼트
특이도로 라우트를 자동 정렬하므로, 현재 `router.tsx`에 반영된 선언 순서(정적
`researchNews`를 `researchDetail`보다 앞에 둠)는 방어적 배치일 뿐 실제로는
불필요하지만 해가 되지도 않습니다. 차단 사유는 아닙니다.

## Suggestions

**S1. `getResearchSymbol` 헬퍼가 두 페이지에 동일하게 중복 정의되어 있습니다.**
`ResearchPage.tsx`와 신규 `ResearchNewsPage.tsx` 양쪽에 `symbol?.trim()
.toUpperCase() || 'UNKNOWN'` 로직이 동일하게 복사되어 있습니다.
`NewsDisclosureList`나 `categoryTone.ts`처럼 공용 모듈로 추출할 수 있는
후보입니다. 기능상 문제는 없고 두 파일의 로직이 어긋날 위험도 현재는 낮으므로
후속 정리로 남겨도 무방한 수준입니다.

**S2. `ResearchNewsPage`에서 `assetIdQuery.isError` 분기(종목 정보를 불러오지
못했습니다)가 테스트로 커버되지 않습니다.** `ResearchNewsPage.test.tsx`의 네
개 테스트는 정상 렌더·탭 전환, 로딩 스켈레톤, 뉴스 쿼리 오류·재시도, 빈 상태만
다루고, symbol에 해당하는 asset을 찾지 못하는 경우(`SymbolNotFoundError`)의
`ErrorState` 렌더·재시도 버튼 동작은 검증하지 않습니다. 코드 자체는
`ErrorState` 재사용 패턴이라 위험도는 낮지만, 이번 PR이 새로 추가한 분기이므로
테스트 커버리지 관점에서는 공백입니다.

## Questions

**Q1. `useAssetIdBySymbol`의 쿼리 키 변경(`['assets', 'by-symbol', symbol]` →
`['asset-id', normalizedSymbol]`)이 이번 PR 이전에 이미 다른 곳에서
소비되고 있었는지 확인 부탁드립니다.** 브랜치 전체를 검색한 결과 이 훅은
`queries.ts` 정의부 외에 프로덕션 코드에서 실사용된 곳이 이번 PR의
`ResearchNewsPage`가 처음으로 보입니다(선행 PR #191에서 정의만 되고 아직
소비되지 않았던 것으로 추정됩니다). 만약 다른 화면에서 이미 이 쿼리 키를
참조해 캐시 무효화 등을 하고 있었다면 키 변경으로 캐시 재사용이 끊길 수
있으니, 실사용 이력이 없다는 전제가 맞는지 확인을 부탁드립니다.

## Final Recommendation

차단 이슈는 없습니다. 범위는 설계 문서·이슈 #187과 정확히 일치하고, 보호
파일 변경도 없으며, `NewsDisclosureList`·`categoryTone` 추출은 렌더 결과를
바꾸지 않았음을 diff로 확인했습니다. 로컬 검증 4종과 PR CI가 모두 통과했고
테스트 수(509)도 PR 설명과 일치합니다. S1·S2는 후속으로 처리해도 무방한
수준이며, Q1은 머지를 막을 사유라기보다 확인 차원의 질문입니다. 머지 권한은
개발자에게 있습니다.
