# PR #304 로컬 리뷰 — 뉴스 인사이트 개요 관제 배치 재구성 (#303)

## Review Summary

에픽 #198의 설계 갱신("개요 화면 배치 — 관제 화면 재구성", 2026-07-23)을 구현하는 PR입니다. `main` 대비 두 커밋으로, 설계 문서 반영(`e2787c8`)과 구현(`3896b12`)이 함께 들어 있습니다. 구현은 Codex가 단독 진행했고, 로컬 검증 후 커밋했습니다.

개요 화면을 스크롤 없이 한 화면에 들어오는 관제(cockpit) 배치로 재구성합니다. 핵심 메커니즘은 세 가지입니다. 첫째, 개요 페이지를 2xl 이상에서 뷰포트 높이에 고정하고(페이지 스크롤 제거) 넘치는 영역은 각 패널 내부 스크롤로 처리합니다. 둘째, 관제 배치에 들어가는 위젯에 `compact` prop을, `AgentPipelinePanel`에는 `presentation: 'inline' | 'popover'` prop을 추가해 밀도 높은 표현을 함께 제공합니다(`AgentPipelinePanel`은 헤더에 popover로 배치). 셋째, 공통 밀도·타이포·`cockpit-*` 토큰을 설계 이미지에 맞춥니다. 대상은 개요 페이지와 9개 위젯, 공통 `PanelHeader`입니다. 계약이 없는 지표(BE #387·#394 등)는 기존 표기(`—`·수치만)를 유지합니다.

이번 리뷰는 정보 손실 여부, 신규 토큰의 실제 정의, 접근성, 검증 통과를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. compact·popover 파이프라인 그리드의 `min-w-[52rem]`은 내부 가로 스크롤을 유발 — 정보 보존을 위한 의도된 트레이드오프, 허용.** `AgentPipelinePanel`은 compact·popover에서 7단계를 `grid-cols-7` + `min-w-[52rem]`로 배치해, 좁은 컨테이너에서는 컨테이너 내부 가로 스크롤이 생깁니다. 이는 단계를 접거나 생략하지 않고 7개를 모두 보이게 하려는 선택으로, 설계 원칙("표시 정보 유지, 줄이는 것은 장식")과 일치합니다. 후속으로 단계 수가 늘면 재검토하면 됩니다.

## Questions

**Q1. 새로 쓰인 `cockpit-*` 토큰이 실제 테마에 정의돼 있는지 — 리뷰 중 확인해 해소.** typecheck는 Tailwind 클래스의 존재를 검증하지 않으므로, `cockpit-text`·`cockpit-surface`·`cockpit-border` 등이 정의됐는지 확인했습니다. `src/index.css`에 `--color-cockpit-*` 전 계열이 정의돼 있고 `origin/main`에도 기존 존재합니다. 미정의 토큰으로 스타일이 무시되는 문제는 없습니다.
