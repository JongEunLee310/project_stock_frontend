# PR #130 로컬 리뷰 — feat: 동기화 버튼에 관심종목 분석 트리거 연동

리뷰어: value-for-fable:itsvff (Sonnet) — 구현 비관여 교차모델 리뷰

## Review Summary

`Topbar` 동기화 버튼 클릭 시 `POST /worker/jobs/analysis`로 분석 잡 큐잉을 먼저 요청한 뒤 기존 React Query 캐시 무효화를 수행하도록 연동하는 PR입니다(이슈 #129, BE PR #244 선행).

핵심 구조는 `handleRefresh` 내부 `finally` 이중 가드입니다. 외부 `try`가 관심목록 조회와 트리거 호출을 묶고, `finally`에서 `queryClient.invalidateQueries()`를 호출합니다. 그 안에 또 한 번 `try...finally`를 두어 `invalidateQueries` 자체가 던지더라도 `setLastSyncedAt`이 반드시 실행되도록 보장합니다. 설계 §4.3이 요구한 "트리거 결과와 무관하게 캐시 무효화·시각 갱신 항상 실행" 조건을 이 구조가 충족합니다.

변경 범위는 핸드오프가 지정한 네 파일(`mutations.ts` 신규, `Topbar.tsx`, `Topbar.test.tsx`, `errorCodes.ts`)로 정확히 제한됩니다.

세부 확인 사항은 다음과 같습니다.

- **경로 리터럴**: `apiPost<AnalysisJob>('/worker/jobs/analysis', ...)` — `client.ts:70-71`의 base URL이 `/api/v1`까지 포함하므로 코드에는 `/worker/jobs/analysis`만 씁니다. 설계 §4.1과 일치합니다.

- **상태 문구 리터럴 일치 (§4.4 정본)**: `'idle'`→`동기화`, `'requested'`→`동기화 요청됨`, `'rate-limited'`→`잠시 후 다시 시도해 주세요 (약 60초)`. 세 문구 모두 §4.4 정본과 문자 단위로 일치합니다. `rate-limited` 상태에서 시각(`HH:mm`)이 조건부로 숨겨지는 것도 §4.4 테이블대로입니다.

- **`RATE_LIMIT_EXCEEDED` 판별**: `error instanceof ApiError && error.code === 'RATE_LIMIT_EXCEEDED'` 조건으로 판별하고, `errorCodes.ts`에 `RATE_LIMIT_EXCEEDED: '잠시 후 다시 시도해 주세요 (약 60초)'`가 추가되어 `unwrapEnvelope`가 올바른 `ApiError`를 생성합니다.

- **테스트**: 트리거 성공·429·네트워크 오류·시각 갱신 유지 케이스를 각각 독립 테스트로 커버합니다. 성공 케이스는 `invocationCallOrder`로 트리거가 `invalidateQueries`보다 먼저 호출됨을 단언해 순서 요건도 검증합니다. 기존 테스트는 `async` 전환 외 단언 변화가 없습니다.

- **스코프·보호 파일**: 핸드오프 `Out of Scope` 항목 변경 없음, `docs/harness/` 및 `AGENTS.md`·`CLAUDE.md` 미변경입니다.

## Blocking

블로킹 이슈는 없습니다.

## Suggestions

**S1 빈 관심목록 경로 테스트 누락**

핸드오프 Test Requirements에 "빈 관심목록(빈 목록) 각 경우에 캐시 무효화 지속" 케이스가 요건으로 명시되어 있으나, 추가된 테스트 네 건에는 `apiGetMock.mockResolvedValue({ data: [] })` 경우가 없습니다. 구현 자체는 `if (firstWatchlist)`로 올바르게 처리하므로 런타임 회귀 위험은 없고, 빈 목록 경로는 네트워크 오류 테스트와 구조적으로 유사합니다. 필수 변경은 아니지만, 후속 PR이나 이 브랜치에서 짧은 테스트 한 건을 추가해 요건 대응을 완성하면 좋습니다.

심각도: non-blocking, 후속 권장.

**S2 `RATE_LIMIT_EXCEEDED` 픽스처에 BE 계약 출처 주석 부재**

`Topbar.test.tsx`에서 `new ApiError('RATE_LIMIT_EXCEEDED', '잠시 후 다시 시도해 주세요 (약 60초)')` 픽스처를 합성할 때 BE PR #244가 반환하는 `error.code` 값이 `"RATE_LIMIT_EXCEEDED"`임을 확인한 출처 주석이 없습니다. 현재는 핸드오프 배경 섹션에 BE 계약이 명시되어 있어 사실 추적이 가능하지만, `quality-process-policy.md`의 Real-Contract Fixtures 규율은 픽스처 파일 안에 출처를 남기도록 권장합니다. 짧은 주석으로 보완하면 미래의 판별 로직 변경 시 추적성이 높아집니다.

심각도: non-blocking, 선택 권장.
