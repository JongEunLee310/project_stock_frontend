# PR #92 — watchlist AI 관찰 메모 와이어링 (feat/watchlist-observations-wiring)

리뷰어: Claude Code (Opus, 오케스트레이터). 구현: Codex. 브랜치: feat/watchlist-observations-wiring → main. 관련: FE #86, 설계 75, Pair BE 060(PR #158).

## Review Summary

설계 75대로 WatchlistPage의 "AI 관찰 메모" 카드를 `mockWatchlistObservations`에서 BE 관찰 메모 API(`GET /watchlists/{watchlist_id}/observations`)로 전환했습니다. briefing 슬라이스 패턴을 그대로 따라 신규 슬라이스 `src/features/watchlist-observations/`(dto·adapter·query)를 추가하고, 카드 렌더를 평면 리스트에서 `summary` 리드 문단 + 심볼별 노트 리스트 구조로 바꿨습니다.

`useWatchlistObservations()`는 `usePortfolioBriefing`과 동일하게 `/watchlists?page=1&size=20`로 첫 watchlist를 해소한 뒤 `/watchlists/{id}/observations`를 호출하고, watchlist가 없으면 `null`을 반환합니다. `adaptWatchlistObservations`는 `summary`·`items`를 매핑하고 `items ?? []`로 방어하며 `generated_at`을 버립니다(briefing 선례). 도메인 타입 `WatchlistObservations`·`WatchlistObservationItem`은 `AiBriefing`·`WatchlistObservation`과 동일하게 `shared/model`에 정의했습니다.

설계 §의 결정이 모두 반영됐습니다: (1) 별도 슬라이스 배치, (2) dto snake_case 보존, (3) 신규 도메인 모델·`generated_at` 폐기, (4) `items ?? []` 방어 adapter, (5) 첫 watchlist 해소·null 반환 query, (6) mock 복귀 없는 degradation, (7) mock 정의 유지·사용처만 제거.

## Suggestions

**S1 · "더 보기" 버튼 미동작 (비차단, 기존 상태 유지)**

카드 하단 "더 보기" 버튼은 이전과 동일하게 `onClick`이 없는 장식 상태로 남아 있습니다. 관찰 메모 상세·페이지네이션은 설계 §2에서 범위 밖으로 뒀으므로 스코프 내이며, 동작 연동은 후속(관찰 메모 확장 또는 Topbar/동작 트랙 #91 계열)에서 다룰 여지입니다. 현 단계 비차단입니다.
