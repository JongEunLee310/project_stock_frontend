# PR #306 로컬 리뷰 — 프론트엔드 스킬 활성화 — react-patterns·react-performance·react-testing·coding-standards 배선 (#305)

## Review Summary

커밋돼 있으나 `skillOverrides`가 없어 명시적으로 배선되지 않던 프론트엔드 스킬을 활성화해 구현·리뷰의 참조 근거로 배선하는 harness 설정 PR입니다. 애플리케이션 코드(`src/`) 변경은 없습니다. BE의 동일 작업(`project_stock#424`/PR #425)과 대칭입니다.

두 소비자를 각각 배선했습니다. Claude Code는 `.claude/settings.json`에 `skillOverrides`를 신설해 `react-patterns`·`react-performance`·`react-testing`·`coding-standards`를 `on`으로, `api-design`·`autonomous-agent-harness`·`autonomous-loops`를 `off`로 명시했습니다. Codex는 자동 발견 메커니즘이 없으므로 `.codex/instructions.md`에 네 스킬의 `SKILL.md` 경로를 참조로 배선했습니다. 정책 정합으로 `docs/harness/skill-usage-policy.md`가 템플릿의 "커밋 금지" 규정과 파생 프로젝트의 스킬 사용을 구분하도록 정정됐고, `docs/agent/skill-policy.md`를 신설해 프론트 4개를 reference 허용으로 명시했으며, `docs/knowledge/workflow.md`에 활성화 사실을 기록했습니다.

이번 리뷰는 스킬 선정의 타당성, 두 에이전트 배선의 정확성, 설정 파일 무결성을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. `coding-standards`를 BE와 달리 활성화한 근거의 일관성 — 프로젝트 성격에 따른 의도된 차이, 허용.** BE(`#424`)에서는 `coding-standards`를 프론트엔드 위주라는 이유로 제외했으나, FE에서는 같은 이유로 활성화했습니다. 이 스킬은 React/TypeScript 관례(명명·불변성·가독성)를 담고 있어 FE에 직접 관련되므로, 두 저장소의 상반된 결정은 각 스택에 맞춘 일관된 판단입니다. 정책 문서에도 이 근거가 기록돼 있습니다.

## Questions

**Q1. `.codex/instructions.md`가 참조하는 네 SKILL.md 경로가 실재하는지 — 리뷰 중 확인해 해소.** Codex는 스킬을 자동 로드하지 않고 instructions.md의 참조로만 인지하므로, `react-patterns`·`react-performance`·`react-testing`·`coding-standards`의 `.codex/skills/<name>/SKILL.md`가 실재하는지 확인했습니다. 네 경로 모두 존재합니다.

## CI Result

harness 설정·문서 변경이라 애플리케이션 코드 게이트(`format:check`·`typecheck`·`lint`·`test`)의 대상이 아닙니다. 리뷰어(Claude Code)가 2026-07-24에 다음을 확인했습니다.

- `.claude/settings.json` — `python3 -c json.load` 파싱 통과(유효 JSON).
- `skillOverrides` 최종값 — 프론트 4개 `on`, 나머지 3개 `off`로 의도와 일치.
- `.codex/instructions.md`가 참조하는 4개 `SKILL.md` 경로 모두 실재.
- 변경 파일은 `.claude/settings.json`·`.codex/instructions.md`·`docs/agent/skill-policy.md`(신설)·`docs/harness/skill-usage-policy.md`·`docs/knowledge/workflow.md` 5건이며 `src/` 변경 없음.

## Documentation Impact

이 PR은 문서·설정이 산출물입니다. `docs/agent/skill-policy.md`가 활성 스킬의 정본 상태가 되며, `docs/harness/skill-usage-policy.md`의 템플릿/프로젝트 구분과 `docs/knowledge/workflow.md`의 Skill Usage 항목이 이를 뒷받침합니다. ADR은 불필요합니다 — 새 아키텍처 방향이 아니라 이미 커밋된 스킬의 활성화 스위치를 켜는 설정 변경이고, 자율 워크플로를 도입하지 않습니다. Failure Record도 불필요합니다.

## Final Recommendation

머지 가능합니다. 스킬 선정은 프로젝트 성격에 부합합니다 — `react-patterns`·`react-performance`·`react-testing`은 React/Vite/Vitest 스택에 직접 관련되고, `coding-standards`는 FE의 React/TS 관례로서 활성화되며, 제외한 `api-design`(소비 전용)·`autonomous-*`(정책 제약)는 근거와 함께 `off` 유지됩니다. 두 에이전트 배선이 각 로딩 메커니즘에 맞게 정확합니다 — Claude Code는 `skillOverrides`, Codex는 instructions.md 참조(경로 실재 확인됨). 설정 파일은 유효 JSON입니다. Protected Files 개념상 `.codex/instructions.md`를 수정했으나, FE 저장소는 protected-files 훅이 배선돼 있지 않으며 변경은 사용자의 명시적 요청에 따른 스킬 활성화 범위에 필수적입니다. Blocking은 없고, Suggestions S1은 스택별 의도된 차이, Questions Q1은 리뷰 중 해소됐습니다.

최종 머지 권한은 개발자에게 있습니다.
