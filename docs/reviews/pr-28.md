# PR #28 Local Review — 공통 Status Badge 상태·리스크 레벨 확장 (task-005 / 이슈 13)

## Review Summary

task-005 핸드오프 구현 리뷰. `StockStatus`에 `관망 유지`·`비중 축소 검토`를 추가하고, 리스크 레벨은 별도 `RiskLevel`(`높음`/`중간`/`낮음`) 타입으로 분리했다. `src/index.css` `@theme`에는 신규 상태·레벨 색상 토큰을 추가만 했고 기존 토큰은 변경하지 않았다. `Badge`는 `status` XOR `riskLevel` discriminated union으로 확장되어 두 군을 한 컴포넌트로 표현한다. 핸드오프 Goal·Implementation Scope·Test Requirements를 충족하며 Out of Scope(페이지 배치, 도메인 모델 대확장) 침범 없음.

검토 항목:

- `StockStatus`(model)와 `RiskLevel`(신규 `shared/model/riskLevel.ts`)을 분리 — 핸드오프의 "개념 혼합 금지" 요구 충족.
- 색상 매핑을 `Record<StockStatus, string>` / `Record<RiskLevel, string>`로 작성 — 값 추가 시 매핑 누락이 typecheck에서 차단(확장 용이 구조 충족).
- 보호 파일 `src/index.css`는 신규 토큰 추가만, 기존 `@theme` 토큰 수정·삭제 없음 — 보호 규칙 준수(diff로 확인).
- Badge children 미지정 시 상태/레벨 라벨 출력하는 기존 동작 유지.
- `shared/README.md`에 상태/레벨 추가 절차(union + 토큰 + 매핑 동시 갱신)를 문서화 — 확장 가이드 보강.

로컬 검증(worktree): `pnpm lint`·`pnpm typecheck`·`pnpm test`(16/16)·`pnpm build` 전부 통과.

## Blocking

None.

## Suggestions

- `status-watch-hold`(관망 유지) 색이 `status-watch`(관망)와 동일 노랑 계열로 근접 — 두 상태의 시각적 구분이 약할 수 있다. 후속 페이지 구현에서 실제 배지를 나란히 두고 대비를 점검 권장.
- `level-high`/`level-medium`/`level-low` 토큰 값이 각각 `risk`/`watch`/`stable` 색상값을 그대로 복제. 같은 의미=같은 색 의도라면 적절하나, 토큰 값 중복이라 향후 색 조정 시 두 곳을 동기화해야 한다. CSS 변수 alias(예: `var(--color-status-risk-bg)`) 참조로 단일 출처화하는 방안 고려 가능(선택).

## Questions

- 리스크 레벨 `높음` 배지와 상태 `위험 증가` 배지가 동일한 색으로 보이는 것이 의도된 동작인지(화면에서 두 개념이 함께 노출될 때 혼동 여지). 의도라면 그대로 두고, 아니라면 레벨군 톤을 차별화.
