# PR #276 로컬 리뷰 — 토픽 종목 민감도·키워드 관계망 (#265)

## Review Summary

토픽 상세 페이지의 2차 placeholder 두 자리(키워드 관계망·종목 민감도)를 실데이터로 교체한 PR입니다. 단일 커밋(`feat: 토픽 키워드 관계망과 종목 민감도 구현`)입니다.

기존 `src/features/news-insights/`에 두 query(`useNewsTopicSymbolsQuery`·`useNewsTopicGraphQuery`)와 dto·adapter를 추가했고, enum presentation 맵(relationship·valuation_burden·signal 라벨/톤)을 확장했습니다. 두 query 모두 `enabled: topicId.length > 0` 가드를 둡니다. 위젯 2종을 신설했습니다.

**Part A — 키워드 관계망(#265, 스펙 §5.5).** `TopicKeywordGraph`는 개요 토픽 맵(`src/widgets/TopicMap/`)의 Cytoscape lazy-load 패턴을 재사용합니다. 노드 크기는 언급량, 색은 감성, edge 굵기는 연관 강도로 **연관 강도와 감성을 별도 시각 요소로 분리**했습니다. 노드 탭 시 `SelectedKeyword` 패널에 선택 키워드의 관련 종목·이벤트를 표면화해 "장식용 그래프 금지" 요건을 충족합니다. Cytoscape 인스턴스는 재바인딩 시 이전 인스턴스를 destroy하고 언마운트 시 cleanup합니다.

**Part B — 종목 민감도(#265, 스펙 §5.8).** `TopicSymbolSensitivity`는 표로 종목·노출도·영향 방향·관계 유형·밸류 부담·포트폴리오 비중·현재 시그널을 렌더합니다. **노출도(막대+수치)와 영향 방향(별도 배지)을 시각적으로 분리**했고, null 필드(밸류 부담·비중·시그널)는 "—"·"미보유"로 명시합니다. 패널은 그리드 전체 폭(`xl:col-span-3`)을 차지합니다.

두 위젯은 각자 `topicId`를 받아 내부에서 query를 호출하며 독립 loading·error·empty를 처리합니다. 페이지는 `keywordGraph` placeholder를 `TopicKeywordGraph`로 교체하고 `TopicSymbolSensitivity`를 추가했으며, `investorReaction` placeholder는 #264 범위로 좁혔습니다.

이번 리뷰는 계약 일치, 노출도/방향·강도/감성 분리 원칙, 그래프 상호작용(장식 금지), Cytoscape 생명주기, 부분 실패 격리를 축으로 봤습니다.

## Suggestions

**S1. 패널이 query를 내부 호출하는 패턴 — 자기완결적 패널로 허용, 라운드1 패턴과 차이 인지.** 라운드1 위젯(`TopicTrendChart` 등)은 페이지가 query를 소유하고 data·상태를 props로 내려주는데, 이번 두 위젯은 `topicId`만 받고 내부에서 query를 호출합니다. 자기완결적 패널로 동작·부분 실패 격리에 문제가 없고 페이지가 단순해지는 이점이 있어 허용합니다. 다만 페이지 테스트에서 query mock 위치가 위젯별로 달라지므로, 이후 패널 추가 시 한 패턴으로 수렴하는 편이 유지보수에 낫습니다.

## Questions

**Q1. 감성 색상 임계.** 그래프 노드 색은 `sentimentColor`가 `sentiment_score`(0~1)를 0.34·0.67 임계로 부정/중립/긍정으로 나눠 칠합니다. 색만으로 상태를 표현하지 않도록 노드 하단 배지·범례(부정/중립/긍정 감성)를 병기해 접근성을 확보했음을 확인했습니다. 임계값은 표현용 파생이며 BE 수치를 변경하지 않습니다.
