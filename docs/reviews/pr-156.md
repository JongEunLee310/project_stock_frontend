## Suggestions

**S1. 같은 심볼에서 `section`이 바뀔 때 재스크롤이 되지 않습니다**

effect의 조기 반환 조건은 `focusedSymbolRef.current === displaySymbol`입니다.
심볼은 같은데 쿼리만 `?section=briefing`에서 `?section=risks`로 바뀌는 경우
ref가 이미 설정되어 있어 effect가 무동작으로 통과합니다. 현재 진입 지점(시그널
"근거 보기"·대시보드 우선 확인 큐)은 서로 다른 섹션으로 보내지만 같은 심볼에
대해 `section`을 바꾸는 UI 경로가 없으므로 실제 영향은 없습니다. 다만 향후
탭·링크 추가 시 혼란이 생길 수 있어, ref를 `{ symbol, section }` 객체로
바꾸거나 `focusedSymbolRef.current = ${displaySymbol}#${section}` 형태로 키를
구분하는 쪽이 방어적입니다.

심각도: 비차단, 향후 진입 지점 추가 전 정리 권장.

**S2. 레이아웃 외 카드에 `tabIndex={-1}`가 부여되어 포커스 순서에 영향이 있습니다**

`RiskPanel`·`ChecklistPanel`·`ReportsPanel` 카드에 `tabIndex={-1}`가 추가됩니다.
이 값은 키보드 탭 순서에서 제외되되 프로그래밍 방식 포커스(`focus()`)는 가능하게
하는 올바른 설정입니다. 딥링크 진입 시 키보드 사용자가 포커스를 받은 카드에서
바로 탭을 눌러 내부 상호작용 요소로 이동할 수 있어 접근성 관점에서 적절합니다.
단, 브라우저마다 `tabIndex={-1}` 컨테이너에 포커스가 설정된 후 포커스 링이
시각적으로 보이지 않을 수 있어, 포커스 스타일(`focus-visible` 등)이 카드
컨테이너에 지정되어 있지 않다면 사용자가 어디에 포커스가 있는지 알기 어렵습니다.
현재 `Card` 컴포넌트의 포커스 링 처리 여부는 이 PR 범위 밖이므로 차단하지
않습니다.

심각도: 비차단, 접근성 후속 이슈로 분리 권장.

## Questions

**Q1. `section` 의존성이 effect 배열에 포함되어 있으나 `section` 변경만으로 재실행이 막히는 이유가 명시적이지 않습니다**

`useEffect`의 deps는 `[displaySymbol, research, section]`이어서 `section`이
바뀌면 effect가 재실행됩니다. 그러나 조기 반환 조건에서 `focusedSymbolRef.current
=== displaySymbol`가 이미 참이므로 실질적으로 아무 동작도 하지 않습니다. 이 설계는
의도적인 것(심볼당 1회만 처리)으로 읽히지만, deps에 `section`이 있으면서 실제로는
`section` 변경에 반응하지 않는다는 사실이 코드 내 주석 없이는 혼란을 줄 수 있습니다.
의도가 "심볼당 1회 보장"이라면 deps에서 `section`을 제거하는 것이 더 명확합니다.
단, 이를 바꾸면 eslint-plugin-react-hooks 경고가 발생할 수 있어 `// eslint-disable`
처리가 필요할 수 있습니다. 현재 동작 자체는 올바르므로 차단하지 않습니다.

심각도: 문의(의도 확인 후 처리).

## Final Recommendation

**Blocking이 없습니다. 머지 가능 판단입니다.**

section 처리 effect는 `!research` 조건으로 데이터 로드 전 미실행을 보장하고,
`research.symbol.toUpperCase() !== displaySymbol` 조건으로 데이터가 이전 심볼에
속한 경우도 차단합니다. 심볼 전환 시 재실행은 `focusedSymbolRef`가 새 심볼과
불일치하므로 자동으로 처리됩니다. PR #140 당시의 의존성 배열 함정(초기화 전
effect 실행 또는 재실행 누락) 패턴은 발견되지 않았습니다.

링크 부착 범위는 설계 문서 명시에 정확히 부합합니다. 시그널 "근거 보기"와
대시보드 우선 확인 큐만 변경됐고, 시그널 카드 헤더·레일·대시보드 내 나머지
리서치 링크는 그대로입니다. `src/features/`·`src/shared/`·라우트 정의는 전혀
변경되지 않았습니다.

테스트는 설계 문서의 세 요건(스크롤+포커스 호출·무효 값 무동작·심볼 전환
재실행)을 모두 단언하며, `scrollIntoView` jsdom mock과 탐색 경로 확인이 충실히
갖춰져 있습니다. 434개 테스트 전부 통과합니다.

S1(section 변경 시 재스크롤 미지원)은 현재 진입 경로에서 발생하지 않으므로
후속 정리 대상입니다. S2(카드 포커스 링 스타일)는 `Card` 컴포넌트 범위 문제여서
별도 접근성 이슈로 분리가 적절합니다. Q1은 의도 확인 후 필요시 deps 정리 또는
주석 추가로 처리할 수 있습니다.

최종 머지 권한은 개발자에게 있습니다.
