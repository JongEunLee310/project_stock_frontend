# PR #212 — 리서치 가격 차트 표시 문제 3건 수정 (fix/211-chart-polish)

리뷰어: Claude Code (Sonnet, Value-for-Fable 세션). 구현: Codex(gpt-5.6-sol). 브랜치: fix/211-chart-polish → main. 관련: 이슈 #211, 핸드오프 `.codex/tasks/task-078-chart-polish.md`, BE 짝 #317(1D 5분 간격 전환).

## Review Summary

이슈 #211이 지적한 리서치 가격 차트의 표시 문제 3건을 핸드오프 태스크 범위대로 수정했습니다.

첫째, `LineChart.tsx`와 `BarChart.tsx`의 `<Tooltip>`에 `chartTheme` 기반 `contentStyle`/`labelStyle`/`itemStyle`을 적용했습니다. 기존 Recharts 기본 스타일 대신 배경 `#111827`, 텍스트 `#e2e8f0`, 보더 `#334155`를 신설 `chartTheme` 상수로 추가해 다크 배경에서 충분한 대비를 확보했습니다. `showTooltip`을 쓰는 소비처는 저장소 전체에서 `ResearchPage.tsx`가 유일해 이번 스타일 변경이 다른 화면에 회귀를 일으킬 여지가 없습니다.

둘째, 1D 호버 시간 포맷을 위해 `shared/lib/format/datetime.ts`에 `formatKstDateTimeCompact`를 추가했습니다. `Intl.DateTimeFormat`을 `timeZone: Asia/Seoul`·`hourCycle: 'h23'`로 호출해 `formatToParts` 결과를 직접 조립하는 방식이라, 자정 시각을 `24:00`으로 잘못 표기하는 일부 엔진의 알려진 버그를 피합니다. `ResearchPage.lib.ts`의 `formatResearchChartTooltipLabel`은 정규식 `/^\d{4}-\d{2}-\d{2}T/`로 라벨이 ISO datetime(`T` 포함)인지 판별해 intraday만 변환하고, 일봉의 `YYYY-MM-DD` 라벨은 그대로 반환합니다. `LineChart`에는 `tooltipLabelFormatter` optional prop을 신설해 이 포맷터를 주입하며, 값을 넘기지 않는 기존 호출부는 `undefined`가 그대로 Recharts `labelFormatter`에 전달되어 동작이 바뀌지 않습니다.

셋째, 현재가 pill 클램프는 `renderLastValueShape`에 `plotTop`·`plotBottom` 인자를 추가해 pill 중심 y좌표(`labelCenterY`)를 `[plotTop + RADIUS, plotBottom - RADIUS]` 범위로 고정하는 방식으로 구현했습니다. 호출부(`LineChart` 본문)는 `margin.top`과 `height - margin.bottom`을 그대로 넘깁니다.

## Suggestions

**S1 · 클램프 시 원(circle)과 pill이 수직으로 어긋남 (비차단, 후속 검토 권장)**

`renderLastValueShape`는 pill(사각형·텍스트)의 중심만 클램프하고, 데이터 포인트를 표시하는 원(`<circle cx={cx} cy={cy} .../>`)은 원본 `cy`를 그대로 사용합니다. 클램프가 실제로 발동하는 구간(현재가가 구간 최저·최고인 경우)에서는 원이 실제 데이터 위치에, pill이 그보다 안쪽으로 당겨진 위치에 그려져 둘의 중심이 최대 `LAST_VALUE_PILL_RADIUS`(11px)만큼 어긋납니다. 클램프 이전에도 둘을 잇는 연결선은 없었지만, 기존에는 항상 같은 y좌표를 공유했기 때문에 이번 변경으로 시각적 정합이 새로 깨지는 지점입니다. 이슈의 핵심 요구사항(잘림 방지)은 충족하므로 비차단이며, 후속 폴리시로 원과 pill을 잇는 짧은 연결선을 추가하거나 원도 함께 클램프 범위 안으로 당기는 방안을 검토할 수 있습니다.

**S2 · plotBottom 계산이 XAxis 높이를 반영하지 않음 (비차단, 현재 시나리오에서는 안전)**

클램프 경계 `plotBottom = height - (margin.bottom ?? 0)`은 Recharts가 `<XAxis>` 렌더링 시 자동으로 소비하는 축 높이를 빼지 않습니다. 이슈가 실제로 재현되는 조합은 `PriceSparkline`이 `hasVolume`일 때 `hideXAxis`를 켜는 1D 케이스라 축 높이 문제가 없고, 축이 보이는 경우(`hasVolume=false`)는 실제 플롯 하단이 이 추정치보다 항상 위쪽이라 클램프가 과소 적용될지언정 잘림을 만들지는 않습니다. 다만 향후 margin·축 구성이 바뀌면 어긋날 수 있는 근사치라는 점은 남겨둡니다.

**S3 · 거래량 BarChart 툴팁의 1D 라벨은 여전히 ISO 원문 (비차단, 범위 밖)**

`ResearchPage.tsx`의 거래량 `BarChart`(464행)는 `showAxes`가 켜져 있고 `xDataKey="date"`를 그대로 사용하지만, `BarChart` 컴포넌트에는 `labelFormatter`를 주입할 지점이 없습니다. 1D 구간에서 거래량 막대에 개별적으로 마우스를 올리면 툴팁 라벨이 여전히 ISO datetime 원문으로 노출됩니다. 이슈 본문과 핸드오프 태스크 모두 `BarChart`에는 스타일 정렬만 요구했고 라벨 포맷은 범위에 없었으므로 이번 PR의 범위 미달은 아니지만, 가격 차트 툴팁과의 일관성 관점에서 후속 이슈로 남길 만합니다.
