# PR #258 로컬 리뷰 — 판단 상세 2차 (#253)

## Review Summary

판단 기록 재설계 2차 FE입니다. 판단 상세(`widgets/decision-detail`)의 "2차 기능" placeholder 카드를 실제 구현으로 대체합니다. 대부분 상세 응답과 복기 목록에 이미 있는 데이터로 구성합니다.

당시/현재 비교는 `detail.snapshots`의 당시 값과 현재 값을 나란히 표시하며, 종목 대상의 현재가는 기존 가격 소스를 재사용하고 현재값 소스가 없는 지표는 `—`로 둡니다. 스냅샷은 immutable로 유지하고 현재 값으로 덮어쓰지 않습니다. 변화 타임라인은 `created_at`·`activated_at`·`reviewed_at`·`review_triggers[].triggered_at`와 복기(`useDecisionReviews`) 이벤트를 시간순으로 표시합니다. 버전 이력은 `superseded_by_id`가 있을 때 대체 판단 링크를 노출합니다. `adapters.ts`·`dto.ts`에 필요한 필드가 보강됐고 `DecisionDetailPage`가 복기 목록과 연동됩니다.

이번 리뷰는 스냅샷 immutable 유지, 기존 데이터로의 구성, 설계 순서 원칙을 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 변화 타임라인이 외부 이벤트(뉴스·시그널 변화)가 아닌 판단 라이프사이클 기반 — 설계 확정 범위.** 타임라인은 판단 자신의 라이프사이클·트리거·복기 이벤트로 구성되고, 외부 이벤트 전체 타임라인은 신규 데이터 소스가 필요해 이번 스코프에서 제외했습니다(핸드오프 Out of Scope). 필요 시 뉴스·시그널 변화 이력을 잇는 후속으로 확장할 수 있습니다.

## Questions

**Q1. 스냅샷이 현재 값으로 덮어써지지 않는가.** 당시/현재 비교가 스냅샷 당시 값을 그대로 두고 현재 값을 별도 열로 표시함을 확인했고, 현재값 소스가 없으면 `—`로 처리합니다. 설계 §11의 immutable 원칙이 지켜져 해소됐습니다.
