# PR #279 로컬 리뷰 — 예상 자금 흐름 전망·시나리오 위젯 (#267)

## Review Summary

개요 "예상 자금 흐름"(§3.6)과 토픽 상세 "예상 자금 흐름 시나리오"(§5.9) placeholder 두 자리를 실데이터로 교체한 PR입니다. FE 3차의 첫 항목이며 단일 커밋(`기능: 자금 흐름 전망과 시나리오 위젯 추가`)입니다.

`src/features/news-insights/`에 두 dto·adapter(`adaptNewsFundFlowOutlook`·`adaptNewsTopicScenarios`)·query(`useNewsFundFlowOutlookQuery`·`useNewsTopicScenariosQuery(topicId)`, 후자는 `enabled` 가드)를 추가하고 FundFlowDirection·FlowLikelihood·ScenarioKind presentation 맵을 확장했습니다. 위젯 2종을 신설했습니다.

**Part A — 예상 자금 흐름(#267, 스펙 §3.6).** `FundFlowOutlookPanel`은 섹터별 방향·흐름 가능성 수준(`likelihood`)·예상 범위·신뢰도·주요 가정·위험 요인을 표시합니다. "흐름 가능성: 높음" 수준으로 표기하고 "확정 예측이 아닙니다"를 명시하며, `estimated_range`가 null이면 "범위 미제공"으로 폴백합니다. 개요 `plannedPanels`의 `fund-flow-outlook` 항목을 제거하고 위젯을 배치했습니다.

**Part B — 자금 흐름 시나리오(#267, 스펙 §5.9).** `FundFlowScenarioPanel`은 낙관·기준·보수 3 시나리오 카드를 항상 정렬된 순서로 렌더합니다. 가중치는 "현재 근거 기준 가중치 X%"로 표기해 통계 확률로 과표현하지 않고, "통계적 확률이나 확정 예측이 아닙니다" 문구를 병기합니다. 각 카드는 자금 방향·주요 가정·수혜/위험 섹터·관련 종목·무효화 조건을 담습니다. 토픽 상세 `plannedPanels.fundFlowScenario`를 대체했습니다.

두 위젯 모두 독립 query·부분 실패를 처리하며, 특히 시나리오 패널은 미분석 토픽의 BE 500과 3종 미완성 구성(`hasCompleteScenarioSet`)을 error 상태로 격리해 페이지 전체를 깨지 않습니다. 분석 버전(analysis_version)과 데이터 기준 시각(as_of)을 표기합니다.

이번 리뷰는 확정 예측 금지 표기, 가중치의 비확률적 서술, 근거 문장 병기, 미분석 토픽 500 격리, 두 페이지 회귀를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 시나리오 3종 미완성을 error로 처리 — 계약상 always-3 전제에서 합리, 대안 여지.** `FundFlowScenarioPanel`은 시나리오가 1건 이상이지만 낙관·기준·보수를 모두 갖추지 못하면 error 상태로 표시합니다. BE 계약이 항상 3종을 보장하므로 미완성은 데이터 이상으로 보는 판단이 타당합니다. 다만 부분 데이터라도 있는 카드만 보여주는 대안도 가능하므로, 실수집 단계에서 3종 보장이 흔들리면 재검토할 여지가 있습니다. 병합을 막지 않습니다.

**S2. BE S1(미분석 토픽 500)에 대한 FE 방어 확인.** BE PR #384 리뷰의 S1(데이터 없는 토픽 scenarios/explanation이 RuntimeError→500)을 FE가 패널 error 격리로 방어함을 확인했습니다. FE 부분 실패 처리가 이 500을 페이지 전체 오류로 전파하지 않으므로, BE 후속 완화(graceful 빈 응답) 전까지 사용자 영향은 해당 패널 error 상태로 제한됩니다.

## Questions

**Q1. 가중치 합계.** 시나리오 weight는 "현재 근거 기준 가중치"로 개별 카드에 %로 표기됩니다. 세 시나리오의 합이 100%가 아닐 수 있음을 UI가 강제하지 않으며(BE가 합을 보장하지 않음), 통계 확률이 아니라는 문구로 오인을 방지함을 확인했습니다. 합계 표시나 정규화는 하지 않는 것이 스펙(§5.9 과표현 금지) 취지에 맞습니다.

## Final Recommendation

머지 가능합니다. 핸드오프 요구사항을 항목별로 확인했습니다. 확정 예측 금지 표기("흐름 가능성"·"확정 예측이 아닙니다"), 가중치의 비확률적 서술("현재 근거 기준"), 숫자에 근거 문장 병기(가정·위험), 3 시나리오 카드 구성, 분석 버전·데이터 신선도 표기, 미분석 토픽 500과 미완성 구성의 error 격리가 모두 확인됩니다.

범위는 지켜졌습니다. 설명·반대 관점(#268)·캘린더·파이프라인(#269)·액션(#270)·폴링(#266)에는 손대지 않았습니다. Protected Files는 없으며 신규 npm 의존성 추가도 없습니다. 추가된 테스트는 두 query·adapter(성공·오류·빈 데이터), 두 위젯(outlook 섹터·근거·가능성 표기, scenario 3카드·가중치·무효화 조건·미완성 error), 개요·토픽 상세 페이지의 placeholder 교체·부분 실패를 덮습니다.

Blocking은 없습니다. S1·S2는 계약 전제·BE 후속 사항으로 병합을 막지 않으며, Q1은 가중치 표기가 스펙 취지에 맞음을 확인해 해소했습니다.
