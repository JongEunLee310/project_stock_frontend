## Review Summary

알림 관제 개편 라운드(에픽 #133)의 마지막 FE 조각으로, Signals 카드에서 Alerts Rule Builder로
넘어가는 단방향 deep-link를 연결합니다. ADR-013이 정한 원칙(Signals 화면에는 알림 보조 버튼
하나만 두고, 채널·규칙 테이블은 두지 않는다)을 그대로 지키면서 세 파일을 얕게 손댔습니다.

`SignalsPage`는 카드 하단 세 번째 버튼을 기존 `disabled` 자리표시에서 활성 버튼으로 바꾸고,
클릭 시 `navigate`로 `/alerts?builder=create&symbol={signal.symbol}`로 이동시킵니다. 표시
텍스트는 다른 두 버튼과 톤을 맞춰 "변화 알림"으로 짧게 두고, 접근성 이름(`aria-label`)만
"이 시그널 변화 알림 받기"로 전체 문구를 유지합니다. `AlertsPage`는 마운트 시
`useSearchParams`로 `builder=create`(+선택적 `symbol`) 쿼리를 읽어 Rule Builder를 create
모드로 열면서 `prefill: { templateType: 'NEWS_RISK_HIGH', targetId?: symbol }`을 넘기고,
같은 effect 안에서 `setSearchParams({}, { replace: true })`로 쿼리를 즉시 제거합니다.
`AlertRuleBuilder`는 선택적 `prefill` prop(`templateType`·`targetId`)을 추가했는데, create
모드 초기화 effect에서 기존 "첫 active 템플릿 seed" 로직 앞에 prefill 매칭 템플릿을 우선
탐색하도록 끼워 넣었습니다. `templateType`이 active 템플릿 중에 없으면 기존 첫 active 템플릿
fallback으로 자연스럽게 이어지고, `mode`가 `edit`/`duplicate`일 때는 그 분기가 조기 `return`
되므로 prefill 값 자체가 도달하지 않아 기존 계약을 건드리지 않습니다.

## Suggestions

**S1(경미). `AlertsPage`의 쿼리 소비가 `builder`·`symbol` 외 쿼리 파라미터를 함께
날립니다.** `setSearchParams({}, { replace: true })`가 전체 쿼리 스트링을 빈 객체로
교체하므로, 만약 다른 기능이 `/alerts`에 별도 쿼리 파라미터(예: 필터 상태 공유 링크)를
붙이게 되면 deep-link 진입과 동시에 그 파라미터도 삭제됩니다. 현재 `AlertsPage`에는 그런
파라미터가 없어 지금은 영향이 없고, 핸드오프도 전체 제거만 요구했으므로 범위 내 정상
구현입니다. 다만 후속으로 `/alerts`에 다른 쿼리 파라미터가 추가될 경우
`searchParams.delete('builder'); searchParams.delete('symbol')` 방식으로 바꿔두면
안전합니다.

**S2(경미). templates 로딩 전/후 두 단계로 렌더되는 짧은 과도 상태가 있습니다.**
`AlertRuleBuilder`의 prefill effect는 `templatesQuery`가 아직 비어 있을 때(`emptyTemplates`)
한 번 실행되어 `initialTemplate`을 찾지 못한 채 `targetId`만 prefill 값으로 설정하고,
템플릿이 로드된 뒤 effect가 재실행되며 `applyTemplate`으로 템플릿 필드를 채웁니다.
`applyTemplate` 내부가 `targetId`를 `''`로 초기화하지만 같은 effect 실행 안에서 바로 다음
줄이 `prefill.targetId`로 다시 set하므로 최종 렌더 값은 항상 올바르고, 테스트도
`waitFor`로 이 비동기 안정화를 반영하고 있어 실사용에 문제는 없습니다. 다만 로직이
"reset 후 즉시 재설정"에 의존하는 순서 결합이라, 추후 `applyTemplate`의 내부 순서가
바뀌면 조용히 깨질 수 있는 지점입니다. 정확성 문제는 아니므로 blocking은 아니지만, 두
줄 사이에 짧은 주석으로 "prefill.targetId가 applyTemplate의 초기화를 덮어써야 한다"는
의도를 남겨두면 유지보수에 도움이 될 것 같습니다.

개발자에게 있습니다.
