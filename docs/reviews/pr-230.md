## Review Summary

알림 관제 개편 FE의 마지막 조각으로, 결과(내역)·상세·채널 레이어와 페이지 통합을 완성합니다.
F1(요약 카드)·F2(규칙 테이블·빌더)가 만든 위젯을 `AlertsPage`가 조립해, 관제 요약 → 규칙·설정
→ 내역·결과 → 채널 순으로 배치하고 규칙(설정)과 내역(결과)을 `border-t` 구분선으로 시각적으로
분리합니다. 구 인박스(Alerts/Candidates 탭 UI)는 이 통합 레이아웃으로 대체됩니다.

세 위젯이 신설됩니다. `AlertHistoryPanel`은 severity·read·target_type 필터와 정렬·페이지네이션,
개별/일괄 읽음을 지원하고 행 클릭으로 상세를 엽니다. `AlertDetail`은 `triggered_value`를 단일
(`{metric,current,previous,threshold}`)과 복합(`{conditions:[...]}`) 양쪽으로 처리해 지표·현재값·
임계값·이전값을 표시하고, `evidence`는 스키마를 하드코딩하지 않고 `kind`를 헤더로·나머지 키-값을
라벨(+미지 키 fallback)로 일반 렌더합니다. `NotificationChannelPanel`은 채널 목록과 APP·EMAIL
추가를 지원하며 EMAIL은 `configuration.email`로 검증합니다(DISCORD/SLACK 미노출, BE 422와 일치).

기존 관례를 따릅니다: DTO(snake)→`adapt*`→도메인(camel), `apiGet`/`apiPost` 엔벨로프,
`alertKeys` 팩토리 확장, `@/shared/ui` 재사용, 중요도 색상은 배지 제한. `useAlertEvent`는
`enabled: id !== null`로 미선택 시 요청하지 않고, 읽음/채널 추가 성공 시 관련 키를 invalidate합니다.

## Suggestions

**S1(가장 중요, 후속 계약). 내역·상세가 채널별 전달 상태(PENDING/SUCCESS/FAILED)를 표시하지
못합니다.** BE `AlertEventProjection`에 전달 상태 필드가 없어(전달은 별도 `AlertDelivery`
모델이나 이벤트 계약에 노출되지 않음), 구현은 임의의 성공 상태를 만들지 않고 목록 도달 사실만
표시했습니다. 이는 핸드오프의 "stub 금지·정직 표기" 원칙을 따른 올바른 처리입니다. 실제 전달
상태를 보여주려면 BE 이벤트 목록/상세 projection에 delivery 상태를 포함하는 계약 확장이
필요합니다. F3 범위 밖의 후속 항목으로 분리하는 것을 권합니다.

**S2(정리). 구 인박스 전용 훅이 미참조 상태로 남아 있습니다.** 페이지 재구성으로 `useAlerts`·
`useReadAlert`·`useDismissAlert`·`useReadCandidate`·`useConfirmCandidate`가 더 이상 어디서도
참조되지 않습니다(외부 참조 0건 확인). export라 lint는 통과하지만 dead code입니다. `useAlertCandidates`는
`DashboardPage` 우선순위 큐가 사용하므로 올바르게 보존됐습니다. 미참조 훅과 그 테스트는 별도
정리 PR에서 제거해도 좋습니다(핸드오프가 제거를 선택 사항으로 허용).

**S3(경미). metric 라벨 맵이 중복됩니다.** `conditionText.ts`에 `alertMetricLabels`를
추가했는데, `AlertRuleBuilder`·`AlertRuleTable`도 각자 `metricLabels`를 가집니다. 한 곳으로
합치면 유지보수가 쉬워집니다. 동작 문제는 아닙니다.
