## Review Summary

리서치 페이지를 비롯한 공용 배지·버튼의 시각 톤을 research.png 기준의
저채도 칩 스타일에 맞춰 정리하는 변경입니다. `git diff main...HEAD` 기준
설계 문서 1개와 소스 3개 파일(`Badge.tsx`, `Button.tsx`, `stockStatus.ts`)에서
각 1줄씩만 바뀐 최소 diff입니다.

`Badge`(`src/shared/ui/Badge.tsx`)의 베이스 클래스는
`min-h-7 px-2.5 py-1 text-sm font-medium`에서
`min-h-6 px-2 py-0.5 text-xs font-semibold`로 축소되었고,
`badgeToneClassNames.accent`(`src/shared/ui/stockStatus.ts`)는 원색 면 채움
(`bg-app-accent-strong text-app-accent-text`)에서 저채도 조합
(`border-app-accent/40 bg-app-accent/15 text-app-accent`)으로 바뀌었습니다.
`Button`(`src/shared/ui/Button.tsx`)의 ghost variant는 hover 배경이
`hover:bg-app-surface-muted`에서 `hover:bg-app-surface-muted/60`으로
완화되었습니다. 세 변경 모두 설계 문서 3절의 계획과 정확히 일치합니다.

공용 컴포넌트 회귀 관점에서 `Badge` 사용처를 전수 확인했습니다(`grep`으로
9개 파일 30건). 대시보드·워치리스트·시그널·알림·의사결정 로그·포트폴리오
페이지 전반에서 텍스트 라벨 용도로만 쓰이고 있으며, 아이콘을 내부에 배치해
정렬을 맞추는 패턴은 발견되지 않았습니다. 워치리스트 테이블의 상태 배지는
`Badge`가 아니라 별도 컴포넌트인 `TableBadge`를 사용하므로 이번 변경과
무관합니다. `ResearchPage.tsx`·`DecisionLogPage.tsx`의 일부 호출부는
`className="text-xs"` 또는 `className="min-h-6 text-xs"`를 이미 덧대고
있었는데, 이는 새 베이스 규격과 값이 동일해 충돌 없이 중복 지정으로만
남습니다(이번 PR 이전부터 있던 코드로, 이 PR이 만든 문제는 아닙니다). 축소
방향과 반대되는 `text-sm`이나 `min-h-7` 등을 덧대는 호출부는 발견되지
않았습니다.

accent 저채도화의 대비 문제도 확인했습니다. `--color-app-accent: #38bdf8`은
`src/index.css`의 `@theme` 블록에 정의되어 있어 Tailwind v4가 `/15`·`/40` 같은
불투명도 modifier를 네이티브로 지원하며(별도 arbitrary value 없이도 CSS
`color-mix` 기반으로 생성), 실제로 `pnpm typecheck`·`pnpm lint`·`pnpm test`가
모두 통과해 클래스 자체는 정상 빌드됩니다. WCAG 대비도 계산했습니다.
`text-app-accent`(#38bdf8)를 `bg-app-accent/15`가 `app-surface`(#111827) 위에서
블렌딩된 배경(약 rgb(23,49,70))과 비교하면 대비비 약 6.3:1, `app-surface-muted`
(#1f2937) 위에서는 약 5.1:1로 계산되어 WCAG AA 일반 텍스트 기준(4.5:1)을
충분히 넘습니다. accent 배지는 리서치 페이지의 "신뢰도" 표시
(`ResearchPage.tsx:799`)에 쓰이는 정보성 라벨이며, CTA 버튼은 `Button`의
`primary` variant(이번 PR에서 미변경)가 담당하므로 저채도화로 인한 CTA 의미
약화 우려는 없다고 판단합니다.

status/decision/risk 계열 톤(`stockStatusClassNames`·`decisionTypeClassNames`·
`riskLevelClassNames`)은 diff에 포함되지 않아 `@theme` 토큰 기반 값 그대로
유지되며, `Badge`의 베이스 규격 축소만 공통 적용받습니다(설계 문서 3절 서술과
일치).

`Button` ghost variant는 저장소 전체에서 15건 사용되고 있으며, hover 배경
불투명도 완화(`/60`)는 시각적 미세 조정 수준이라 텍스트 대비나 클릭 영역에는
영향이 없습니다.

결정 기록 대상이 아닙니다. failure record도 불필요합니다. 설계 문서 3절에
남아 있던 `info`·`warning` 원시 Tailwind 색 토큰화 후속 과제(pr-34 리뷰 유래)는

계산으로 WCAG AA 기준을 충분히 만족함을 확인했고, 용도가 CTA가 아닌
정보성 라벨이라 의미 약화 우려도 낮다고 판단합니다. Tailwind v4의
`@theme` 커스텀 색 불투명도 modifier는 정상 동작이 typecheck·lint·test
통과로 간접 확인되었습니다. status/decision/risk 계열은 diff에 포함되지
않아 미변경이 확인됩니다. CI(`Verify React Template`)와 로컬 4종 검증
(format:check·typecheck·lint·test 490개) 모두 통과했습니다.
