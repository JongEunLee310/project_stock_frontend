# PR #277 로컬 리뷰 — 이벤트 상세 페이지 (#204)

## Review Summary

개별 시장 이벤트의 근거를 검증하는 이벤트 상세 화면(`/news/events/:eventId`)을 신설한 PR입니다. 단일 커밋(`이벤트 상세 뉴스 인사이트 화면 구현`)입니다. 토픽 상세가 토픽 단위 분석이라면 이 화면은 개별 이벤트 단위로 영향 종목·근거 문서·관련 토픽을 확인합니다.

라우트 `newsEventDetail: '/news/events/:eventId'`를 `navigation.ts`에 추가하고 `AppRouteId` union에서 제외해 사이드바 비노출 detail 라우트로 두었으며, `router.tsx`의 AppShell children에 배선했습니다. `src/features/news-insights/`에 이벤트 상세 dto·adapter(`adaptNewsEventDetail`)·query(`useNewsEventDetailQuery`, `enabled` 가드)를 추가하고 기존 presentation 맵(`importancePresentations`·`sentimentPresentations`·`eventTypeLabels`·`documentTypePresentations`·`evidenceRolePresentations`)을 재사용했습니다.

위젯 4종을 신설했습니다. `NewsEventHeader`는 이벤트 유형·제목·요약·중요도(점수·수준·설명)·감성(방향·점수)을 분리 표기하고, `NewsEventAffectedSymbols`는 방향·노출도·사유를 담아 클릭 시 `/research/:symbol`로 이동하며, `NewsEventEvidenceList`는 evidence_role 배지와 원문/AI 요약을 분리하고, `NewsEventRelatedTopics`는 `/news/topics/:topicId`로 링크합니다. 페이지 `NewsEventDetailPage`는 단일 리소스 detail이라 패널 격리 대신 페이지 레벨 loading·error(404 분기)·empty를 처리합니다.

이번 리뷰는 계약 일치, 중요도/감성 분리, 사실/분석 구분과 없는 데이터 미창작, 404 처리, 라우트·타입 추가를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. evidence per-doc summary 부재의 정직한 노출 — 계약 한계에 대한 적절한 처리.** `EventDetailEvidence` 계약에는 문서별 summary가 없어 '원문 보기'는 출처·발행 시각·문서 번호 메타데이터만, 'AI 요약 보기'는 "문서별 AI 요약 미제공, 이벤트 수준 요약은 상단 확인"으로 안내합니다. 없는 요약을 만들지 않는 원칙에 부합합니다. per-doc 요약 계약이 생기면 이 영역을 연결하면 됩니다.

**S2. 404 판별을 에러 코드 문자열 매칭에 의존 — 현재 방식 허용, 계약 안정성 인지.** 페이지가 `error.code.includes('NOT_FOUND')`로 404를 구분해 "이벤트를 찾을 수 없습니다" 메시지를 노출합니다. 백엔드 에러 코드 규약에 의존하므로, 코드 문자열이 바뀌면 일반 오류 문구로 폴백합니다(치명적이지 않음). 현재 envelope 규약과 일치하며 병합을 막지 않습니다.

## Questions

**Q1. 라우트 등록 순서.** `newsEventDetail`(`/news/events/:eventId`)을 `newsTopicDetail`(`/news/topics/:topicId`) 앞에 등록했습니다. 두 경로는 두 번째 세그먼트(`events` vs `topics`)가 달라 겹치지 않으므로 순서 무관하게 정확히 매칭됨을 확인했습니다.
