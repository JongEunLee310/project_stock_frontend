Adapter tests cover the updated contract and a null-asset scenario. Dashboard tests add a `useAlertCandidates` vi.mock plus data-render, loading, error, and empty assertions. CI 5-check all PASS.

## Suggestions

**S1 · Design document status header**

`docs/designs/68-dashboard-priority-queue-wiring.md` does not have an explicit status line, but the handoff notes a status update to "완료/Implemented" as optional. Following the convention established in prior PRs (e.g., PR #74 Q2), updating the header after merge is recommended. Non-blocking.

**S2 · `riskRank` constant scope**

`riskRank` is declared as a module-level constant (`Record<AlertCandidate['riskLevel'], number>`) while the sort that uses it lives inside the component. This is correct and type-safe, but it creates a mild cohesion gap — the type dependency on `AlertCandidate` is not visible at the sort site. A follow-up option is to inline the rank lookup as `{ 높음: 0, 중간: 1, 낮음: 2 }[first.riskLevel]` directly in the sort comparator, which co-locates the logic. This is a readability preference and does not affect correctness or type safety. Non-blocking.

## Questions

**Q1 · `priorityQueueQuery.error.message` type safety**

In the `isError` branch, `priorityQueueQuery.error.message` is accessed directly. TanStack Query types `error` as `Error | null` when the default error type is used, so `.message` is safe here. If the project ever narrows or widens the error type generically, this site would need adjustment. The signals section precedent in the same file uses the same pattern, so no action is needed now — worth noting for future error-type generalisation.
