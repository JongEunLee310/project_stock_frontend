## Review Summary

`git diff main...HEAD` 기준 `src/pages/ui/ResearchPage.tsx`,
`src/pages/ui/ResearchPage.test.tsx`, 설계 문서 3개 파일이 바뀝니다.
핵심 리스크(`RiskPanel`)와 데이터 커버리지(`CoverageAxisRow`)의 항목
카드를 헤더 없는 테이블형 행으로 재구성하는 변경으로, 설계 문서의 범위와
일치합니다.

`RiskPanel`은 `ul`을 `divide-y divide-app-border`로 바꾸고 각 `li`를
수준 색 불릿(`riskDotClassNames`) + 리스크명 + `InfoTooltip`(근거 있는
항목만) + 수준 배지 + truncate된 한 줄 설명으로 구성합니다. 카드 헤더의
리스크 수준 요약·`n/m` 확보 배지·grid 배치(#177)는 그대로 유지되어
범위를 벗어나지 않습니다.

`InfoTooltip` 재사용은 적절합니다. 컴포넌트가 `createPortal`로
`document.body`에 패널을 렌더링하고 `position: fixed`로 배치하므로,
3열 카드처럼 트리거가 좁은 컨테이너 안에 있어도 패널 자체는 컨테이너
폭의 제약을 받지 않습니다. `open()`에서 `PANEL_HALF_WIDTH`(160)와
`VIEWPORT_MARGIN`(8)으로 `left` 좌표를 `window.innerWidth` 기준으로
clamp하므로, `w-80`(320px) 고정 패널이 화면 좌우 경계를 벗어나는 문제도
이미 처리되어 있습니다. `className="shrink-0 [&_button]:text-app-text-muted
[&_button:hover]:text-app-text"`로 트리거 버튼 색만 `app-*` 토큰으로
보정하고 패널 내부는 `cockpit-*` 토큰을 그대로 두는 방식은, 설계
문서(Risks/Notes)가 명시한 "버튼 색만 보정, 패널 토큰 교체는 하지 않는다"
방침과 정확히 일치합니다.

`riskDotClassNames`는 `bg-status-level-high-text` 형태로 `-text`
접미사 토큰을 배경색으로 사용합니다. `src/index.css`의 `@theme` 블록에
`--color-status-level-high-text` 등이 정의되어 있어 Tailwind v4가
`bg-status-level-high-text` 유틸리티를 실제로 생성하므로 렌더링 자체는
문제없이 동작합니다(`pnpm build` 대상 CSS 생성 확인은 별도로 하지
않았으나, 동일 패턴의 `text-status-level-high-text`가 기존
`riskLevelClassNames`에서 이미 쓰이고 있어 토큰 존재는 확인됩니다).
다만 코드베이스의 기존 관례(`stockStatus.ts`)는 `-bg`는 배경,
`-text`는 전경색으로 짝을 맞춰 쓰고 있어, 불릿 배경에 `-text` 토큰을
쓰는 것은 이번 PR에서 처음 등장하는 조합입니다. `-bg` 값(예:
`#3b1d2f`, 어두운 톤)은 배지 배경용으로 설계된 색이라 작은 점(dot)
채우기에는 대비가 약하고, `-text` 값(예: `#fbcfe8`, 밝은 톤)을 쓴
선택은 시각적으로는 합리적입니다. 네이밍과 실제 용도가 어긋나는 점만
Suggestions에 기록합니다.

`truncate` + `title` 속성 조합은 설명(description) 텍스트에 쓰였고,
같은 파일의 뉴스·공시 목록(`isCompact` 모드, 1115행 부근)에서 이미
쓰이던 패턴과 동일합니다. 스크린리더가 `title` 속성을 항상 안정적으로
읽어주지는 않으므로 근거 없는 리스크 항목은 truncate된 설명의 전체
텍스트에 접근할 안정적인 수단이 없습니다만, 이는 새로 도입된 패턴이
아니라 기존 관례를 그대로 따른 것이라 이번 PR만의 회귀는 아닙니다.
리스크명(`h3`)에는 `title` 속성이 없어, 근거가 없고 이름 자체가 길어
truncate되는 항목은 설명과 달리 대체 텍스트 확인 수단이 전혀 없다는
점은 Suggestions에 별도로 기록합니다.

행 레이아웃은 `li`에 `flex min-w-0 items-center gap-3`, 내부 정보
영역에 `flex min-w-0 flex-1 flex-wrap items-center gap-x-2 gap-y-1`을
적용해 불릿·제목·툴팁 트리거는 `min-w-0` inline-flex로 묶고 배지와
설명은 `flex-wrap` 대상에 포함시켰습니다. 설명 `p`에는
`min-w-0 flex-1 truncate`가 있어 좁은 폭에서는 배지가 다음 줄로
밀려나고 설명이 남은 폭만큼 truncate되는 방식으로 겹침 없이 처리됩니다.
`CoverageAxisRow`도 `flex flex-wrap items-center gap-x-2 gap-y-1`로
축 라벨·배지·텍스트가 좁은 폭에서 자연스럽게 줄바꿈되며, truncate
대상이 없어 정보 유실 없이 동작합니다. 설계 문서의 "flex-wrap 허용으로
겹침 방지" 방침과 일치합니다.

테스트는 `it('shows evidence tooltips only for key risks with evidence')`
로 이름을 바꾸고, 카드 구조 시절의 `getByRole('heading', {name: '근거'})`
단언을 `InfoTooltip` 트리거 버튼(`getByRole('button', {name:
'{제목} 근거'})`) 노출 및 `fireEvent.focus` 후 툴팁 콘텐츠(`설명 +
근거 목록`) 텍스트 확인으로 바꿨습니다. 근거 없는 항목(`Supply`)은
동일한 이름 규칙의 버튼이 존재하지 않음을 `queryByRole`로 확인합니다.
행 구조 전환에 맞춰 실질적으로 바뀐 동작(트리거 유무·툴팁 콘텐츠)을
검증하고 있어 카드 구조 잔재 없이 정리되었습니다. `CoverageAxisRow`
관련 기존 테스트(1124~1166행)는 `getAllByText('수집됨'/'미수집')` 등
텍스트 기반 단언이라 카드→행 전환과 무관하게 그대로 유효합니다.

## Suggestions

- `riskDotClassNames`가 `-text` 접미사 토큰(`bg-status-level-high-text`
  등)을 배경색으로 사용합니다. 렌더링 결과는 의도한 대로 나오지만
  네이밍상 "텍스트 색"을 배경에 쓰는 조합이라 다른 작성자가 코드만 보고
  오해할 수 있습니다. `--color-status-level-high-dot`처럼 용도가 드러나는
  토큰을 새로 추가하거나, 최소한 주석으로 "밝은 톤이 필요해 -text 토큰을
  의도적으로 재사용함"을 남기는 편이 이후 유지보수에 도움이 될 것 같습니다.
- 리스크명(`h3`)이 truncate되는 경우, 근거가 없는 항목은 설명과 달리
  `title` 속성이 없어 전체 이름을 확인할 방법이 없습니다. 근거 없는
  항목에도 `h3`에 `title={risk.title}`을 추가하면 일관성이 생길 것
  같습니다. 다만 리스크명은 통상 짧은 문자열이라 실사용에서 truncate가
  발생할 가능성은 낮아 보여, blocking으로 올리지는 않습니다.
