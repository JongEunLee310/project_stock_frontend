# PR #33 Local Review — Signals 시그널 페이지 (task-011 / 이슈 9)

## Review Summary

`SignalsPage`를 플레이스홀더에서 실제 화면으로 구현. 상태별 요약 카드 4종, 필터 바, 시그널 카드
그리드(신뢰도 막대바·근거 bullet·판단 기록 버튼), 우측 우선순위·최근 변경 패널을 구성. 데이터는
`mockSignals` 파생이며 신규 도메인 타입은 추가하지 않았다. 설계 `docs/designs/9-signals-page.md`,
핸드오프 `.codex/tasks/task-011-signals-page.md`와 일치한다.

검토 항목:

- **확정 결정 준수**: 신뢰도=막대바+숫자(`ConfidenceBar`, `role="meter"`+`aria-valuenow`, CSS `width`
  채움 — 차트 라이브러리 미사용), 요약 카드=`mockSignals` 상태별 개수 `useMemo` 파생(신규 SignalSummary
  타입 없음), 레이아웃=카드 그리드 + 우측 레일(우선순위 `priority`↑·최근 변경 `updatedAt`↓). 모두 설계
  "결정" 절과 일치.
- **완료 조건 충족**: 4개 상태(매수 검토 가능·위험 증가·추가 리서치 필요·**관망 유지**) 모두 표시. 기존
  `mockSignals`에 빠져 있던 `관망 유지`(MSFT, technical)를 포함해 3→6건으로 보강(`satisfies Signal[]`
  유지, 신규 타입·필드 없음 — 파괴적 변경 없음). 각 카드에 신뢰도·근거·[판단 기록](→`/decision-log`)
  버튼 존재.
- **공통 컴포넌트 재사용**: `Card`/`Badge`/`Button`/`Input` 재사용. 상태 표시는 `Badge`(StockStatus
  매핑) — 인라인 색상 복제 없음. 네이티브 `<select>`만 신규(공통 Select 미존재, 합리적).
- **타임존 안전**: `timeFormatter`에 `timeZone: 'Asia/Seoul'` 고정(WatchlistPage 선례 반영). 갱신 시각
  표시가 환경 독립적. 테스트도 시간 문자열 단언을 피해 신뢰도(86%)·종목·상태로만 단언 → CI(UTC) 안전.
- **네비게이션 분리**: 카드 헤더·레일 종목은 `Link`(→`/research/:symbol`), [판단 기록]=`/decision-log`,
  [리서치 보기]=`/research/:symbol`로 `useNavigate`. 라우트 상수(`appRoutePaths`) 사용.
- **인터랙션**: 검색·상태·유형·정렬 4필터 + 필터 초기화. `useState`+`useMemo` 파생, 빈 결과 메시지
  처리. 우선순위/최근 변경 레일은 전체 `mockSignals` 기준 상위 4(필터 무관 — 개요성 패널로 합리적).
- **접근성**: 신뢰도 막대 `role="meter"`+`aria-value*`, 카드 `article`+`aria-label`, bullet `aria-hidden`,
  레일 `aria-label`. 양호.

로컬 검증: `format:check`·`lint`·`typecheck`·`TZ=UTC pnpm test`(35/35, SignalsPage 4건 신규)·`build`
모두 통과.

## Suggestions

- **요약 카드 데이터 소스 명시성**: `SummaryCards`는 `signals={mockSignals}`(전체)로 호출되어 필터와
  무관한 전체 개수를 보여준다(개요 의도로 적절). 다만 필터 적용 시 "표시 N개"(그리드 헤더)와 요약 개수가
  달라 보일 수 있어, 추후 요약 카드에 "전체 기준" 라벨 또는 클릭 시 해당 상태 필터링 연동을 고려할 만하다
  (본 PR 차단 아님).
- **필터 Select 공통화 시점**: 상태/유형/정렬 3개 네이티브 `<select>`가 `selectClassName` 인라인으로
  반복된다. Watchlist에도 동일 패턴이 있어 **재사용 2곳 충족** → `shared/ui` 공통 `Select` 승격을 다음
  공통 컴포넌트 라운드 후보로 권장(이미 PR #32 리뷰에서도 제기).
- **신뢰도 의미색**: 막대가 일괄 `app-accent`다. 신뢰도 구간별(고/중/저) 의미색이 생기면 가독성이 오를
  수 있다(토큰 도입 시 치환).
- **레일 항목 키**: `key={\`${mode}-${signal.id}\`}` 구성은 안전하나, 동일 시그널이 두 레일에 중복 노출될
  수 있다(우선순위·최근 변경 모두 상위에 들면). 정보 중복일 뿐 버그는 아니며 mock 특성상 허용.
