# PR #100 — Topbar·Sidebar 실데이터 연동 (feat/topbar-sidebar-realdata-wiring)

리뷰어: Claude Code (Opus, 오케스트레이터). 구현: Codex. 브랜치: feat/topbar-sidebar-realdata-wiring → main. 관련: FE #88·#91, 설계 81, 핸드오프 task-038.

## Review Summary

설계 81대로 두 위젯의 하드코딩·무동작 요소를 기존 FE 쿼리·인증 컨텍스트에 실데이터로
연동했습니다. 신규 BE 계약은 없습니다.

`Sidebar`는 기존 훅 `useUnreadAlertSummary()`를 호출해 `alerts` 배지의 리터럴 `6`을
`unreadCount`로 대체하고, 값이 0이거나 미정의(로딩·오류)면 배지를 비노출합니다. 네비게이션
전체는 정상 렌더를 유지합니다.

`Topbar`는 프로필 이니셜을 `useAuth().user`의 email local-part 첫 글자(대문자)로 도출하며,
`user`가 null이면 기존 폴백 `IC`를 유지합니다. 새로고침 버튼은 `useQueryClient().invalidateQueries()`
전체 무효화와 동기화 시각 갱신을 수행하고, 알림 버튼은 `appRoutePaths.alerts`로 이동합니다
(카운트 미표시로 사이드바 배지와 중복을 피함). 고정 텍스트 `동기화 14:32`는 로컬 상태
`lastSyncedAt` 기반 KST 시:분 표시로 대체됐습니다. 시:분 전용 포맷터 `formatKstTime`가
기존 `datetime.ts` 패턴대로 추가됐습니다.

도움말 버튼·프로필 드롭다운은 별도 UX 정의가 필요해 이번 범위에서 제외했고 현행을 유지합니다.

## Blocking

None.

## Suggestions

**S1 · 새로고침 전체 무효화 범위(비차단)**

`invalidateQueries()`를 인자 없이 호출해 캐시된 모든 쿼리를 무효화합니다. 현재 화면 수의
전역 새로고침 의도에는 부합하나, 쿼리가 늘어나면 광범위 재조회 비용이 커질 수 있습니다.
현 단계에서는 단순성이 타당하며, 필요 시 후속에서 스코프 지정 여지가 있습니다.

## Scope Control

- 소스 변경은 `Sidebar.tsx`·`Topbar.tsx`와 시:분 포맷터(`datetime.ts`)로 한정됐습니다.
- 페이지 테스트 5종(`DashboardPage`·`DecisionLogPage`·`ResearchPage`·`SignalsPage`·`WatchlistPage`)의
  `QueryClientProvider` 래핑 보강은, `Sidebar`가 새 훅 `useUnreadAlertSummary`를 호출하게 되면서
  공용 라우터(`appRouteObjects`)를 렌더하는 이들 테스트에 QueryClient가 필요해진 데 따른
  모듈 계약 정합용 스코프 내 조치입니다. `DashboardPage.test.tsx`는 기존 `@/features/alerts/queries`
  목에 `useUnreadAlertSummary` 항목을 추가해 목 계약을 맞췄습니다.
- `useUnreadAlertSummary`·`useAuth`·알림 슬라이스 동작은 변경되지 않았습니다.
