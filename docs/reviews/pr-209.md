# PR #209 — 리서치 상세 후속 정리: counter_view fallback 제거·커버리지 라벨 truncate 고정 (#197·#207)

리뷰어: Claude Code (VFF, Sonnet). 구현: Codex. 브랜치: chore/197-207-research-followups → main. 관련: 이슈 #197·#207, 핸드오프 `.codex/tasks/task-076-research-followups.md`, BE #298/PR #299(counter_points 구조화 필드).

## Review Summary

이슈 #197과 #207을 함께 처리한 정리성 PR입니다. #197은 PR #196에서 `counter_points` 구조화
필드로 전환하면서 호환용으로 남겨 두었던 구계약 `counter_view` 문자열 불릿 fallback 경로를
제거합니다. `ResearchSummaryDto.counter_view`(dto.ts), `adaptResearchDetail`의 `counterView`
매핑(adapters.ts), `ResearchView.counterView` 필드(adapters.ts), `CounterViewPanel`의
`fallbackItems` prop과 그 렌더 분기(ResearchPage.tsx)가 모두 제거되었고, `counter_points`가
빈 배열이면 기존 `EmptyState`("반대 관점 데이터가 없습니다.")로 곧바로 떨어지는 경로만
남았습니다.

#207(커버리지 축 라벨 overflow 방어)은 이번 PR에서 새로 구현한 것이 아니라, 같은 날 별도
커밋(`eebfac1`, PR #191 리뷰 S1 반영으로 main에 이미 병합됨)으로 이미 처리되어 있었습니다.
PR 본문도 이 사실을 정확히 밝히고 있고, 이번 PR은 그 구현이 회귀하지 않도록 5개 알려진 축
외의 긴 라벨(`대체 데이터 기반의 매우 긴 커버리지 축 라벨`)로 `truncate`·`title` 렌더를
검증하는 회귀 테스트만 추가했습니다.

네이밍 문제이므로 차단 사유는 아닙니다. 다음 리서치 카드 작업 때 함께 정리하는 편이
합리적입니다.
