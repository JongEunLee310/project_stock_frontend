## Review Summary

리서치 상세 페이지의 가격 차트를 일반 라인 차트 스타일에서 증권 서비스형 스타일
(영역 그라데이션·우측 가격축·현재가 pill·통합 거래량)로 고도화하는 변경입니다.
`git diff main...HEAD` 기준 최종 diff는 설계 문서 1개와 소스 4개 파일(`LineChart.tsx`,
`LineChart.test.tsx`, `ResearchPage.tsx`, `ResearchPage.test.tsx`)입니다. 중간 커밋
`5b9abe4`에 `prettier --write .` 실행으로 문서 125개가 의도치 않게 재포맷되어
쓸려 들어갔으나, 다음 커밋 `a90fb60`에서 원복되었고 main 대비 최종 diff에는
영향이 없어 이 리뷰는 문제 삼지 않았습니다.

`LineChart`는 내부 루트를 `RechartsLineChart`에서 `ComposedChart`로 전환하고
`areaSeries`·`yAxisOrientation`·`hideXAxis`·`lastValueLabel` 4개의 optional prop을
추가했습니다. 이 컴포넌트를 소비하는 곳은 `src/pages/ui/ResearchPage.tsx`가
유일합니다(`grep`으로 확인, 대시보드·워치리스트의 스파크라인은 별도 컴포넌트인
`src/shared/ui/charts/Sparkline.tsx`가 자체 `RechartsLineChart`를 직접 사용하므로
이번 변경과 무관합니다). 신규 prop 미지정 시 렌더 경로를 diff로 추적하면
`resolvedSeries.filter((item) => item.dataKey !== areaSeries?.dataKey)`가
`areaSeries`가 `undefined`일 때 항상 `true`이므로 `.map` 결과가 변경 전과
동일하고, `yAxisOrientation` 기본값 `'left'`·`hideXAxis` 기본값 `false`도
기존 렌더를 그대로 보존합니다. `LineChart.test.tsx`에 추가된
`renders every configured series` 인접 테스트도 신규 prop 미지정 케이스에서
`.recharts-area`·`linearGradient`·`[data-last-value-label]`가 모두 부재함을
단언해 이 additive 보장을 커버합니다.

`hideXAxis`는 `<XAxis dataKey={...} hide={hideXAxis} ... />`처럼 동일한 `XAxis`
엘리먼트에 `hide` prop만 전달하는 방식이라 스케일·도메인 계산에는 영향이
없습니다. `LineChart.test.tsx`의 `hides the x axis when hideXAxis is set` 테스트가
`hideXAxis`일 때 `.recharts-xAxis` 자체가 DOM에서 사라짐을 확인하는데(recharts
3.8.1의 `hide` prop은 시각적 은닉이 아니라 축 그룹 자체를 렌더링에서 제외하는
방식), 이는 거래량 `BarChart`의 `<YAxis hide />`도 동일하게 레이아웃 폭을
점유하지 않는다는 근거가 되어 `margin.right: 60`(가격 차트 `right: 12` +
우측 `YAxis` 폭 `48`) 계산의 타당성을 뒷받침합니다. `ReferenceDot` 마커 위치는
같은 `XAxis`/`YAxis` 스케일을 공유하므로 `hideXAxis` 전환으로 인한 영향은
없습니다.

`findLastValidPoint`는 배열을 뒤에서부터 순회하며 `x`(문자열 또는 유한수)와
`y`(유한수) 모두 유효한 마지막 포인트를 찾고, 전부 유효하지 않으면 `null`을
반환합니다. 호출부는 `lastValueLabel && lastValidPoint` 가드로 `null`일 때
`ReferenceDot` 자체를 렌더하지 않으므로 크래시 위험은 없습니다.

한 가지 확인이 필요한 지점은 현재가 pill의 SVG 좌표입니다.
`renderLastValueShape`의 `rect`는 `x={cx - labelWidth - 8}`로 항상 점(`cx`)의
왼쪽에 배치됩니다(`labelWidth`는 최소 48px). `ReferenceDot`의 `ifOverflow="discard"`는
좌표값이 도메인 범위를 벗어날 때만 동작하므로, 마지막 유효 포인트가 도메인
안에 있지만 `cx` 자체가 왼쪽 경계에 가까운 경우(예: 최신 종가만 결측이고
그 이전 앙상블이 대부분 결측인 시리즈, 또는 매우 짧은 시리즈)에는 pill이
차트 왼쪽 경계를 넘어 잘려 보일 수 있습니다. 실사용 데이터(리서치 페이지의
`priceSeries.points`)는 통상 최신 데이터가 배열 끝에 위치하고 결측은 드물어
발생 빈도는 낮을 것으로 판단하지만, 코드 자체로는 이 경계 케이스를 방어하지
않습니다.

범례의 등락 표시는 `latestClose - previousClose`(마지막 두 유효 종가의 차이)로
계산되며, 이는 선택된 기간(1D/1M/3M/6M/1Y)의 수익률이 아니라 시리즈 내 마지막
두 데이터 포인트 간 차이입니다. 일봉 시리즈에서는 직전 거래일 대비 등락으로
해석되어 증권 서비스 UI 관행과 부합하지만, 기간 선택 UI가 함께 있는 화면에서
"기간 수익률"로 오인될 여지는 있습니다. 다만 이는 이번 PR의 설계 범위(범례에
심볼·마지막 종가·등락 표시)와 일치하는 의도된 동작으로 판단합니다.

## Suggestions

**S1. 현재가 pill의 좌측 경계 클리핑 방어**

`renderLastValueShape`에서 계산한 `rect`의 `x`가 음수가 될 수 있는 경우
(마지막 유효 포인트가 차트 왼쪽 경계에 가까울 때) pill이 잘려 보일 수
있습니다. `Math.max(cx - labelWidth - 8, minX)` 형태로 하한을 두거나, 점이
왼쪽 경계에 가까울 때 pill을 점 오른쪽에 그리도록 분기하는 방어 로직을
추가하면 더 안전합니다. 현재 리서치 페이지의 실데이터 패턴(최신 데이터가
배열 끝, 결측 드묾)에서는 발생 가능성이 낮아 Blocking으로 보지는 않습니다.

**S2. 거래량 margin 정렬 계산에 대한 주석의 전제 조건 명시**

`ResearchPage.tsx`에 남긴 `// right 60 = 가격 차트의 right margin 12 + 우측
YAxis 폭 48 (플롯 영역 정렬)` 주석은 계산 자체는 정확하지만, 이 정렬이
성립하는 전제(`BarChart`의 `<YAxis hide />`가 레이아웃 폭을 점유하지 않는다는
recharts 내부 동작)까지는 설명하지 않습니다. 향후 recharts 메이저 업그레이드나
`showAxes` 동작 변경 시 이 전제가 깨질 수 있으므로, 전제 조건을 한 줄
덧붙이면 유지보수에 도움이 될 것입니다.
