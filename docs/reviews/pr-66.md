## 배경

main CI run #139(PR #64 머지 커밋)에서 `ResearchPage.test.tsx > toggles checklist items locally` 간헐 실패. 동일 코드로 #138/#140 통과·#137/#139 실패한 타이밍 의존 증상. 로컬 재현 8회 중 4회 실패.

## 원인 (race condition)

- `checklist` state가 `[]`로 시작 → seeding `useEffect`가 쿼리 로드 후 `research.buyChecklist`로 채움.
- `displayedChecklist`는 state 비면 서버 데이터 폴백.
- 클릭 토글 직후 **늦게 실행된 seeding effect가 체크리스트를 미체크 서버 데이터로 덮어씀** → `toBeChecked()` 실패.

## 정확성

- 체크리스트를 `{ assetId, items }` 단일 state로 재구성, effect의 checklist seeding 제거(effect는 favorite 리셋만 유지). ✔
- 토글·표시 모두 현재 `research.assetId` 기준 → effect 타이밍 비의존, 클럽버 제거. ✔
- 자산 변경 시 assetId 불일치로 로컬 편집 자동 폐기 → 서버 데이터 복귀(기존 reset 동작 보존). ✔
- `toggleChecklistItem`은 `research` null 가드 추가, 호출처는 research 존재 시에만 렌더되어 안전. ✔
- 남은 `checklist` 식별자(280~292)는 `BuyChecklistCard` prop으로, 페이지 state 아님 → 무관. ✔
