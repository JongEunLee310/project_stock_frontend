# PR #281 로컬 리뷰 — 이벤트 캘린더·에이전트 파이프라인 패널 (#269)

## Review Summary

개요 페이지의 마지막 placeholder 두 자리(이벤트 타임라인·에이전트 파이프라인)를 `/calendar`·`/agent-runs` 실데이터로 교체한 PR입니다. 단일 커밋(`feat: 캘린더와 에이전트 파이프라인 패널 추가`)이며, 이 PR로 개요 페이지가 전량 라이브 패널로 완성됩니다.

`src/features/news-insights/`에 calendar·agent-runs dto·adapter(`adaptNewsCalendar`·`adaptNewsAgentRuns`)·query(`useNewsCalendarQuery({ market, window })`·`useNewsAgentRunsQuery()`)를 추가하고 MarketEventKind·AgentStage·AgentRunStatus presentation 맵을 확장했습니다. 위젯 2종을 신설했습니다.

**Part A — 이벤트 타임라인(#269, 스펙 §3.7).** `MarketEventTimeline`은 `/calendar`(market="KR"·window="30d")로 향후 검증 이벤트를 시간순으로 표시합니다. `scheduled_at >= now`로 미래 이벤트만 필터해 정렬하고, event_kind 배지·중요도·종목과 함께 `daysUntil`로 D-N 카운트다운을 파생 표기하며, `related_topic_ids`를 `/news/topics/:topicId` 링크로 연결합니다.

**Part B — 에이전트 파이프라인(#269, 스펙 §3.8).** `AgentPipelinePanel`은 `/agent-runs`로 7단계(수집→정규화→이벤트추출→토픽·감성→영향→연결) 각각의 status·지연 배지와 집계 수치(처리 문서·추출 이벤트·활성 토픽)·마지막 처리 시각·분석 버전을 표시합니다. **검증 가능한 처리 단계·집계 수치만** 노출하고 비공개 추론 과정은 담지 않습니다.

개요 페이지는 두 placeholder를 위젯으로 교체하면서 `plannedPanels` 배열·"단계별 확장 패널" 섹션·`PlannedPanelCard` import를 모두 제거했습니다. 두 패널은 독립 query로 부분 실패를 격리합니다.

이번 리뷰는 D-N 파생 표기와 토픽 연결, 파이프라인의 검증가능 수치 한정(비공개 추론 미노출), placeholder 섹션 정리에 따른 개요 회귀, 부분 실패 격리를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 토픽 링크를 문자열 경로로 직접 구성 — 동작 무해, 컨벤션 수렴 여지.** `MarketEventTimeline`이 토픽 링크를 `` `/news/topics/${encodeURIComponent(topicId)}` ``로 직접 만듭니다. 다른 위젯은 `appRoutePaths.newsTopicDetail` + `generatePath`를 쓰기도 하므로, 경로가 바뀌면 이 한 곳이 누락될 수 있습니다. 현재 경로와 일치하고 `encodeURIComponent`로 안전하므로 병합을 막지 않으며, 이후 링크 추가 시 `generatePath`로 수렴하면 됩니다.

**S2. 캘린더 market·window 고정 — 3차 범위에서 허용.** 개요 타임라인은 `market="KR"`·`window="30d"`를 하드코딩합니다. seed·계약이 KR 기준이고 기간·시장 선택 UI는 범위 밖(후속)이라 타당합니다.

## Questions

**Q1. D-N 파생의 정확성.** D-N은 `daysUntil`이 `scheduled_at`과 현재 시각의 차이를 `Math.ceil`로 계산합니다. 파싱 불가·과거 이벤트는 미래 필터(`scheduled_at >= now`)로 목록에서 제외되므로 음수 D-N이 표시되지 않음을 확인했습니다. 이는 BE 수치 창작이 아니라 예정 시각으로부터의 표시용 파생입니다.

## Final Recommendation
