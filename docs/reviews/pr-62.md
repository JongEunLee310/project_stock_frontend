## API 경로 prefix — 정합성 검사 결과

설계 §2 규약: `apiGet`/`apiPost` 호출 경로는 RELATIVE(`/signals`, `/auth/me`). `VITE_API_BASE_URL`이
이미 `/api/v1`을 포함하므로 호출부에서 `/api/v1`을 재추가하면 더블-prefix 404가 된다.

| 기능 | 경로 예시 | 결과 |
|---|---|---|
| Signals | `/signals`, `/signals/${id}`, `/stocks/${symbol}/prices?range=1mo&interval=1d` | **PASS** |
| Research | `/assets?symbol=`, `/assets/${id}/detail`, `/assets/${id}/research-summary`, `/assets/${id}/buy-checklist`, `/reports?asset_id=`, `/theses/latest` | **PASS** |
| Alerts | `/alerts`, `/alert-candidates`, `/alerts/${id}/read`, `/alerts/${id}/dismiss`, `/alert-candidates/${id}/read`, `/alert-candidates/${id}/confirm` | **PASS** |
| Settings | `/auth/me` | **PASS** |
| DecisionLog | `/decision-logs` (GET·POST) | **PASS** |

전 기능 PASS. 이전 Track A(PR #58)에서 발생한 `/api/v1` 더블-prefix 패턴은 이번에 재발하지
않았다.

## 도메인 갭 처리

**G9 Signal 모델 교체**: `kind/confidence/trendSeries/previousStatus` 완전 폐기, BE 계약
필드(`signal_type/score/risk_level/reason/evidence/expires_at`)로 교체. `score`는
`parseDecimal` + `?? 0` 처리. `symbol` 해소는 `dto.symbol ?? dto.asset?.symbol ?? 'UNKNOWN'`
순서로 fallback 확보.

**G4 sparkline BE 미완**: `useSignalSparkline` `enabled: false`·`initialData: []`, Research도
동일하게 빈 배열 할당. 페이지에서 빈 배열이면 "가격 시계열 대기" 플레이스홀더 렌더링. 설계 §3.1
지시 이행.

**G6 symbol→assetId 해소**: `fetchAssetIdBySymbol`이 `GET /assets?symbol=` 결과가 없으면
`SymbolNotFoundError`를 throw하고, `useResearchView`가 이를 상위로 전파해 `ErrorState`로
처리한다. 빈 배열 경계 확인됨.

**G8 Alerts 인박스 재정의**: `AlertRule` 빌더 UI 완전 폐기, 인박스 탭(`alerts` / `alert-candidates`)으로
교체. mutation 4개(read/dismiss/readCandidate/confirm) 각각 올바른 쿼리 키 무효화. 설계 §3.3
이행.

**G10 DecisionLog BE 미완**: `useDecisionLogs` `enabled: false`·`initialData: []`, `saveDecision`
핸들러 내부에서 `createDecisionLog.mutate`를 호출하지 않고 `void createDecisionLog.mutate`로
참조만 평가하여 로컬 임시 상태에만 저장. `enabled` 조건 제거 시 서버 연동으로 전환되는 구조.

**G11 Settings**: `/auth/me` 한 엔드포인트만 연동, 알림 설정 UI는 섹션 제거. 계획 외 엔드포인트
침범 없음.

## 계약 준수

- snake_case DTO는 어댑터 경계에서 camelCase 도메인 타입으로 전환되며 컴포넌트에 노출되지 않음.
- `parseDecimal` 사용: `score`, `market_cap`, `per`, `peg`, `fifty_two_week_low/high`,
  `target_price/upside_percent`, `stance_confidence` 전수 적용.
- `toLabel`·`riskLevelLabels`·`alertStatusLabels` 재사용.
- `formatKstDateTime` 날짜 변환 전수 적용, 네이티브 `alert/confirm` 호출 없음.
- `decisionTypeWireByLabel: Record<DecisionType, string>` 선언으로 컴파일 타임에
  `DecisionType` 전체 매핑 완전성 보장.

## 관찰 (non-blocking)

1. **DecisionLogPage `void createDecisionLog.mutate`**: 현재 G10 미완 전략상 의도적 주석
   처리이나, `void`로 메서드 참조를 평가하는 방식은 `// eslint-disable` 없이 일부 린트 규칙에서
   경고될 수 있음. 향후 `enabled` 조건을 실 호출로 전환할 때 해당 줄을 실제 mutation 호출로
   교체하면 충분하므로 지금은 무해.
2. **Research `useResearchView` 단일 queryFn 내 직렬 조합**: `fetchAssetIdBySymbol`이 완료된 후
   4개 `Promise.all`을 실행하는 구조로, asset lookup과 후속 병렬 요청 사이 워터폴이 불가피하다.
   설계 §3.2 선택 그대로이며 스코프 밖 최적화. 향후 BE가 단일 엔드포인트로 합쳐지면 해소됨.

## 결론

5화면 모두 API 계약 규약을 준수하며 연동되었다. 더블-prefix, 더미 값 노출, 네이티브 다이얼로그
호출 등의 전형적 결함은 발견되지 않았다. G4·G10 미완 갭은 설계 지침대로 `enabled: false` +
fallback 구조로 처리되어 BE 완성 시 한 줄 변경으로 연동 전환이 가능하다. Blocking 없음.
