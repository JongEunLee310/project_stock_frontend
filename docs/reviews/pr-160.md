# PR #160 로컬 리뷰 — feat: 밸류에이션·실적 탭 연동

리뷰어: Claude Code — VFF(Sonnet) 위임 교차 리뷰. 구현에 관여하지 않음.

구현자: Codex(gpt-5.6-sol), 커밋 `805d393`

## Review Summary

이슈 #149의 구현입니다. 리서치 상세 화면 `PriceChartCard`에서 placeholder로 존재하던
disabled 탭 두 개("밸류에이션", "실적")를 BE #270(PR #277)의 두 신규 엔드포인트에
연결합니다. 변경은 7개 파일, +946줄입니다.

구조적으로는 PR #157~#159가 확립한 카드 독립 쿼리 패턴을 그대로 따릅니다.
`useValuationMetrics(assetId, enabled)`와 `useEarningsSummary(assetId, enabled)` 두
훅이 신설되며, 각각 `enabled: assetId != null && enabled` 조건으로 해당 탭이 활성일
때만 API를 호출합니다. `PriceChartCard` 내부에서 `activeTab` 상태를 관리하며, 패널
단위 로딩 스켈레톤과 오류 `ErrorState`(재시도)를 갖추어 밸류에이션·실적 API 실패가
페이지 전체나 가격 패널에 전파되지 않습니다.

어댑터 레이어에서는 7개 metric enum을 한국어 라벨로 매핑하는 `valuationMetricLabels`,
5개 profile enum을 한국어 라벨로 매핑하는 `valuationProfileLabels` 상수를 신설하고
알 수 없는 값은 원문 폴백으로 처리합니다. decimal 문자열은 기존 `parseDecimal`로
변환되며 null은 그대로 유지됩니다. `isHighlighted`는 `highlighted_metrics`를 `Set`으로
변환 후 포함 여부로 파생합니다.

PR #154 S1에서 예고한 ARIA 요건(세 탭 모두 `id`와 `aria-controls`, 각 tabpanel은
`aria-labelledby` 참조)을 이 PR에서 이행합니다. 탭 id와 panel id를 `chartTabIds`
상수로 중앙 관리하고, 단일 tabpanel 컨테이너가 `activeTab`에 따라 `id`와
`aria-labelledby`를 동적으로 교체하는 방식입니다.

## Blocking

없습니다.

## Suggestions

**S1. 단일 tabpanel 컨테이너가 ARIA controls 연결을 끊을 수 있습니다**

현재 구현에서 tabpanel 역할의 `div`는 하나이고, `id`와 `aria-labelledby`가
`activeTab`에 따라 동적으로 교체됩니다. 즉 비활성 탭이 가리키는 `aria-controls`
대상(`research-valuation-panel`, `research-earnings-panel`)이 가격 탭 활성 시 DOM에
존재하지 않습니다. ARIA Authoring Practices Guide의 탭 패턴은 숨겨진 패널도 DOM에
유지하고(`hidden` 속성 토글)하여 `aria-controls` 연결이 항상 유효하도록 권고합니다.
보조 기술이 `aria-controls`로 패널 존재 여부를 탐색할 때 빈 참조가 발생할 수
있습니다. 다음 탭 관련 PR에서 패널을 `hidden` 속성으로 토글하는 방식으로 전환하는
것을 검토하시기 바랍니다. 현재 범위에서 기능상 문제는 없으며 이번 머지를 막지는
않습니다. 심각도: 비차단·후속 개선 권장.

**S2. adapters.test.ts 픽스처가 분기 2개만 포함합니다**

`earningsSummary` 픽스처(`adapters.test.ts` diff 110~142행)가 2개 분기만 담아 BE
계약에서 명시한 "최근 4분기 오름차순" 요건과 다소 거리가 있습니다. 어댑터 로직
자체는 분기 수에 무관하게 `map`으로 처리되어 실제 결함은 아니지만, 4분기 픽스처를
갖추면 오름차순 유지·4분기 슬라이싱 여부를 직관적으로 검증할 수 있습니다. 현재
`ResearchPage.test.tsx`의 페이지 픽스처는 4분기를 담아 보완하고 있으므로 현재로서는
테스트 커버에 공백이 없습니다. 심각도: 비차단·향후 보완 대상.

**S3. 밸류에이션 탭 패널에서 `formatHistoricalPosition`이 `value`를 null 체크 기준으로 사용합니다**

`formatHistoricalPosition(value, percentile)`은 `value === null || percentile ===
null`이면 "-"를 반환합니다(`ResearchPage.tsx` diff +991~+996행). 이는 설계 문서의
"value null이면 값·중앙값·위치 모두 '-'" 요건에 부합합니다. 다만 `percentile`은
null이고 `value`는 존재하는 경우(BE 계약상 발생하지 않는다고 가정되더라도)에
대해 단언이 없어, 향후 BE 응답 변경 시 조용히 통과될 수 있습니다. 현재 계약
범위에서는 문제가 없습니다. 심각도: 비차단·정보 제공.

## Questions

**Q1. `useValuationMetrics`·`useEarningsSummary` 쿼리에서 `enabled`가 false일 때
`queryFn` 내부 방어 코드의 dead code 여부를 구현자가 확인해 주시면 좋겠습니다**

두 훅 모두 `enabled: assetId != null && enabled` 조건 덕분에 `queryFn`이 실행되는
시점에는 `assetId`가 항상 non-null입니다. 그러나 `queryFn` 내부에
`if (assetId == null) return { ... }` 방어 코드가 있습니다(`queries.ts` diff
+601~+603, +621~+623행). 이는 타입 narrowing을 위한 의도적 코드로 보이며
런타임에는 도달하지 않습니다. 의도를 확인해 주시면 기록이 깔끔해집니다.

`lint`·`test`(58개 파일, 468개) 통과. GitHub Actions CI(Verify React
Template)도 통과했습니다.

신규 테스트는 다음 항목을 커버합니다. adapter 레이어에서는 metric·profile 라벨
매핑과 알 수 없는 값 폴백, `isHighlighted` 파생, null 필드 처리(DEFICIT PER·PEG null),
decimal 문자열 파싱과 분기 오름차순 유지를 검증합니다. query 레이어에서는 두 훅
각각에 대해 enabled false 시 미조회, enabled true 전환 후 조회와 캐시 키 등록,
`assetId undefined` 시 미조회를 검증합니다. 페이지 레이어에서는 탭 전환 시
`aria-selected`·`aria-controls`·`aria-labelledby` 연결, 밸류에이션 탭의 "하위/상위
nn%" 백분위 표기·null "-" 처리·강조 지표 배지, 실적 탭의 분기 오름차순 표시·상회
(+8.0% emerald)·하회(-4.0% red) 색상·guidance·segments 렌더, 패널 오류 격리(밸류에이션
실패 시 가격 탭·aside 불변)·재시도 호출, 로딩 중 스켈레톤 격리를 검증합니다.

## Documentation Impact

설계 문서 `docs/designs/149-valuation-earnings-tabs.md`와 구현이 전반적으로 일치합니다.
DTO 필드명, 어댑터 인터페이스 시그니처, 쿼리 키, enabled 게이트 조건, 라벨 매핑 상수,
백분위 표기 규칙("50 초과면 상위 (100-n)%"), null 처리, 탭 활성화 및 ARIA 연결 방식
모두 설계 명세를 따릅니다.

ADR은 불필요합니다. 기존 카드 독립 쿼리 패턴의 확장이며 새로운 아키텍처 결정이
포함되지 않습니다. failure record도 불필요합니다.

## Final Recommendation

Blocking이 없습니다. 머지 가능 판단입니다.

설계 문서 명세의 핵심 항목을 모두 충족합니다. enabled 게이트가 탭 활성 전 불필요한
요청을 차단하고, 패널 오류 격리가 페이지 나머지에 영향을 주지 않으며, PR #154 S1에서
예고한 ARIA 연결 요건(id·aria-controls·aria-labelledby·aria-selected)이 이 PR에서
이행되었습니다. 픽스처는 enum을 영문으로 유지하여 PR #159 B1 선례를 준수합니다.
가격 탭 내부(기간칩·차트)와 다른 페이지는 변경되지 않았습니다.

`App.test.tsx`·`WatchlistPage.test.tsx`의 변경은 두 신규 훅 mock 추가로, 새 훅이
해당 페이지 렌더에 영향을 주지 않음을 확인하는 정당한 범위 내 수정입니다.

S1(단일 tabpanel ARIA controls 공백)은 후속 탭 관련 PR에서 개선을 권장합니다.
S2·S3·Q1은 비차단 후속 검토 대상입니다.

최종 머지 권한은 개발자에게 있습니다.
