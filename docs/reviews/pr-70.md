# 로컬 리뷰: PR #70 — 이슈 #67 Signal DTO nullability·evidence 타입 정렬

## 배경

이슈 #67 통합 점검 후속. BE `SignalResponse`(`risk_level`/`expires_at`/`evidence` 모두 nullable, `evidence`는 object) 대비 FE `SignalDto`가 non-null·string 가정 → smoke test 전 런타임 크래시·오표기 위험. 코드로 모두 검증된 4건.

## 정확성

- **evidence object 크래시 차단** — 기존 `dto.evidence ?? null`이 object를 `SignalsPage.tsx:196 {signal.evidence}`로 직접 렌더 → React "Objects are not valid as a React child" 크래시 경로. `formatEvidence`로 object→2-space JSON, string→그대로, falsy→null 처리. 도메인 모델 `Signal.evidence: string | null` 안정 유지. ✔
- **만료일 null** — `formatExpiresAt`가 falsy면 `formatKstDateTime` 우회하고 "만료 없음" 반환. 기존 `new Date(null)`=1970 오표기 해소. ✔
- **risk_level null** — `formatRiskLevel`가 null→"미지정"(기존엔 `toLabel`이 null 반환해 타입 거짓말). ✔
- **enum fixture** — `EARNINGS_REVISION`(BE 부재) → `BUY_CANDIDATE`(실 `SignalType`). contract test가 실계약 샘플 역할 복원. ✔
- DTO nullability 3건이 BE 계약과 일치. 도메인 모델 외부 타입·`/signals/{id}` 동작 무변경. 범위 준수(라벨 맵·차트·prefix·BE 레포 미포함). ✔
