## Review Summary

이슈 #166을 해결하는 변경으로, `src/pages/ui/ResearchPage.tsx` 레이아웃
재배치와 `docs/designs/166-research-detail-layout-rebalance.md` 신설
설계 문서만 포함합니다(총 2개 파일, +72/-4). PR #165에서 차트 카드가 aside
높이만큼 늘어나는 stretch 문제를 고친 뒤에도, 우측 aside에 카드 4장(AI
브리핑·반대 관점·핵심 리스크·데이터 커버리지)이 쌓여 있어 xl 브레이크포인트
아래 빈 공간이 남는 문제를 다룹니다.

diff와 설계 문서 3절을 대조한 결과 완전히 일치합니다. aside에서
`CounterViewPanel`·`ResearchCoveragePanel`을 제거하고 `RiskPanel`만
`AI 브리핑` 카드와 함께 남겼으며, 차트 grid(`xl:grid-cols-[minmax(0,2fr)_minmax(18rem,1fr)]
xl:items-start`) 아래에 신설한 `grid gap-6 md:grid-cols-2` 행으로 두 컴포넌트를
옮겼습니다. 두 컴포넌트의 시그니처(`CounterViewPanel({ items })`,
`ResearchCoveragePanel({ assetId })`)는 그대로이며, 컴포넌트 내부 `Card`에
`h-full`을 추가한 부분도 설계 문서 3절 마지막 항목("이동한 2열 행의 카드는
좌우 높이 균형을 위해 h-full을 적용")과 일치합니다.

**deep-link 앵커 영향 없음** — `researchSectionIds`(78행)는
`briefing`·`risks`·`news`·`checklist` 4개만 정의하고 있고,
`CounterViewPanel`·`ResearchCoveragePanel`은 애초에 `id`를 갖지 않는
비앵커 컴포넌트입니다. 두 컴포넌트가 이동해도 딥링크 대상 4개 섹션은
그대로 aside(briefing·risks)와 하단 4열 행(news·checklist)에 남아 영향이
없습니다.

**h-full 부작용 없음** — `grep -rn "CounterViewPanel\|ResearchCoveragePanel"
src/`로 확인한 결과 두 함수는 `ResearchPage.tsx` 안에서만 정의·호출되는
모듈-프라이빗 컴포넌트로, export되지 않고 다른 페이지·컴포넌트에서
재사용되지 않습니다. 따라서 내부 `Card`에 `h-full`을 고정해도 이번 PR
범위 밖에서 부작용이 생길 여지가 없습니다.

**md 브레이크포인트 일관성** — 신설 2열 행은 `md:grid-cols-2`만 쓰고,
차트+aside 열은 `xl:` 미만에서 단일 열로 쌓이며, 기존 하단 4열 행은
`md:grid-cols-2 xl:grid-cols-4`입니다. 즉 md~xl 구간에서는 차트·aside가
세로로 쌓인 뒤, 2열짜리 반대 관점/커버리지 행과 2열짜리 하단 행이 동일한
규칙으로 이어지는 구조입니다. 신설 행은 기존 하단 행이 이미 쓰던 첫
브레이크포인트를 그대로 확장한 것이라 새로운 비일관성이 생기지 않습니다.

**테스트** — DOM 순서에 의존하는 기존 테스트
(`renders counter views below the AI briefing`, 1080행)는
`compareDocumentPosition`으로 "브리핑 헤딩보다 반대 관점 헤딩이 뒤에
있는지"만 검증하며, 절대 위치(aside 내부 vs 하단 행)에는 의존하지
않으므로 이동 후에도 유효합니다. `pnpm test -- --run
src/pages/ui/ResearchPage.test.tsx`를 재실행해 44개 테스트 전부 통과를
직접 확인했습니다. 설계 문서 5절이 요구한 "반대 관점·커버리지가 여전히
렌더되는지 확인하는 수준"은 기존 테스트로 충족되며, 신규 테스트가
추가되지는 않았습니다.
