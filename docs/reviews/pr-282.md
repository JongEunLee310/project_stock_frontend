# PR #282 로컬 리뷰 — 토픽 액션 체크리스트 골격 (#270)

## Review Summary

토픽 상세 "액션 체크리스트"(§5.12) placeholder를 실제 위젯으로 교체한 PR입니다. 단일 커밋(`feat: 토픽 액션 체크리스트 골격 구현`)이며, 이 PR로 토픽 상세 페이지의 placeholder가 모두 소진되어 전량 라이브가 됩니다.

`TopicActionChecklist` 위젯(신규)은 분석에서 사용자 행동으로 이어지는 마무리 레이어(골격)로, `topicId`와 `affectedSymbols`(리서치 이동용)를 받습니다. 액션을 두 부류로 나눠 정직하게 표기합니다.

**활성 액션(기존 라우트 이동).** 관련 종목 리서치(첫 `affectedSymbols` 종목의 `/research/:symbol`, `generatePath` 사용)·포트폴리오(`/portfolio`)·판단 기록(`/decision-log`)·변화 알림(`/alerts`). 영향 종목이 없으면 리서치 액션을 비활성("종목 없음")으로 둡니다.

**준비 중 액션(BE 미비, 비활성).** 관심 토픽 팔로우(영속화 API 없음)·유사 토픽/버전 비교(BE 골격 미구현). 비활성 버튼 + "준비 중" 배지·툴팁으로 두고, 설명에서 서버 기능 준비 중임을 밝힙니다. 영속화 없는 가짜 팔로우 상태를 만들지 않고, 직접 매수·매도 버튼도 두지 않습니다(§5.12).

페이지는 `actionChecklist` placeholder를 위젯으로 교체하면서 마지막 `plannedPanels` const와 `PlannedPanelCard` import를 제거했습니다. 이로써 토픽 상세 페이지는 placeholder 0개가 됩니다.

이번 리뷰는 BE 미비 기능의 정직한 "준비 중" 처리(가짜 상태 금지), 매수·매도 버튼 부재, 종목 없음 비활성, 기존 라우트만 사용, 페이지 placeholder 정리를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 활성 액션과 헤더 버튼의 중복 — 설계 의도로 허용.** 알림 생성·판단 기록 연결은 `TopicSummaryHeader` 상단 액션 버튼과 액션 체크리스트에 모두 있습니다. 디자인(topic-insight.png)이 상단 quick action과 하단 guided checklist를 함께 두므로 의도된 중복이며, 체크리스트는 흐름·설명을 곁들인 안내 역할을 합니다. 병합을 막지 않습니다.

**S2. 포트폴리오·알림 이동이 토픽 비특정 — 골격 단계에서 허용.** 포트폴리오·알림 액션은 토픽 컨텍스트 없이 해당 화면으로 이동합니다. 토픽별 사전 필터·prefill은 BE·기능 확장이 필요한 후속 사항이고, 이 이슈가 골격임을 감안하면 화면 진입점 제공으로 충분합니다.

## Questions

**Q1. 준비 중 액션의 정직성.** 팔로우·유사/버전 비교는 BE 엔드포인트가 없어 비활성 "준비 중"으로 처리됩니다. 로컬 state로 팔로우된 것처럼 보이게 하지 않아, 영속화 없는 가짜 상태·오해를 방지함을 확인했습니다. BE(팔로우 API·#373 골격) 구현 시 활성화하면 됩니다.

## Final Recommendation

머지 가능합니다. 핸드오프 요구사항을 항목별로 확인했습니다. 이동 액션(리서치·포트폴리오·판단기록·알림)의 기존 라우트 연결, 영향 종목 없음 시 리서치 비활성, BE 미비 항목(팔로우·유사/버전 비교)의 "준비 중" 비활성 처리(가짜 상태·매수/매도 버튼 없음), 활성/준비 중의 텍스트 배지 구분, placeholder 전량 소진(토픽 상세 라이브 완성)이 모두 확인됩니다.

범위는 지켜졌습니다. 팔로우 영속화·유사/버전 비교 실구현(BE 필요)과 폴링(#266)에는 손대지 않았습니다. Protected Files는 없으며 신규 npm 의존성 추가도 없습니다. 추가된 테스트는 위젯의 활성 액션 네비게이션·종목 없음 비활성·준비 중 표기, 토픽 상세 페이지의 placeholder 교체를 덮습니다.

Blocking은 없습니다. S1·S2는 설계 의도·골격 범위 사항으로 병합을 막지 않으며, Q1은 준비 중 처리의 정직성을 확인해 해소했습니다.

최종 머지 권한은 개발자에게 있습니다.
