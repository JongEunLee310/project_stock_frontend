# PR #124 — 관심 종목 페이지 UI 폴리시 (feat/123-watchlist-ui-polish)

리뷰어: Claude Code (Sonnet / Value-for-Fable). 구현: Codex. 브랜치: feat/123-watchlist-ui-polish → main. 관련: FE #123, 설계 docs/designs/123-watchlist-ui-polish.md, 핸드오프 .codex/tasks/task-048-watchlist-ui-polish.md.

## Review Summary

이슈 #123이 요청한 시각 개선 3건 — 툴바 한 줄 배치, 테이블 헤더 가운데 정렬, 배지 리디자인 — 이 설계 Decisions §1–3의 명세를 그대로 따라 구현되었습니다.

변경 파일은 `src/features/watchlist/adapters.ts`, `src/features/watchlist/adapters.test.ts`, `src/pages/ui/WatchlistPage.tsx` 세 개이며 docs 파일 2개(설계 문서·핸드오프)가 추가됩니다.

핵심 메커니즘은 다음 세 층으로 구성됩니다.

**툴바 재구성(§1)**: Card 안의 그리드+별도 버튼 그룹 구조를 단일 `flex flex-wrap items-center gap-2` 컨테이너로 교체했습니다. 검색 Input에 `min-w-[14rem] max-w-sm flex-1`을, select 3종에 `w-auto`를 부여하고, 버튼 그룹의 첫 버튼(정렬 방향)에 `ml-auto`를 추가해 우측 정렬합니다. 컨트롤 높이는 `min-h-11` → `min-h-9`, Card 패딩은 `p-4` → `p-3`으로 줄었습니다. ⌕ 아이콘의 `top-2.5` → `top-1.5`도 이에 맞게 조정되었습니다. 검색·필터 핸들러, aria-label, `setPage(1)` 리셋은 모두 변경 없이 유지됩니다.

**헤더 정렬(§2)**: th 공통 클래스의 `text-left`를 `text-center`로 교체했고, 배지 셀 5개(상태·뉴스위험도·밸류에이션·테마과열·AI판단)에 `text-center`를 추가했습니다. 로딩 Skeleton에 `mx-auto`, 에러·null 셀에도 `text-center`가 붙어 모든 상태에서 정렬이 일관됩니다.

**배지 리디자인(§3)**: `evaluationBadgeClassNames`의 기존 pill 스타일(`border-*/50 bg-*/15 text-*-200`)을 soft tint 스타일(`bg-*/10 text-*-300`)로 교체하고, `evaluationBadgeDotClassNames`(tone → `bg-*-400`)를 신규 추가했습니다. resolver 5종의 반환 타입이 `{ label, className, dotClassName }`으로 확장되었으며, `resolveStatusBadge`는 `stockStatusClassNames` import를 제거하고 내부 톤 매핑(safe/warning/danger)을 직접 사용합니다. `WatchlistPage.tsx`에는 `TableBadge` 인라인 컴포넌트(`<span aria-hidden="true" ...>` dot + 라벨 텍스트)가 추가되어 상태 배지와 `EvaluationBadgeCell`의 렌더링을 통일합니다.

설계 Verified Facts에서 명시한 `stockStatusClassNames`의 다른 소비처(`Badge.tsx`, `Badge.test.tsx`, `shared/ui/index.ts`)는 `stockStatus.ts` 파일이 수정되지 않아 영향이 없습니다.

## Suggestions

**S1 · `text-*-300 on bg-*-500/10` 대비 — 접근성 후속 트래킹 권장 (비차단)**

기존 스타일(`text-*-200 on bg-*-500/15`)보다 전경색이 약간 어두워지고 배경 불투명도도 낮아졌습니다. 설계 §3에서 의도적으로 낮은 시각 위계를 선택한 것이므로 기능적·설계적 문제는 아닙니다. 다만 다크 테마에서 WCAG AA(4.5:1) 충족 여부를 공식 대비 검사 도구로 확인한 기록이 없으므로, 후속 접근성 이슈로 트래킹해 두는 것을 제안합니다.

**S2 · `resolveStatusBadge`와 `evaluationBadgeClassNames` 선언 순서 (비차단, 가독성)**

`adapters.ts` 내에서 `resolveStatusBadge` 함수 선언이 `evaluationBadgeClassNames` const 선언보다 앞에 위치합니다. TypeScript 모듈 초기화 이후 함수가 호출되므로 런타임 오류는 없고 tsc·테스트 모두 통과합니다. 다만 코드를 위에서 아래로 읽는 독자에게 참조 방향이 역순으로 보일 수 있습니다. `evaluationBadgeClassNames`·`evaluationBadgeDotClassNames` 블록을 `resolveStatusBadge` 위로 이동하면 가독성이 개선됩니다. 동작에 영향이 없으므로 블로커는 아닙니다.

## R1 재리뷰 (배지 인디케이터 분화)

리뷰어: Claude Code (Sonnet / Value-for-Fable). 대상 커밋: c27ea24. 범위: 1차 리뷰(R0) 이후 R1 델타만 재검토합니다.

### R1 명세 일치

설계 R1 절의 톤별 인디케이터 표와 구현을 대조했습니다.

| tone | 명세 | 구현 |
|---|---|---|
| danger | glyph `⚠︎` (U+26A0+U+FE0E), `text-rose-400` | `evaluationBadgeIndicators.danger` — 동일 |
| warning | glyph `!`, `text-amber-400 font-bold` | `evaluationBadgeIndicators.warning` — 동일 |
| safe | dot, `bg-emerald-400` | `evaluationBadgeIndicators.safe` — 동일 |
| neutral | dot, `bg-slate-400` | `evaluationBadgeIndicators.neutral` — 동일 |

glyph span의 크기는 `text-[11px]`로 명세(배지 텍스트보다 작거나 같게)를 충족합니다. dot과 glyph 모두 `aria-hidden="true"`가 유지되어 상태 의미는 라벨 텍스트로만 전달됩니다. 라벨·톤 배경/텍스트 클래스(`evaluationBadgeClassNames`)·폴백 규칙은 R1 diff에서 변경되지 않았습니다.

### U+FE0E 변형 선택자 확인

`src/features/watchlist/adapters.ts`와 `adapters.test.ts` 두 파일 모두에서 `⚠︎` 문자열이 실제로 `e2 9a a0 ef b8 8e`(U+26A0 + U+FE0E) 바이트 시퀀스로 저장되어 있음을 바이너리 검사로 확인했습니다. 변형 선택자가 소스에 포함되어 있어 이모지 렌더링이 방지됩니다.

### dotClassName → indicator 마이그레이션 완전성

`src/features/watchlist/` 및 `WatchlistPage.tsx`에서 `dotClassName` 잔존 참조가 없음을 확인했습니다. `WatchlistBadgeIndicator` 판별 유니온 타입이 `adapters.ts`에서 export되고 `WatchlistPage.tsx`의 `TableBadgeProps`·`EvaluationBadgeCellProps` 인터페이스가 이를 직접 참조합니다. `evaluationBadgeIndicators`는 `as const`로 선언되어 `kind` 필드가 리터럴 타입으로 좁혀지며 타입 단언 약화가 없습니다.

### 테스트

`adapters.test.ts`에 `dangerIndicator`·`warningIndicator`·`safeIndicator`·`neutralIndicator` 픽스처가 추가되어 resolver 5종 단언이 `toEqual`로 인디케이터 객체 전체를 비교합니다. danger=`⚠︎`·warning=`!`·safe/neutral=dot 단언이 모두 존재합니다. `// app/domains/signals/types.py:4-13`, `// app/domains/watchlists/types.py` 출처 주석은 그대로 유지됩니다.

### Suggestions

**S3 · 설계 문서 Components 절 R1 갱신 권장 (비차단)**

`docs/designs/123-watchlist-ui-polish.md`의 `## Components` 절에 `evaluationBadgeDotClassNames` 추가와 `dotClassName` 확장이 R0 기준으로 기술된 채 남아 있습니다. R1 절이 명시적으로 추가되었으나 Components 절은 R1 내용(인디케이터 분화, `evaluationBadgeIndicators`, `indicator` 필드)을 반영하지 않아 차후 독자에게 혼동을 줄 수 있습니다. 설계 문서 Components 절을 R1 기준으로 갱신하거나 "R1에서 대체됨" 주석을 달아 두기를 권합니다. 동작과 무관하므로 블로커는 아닙니다.
