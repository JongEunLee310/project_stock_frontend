구현자: Codex(gpt-5.6-sol, effort high), 커밋 `404bce1`

## Review Summary

이슈 #137에서 보고된 리서치 화면 전체 차단 버그를 수정합니다. `useResearchView`가 내부적으로 다섯 개의 API를 `Promise.all`로 병렬 호출하는데, 그 중 `/theses/latest?asset_id={id}`가 투자 가설 미존재 시 `THESIS_NOT_FOUND` 에러 코드가 담긴 404 envelope를 반환하면 `apiGet`이 `ApiError`를 던지고 `Promise.all` 전체가 reject되어 리서치 화면이 ErrorState로 떨어졌습니다.

수정 방식은 설계 문서(`docs/designs/137-research-thesis-404-fix.md`)가 지정한 대로입니다. `fetchLatestThesis(assetId: number): Promise<ThesisDto | null>`을 신설해 `THESIS_NOT_FOUND` 코드의 `ApiError`만 `null`로 흡수하고, 나머지 오류는 그대로 다시 던집니다. `useResearchView`의 `Promise.all` 다섯 번째 항목을 인라인 `apiGet` 호출에서 이 함수로 교체하는 것이 변경의 전부입니다. 어댑터(`adaptResearchDetail`)와 DTO는 이미 `thesis: ThesisDto | null`을 받으므로 추가 변경이 없습니다.

핵심 설계 판단은 오류 식별 방법에 있습니다. HTTP 상태 코드(404)가 아니라 `ApiError.code === 'THESIS_NOT_FOUND'` 리터럴로 판별하는데, 이는 BE `app/core/error_codes.py`의 `ErrorCode.THESIS_NOT_FOUND` 값과 정확히 일치하며 설계 문서가 명시한 방식입니다.

## Suggestions

**S1. 테스트 픽스처에서 `unwrapEnvelope`를 직접 호출하는 방식이 의도보다 간접적입니다**

현재 `thesisNotFoundEnvelope`에 `unwrapEnvelope`를 호출해 mock이 throw를 일으키도록 구성되어 있습니다. `unwrapEnvelope`가 `error` 필드를 보고 `throw new ApiError(...)` 를 일으킨다는 사실을 알아야 코드를 읽을 수 있어, 픽스처의 의도가 한 단계 감춰집니다. `vi.fn().mockRejectedValue(new ApiError('THESIS_NOT_FOUND', '...'))` 형태로 직접 mock하면 의도가 더 명확해집니다. 다만 현재 테스트도 기능적으로 정확하게 동작하며, 기존 테스트 파일의 관례(`unwrapEnvelope` 경유)와 일관될 수 있으므로 비차단 제안입니다. 심각도: 비차단·저비용 개선.

**S2. `fetchLatestThesis`가 `apiGet<ThesisDto | null>`로 호출하지만 성공 시 `data`가 항상 `ThesisDto`입니다**

BE는 가설이 있으면 `ThesisDto` 객체를, 없으면 404 에러 envelope를 반환합니다(200 + `data: null`은 없는 계약). 따라서 `apiGet<ThesisDto>`로 충분하며, `<ThesisDto | null>` 타입 인자는 실제 성공 응답에 null이 올 수 없는 상황에서 의미 없는 허용 범위를 추가합니다. 함수 반환 타입(`Promise<ThesisDto | null>`)은 올바르고 null은 catch 블록이 생성하는 것이므로, 타입 인자만 `apiGet<ThesisDto>`로 조이면 계약이 더 정확해집니다. 심각도: 비차단·저비용 개선.
