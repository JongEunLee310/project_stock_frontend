# PR #283 로컬 리뷰 — 패널별 폴링 갱신·데이터 신선도 표시 (#266)

## Review Summary

뉴스·공시 인사이트 전 패널에 차등 폴링 갱신을 배선하고 패널별 데이터 신선도("N분 전")를 개별 표기하며 백그라운드 refetch 점멸을 최소화한 PR입니다. SSE 전 단계이며 단일 커밋(`feat: 패널별 폴링과 데이터 신선도 표시 추가`)입니다. 이 PR로 뉴스·공시 인텔리전스 1·2·3차 FE가 완성됩니다.

`src/features/news-insights/queries.ts`에 `newsInsightsRefetchIntervals` 상수를 중앙화하고 15개 query 전부에 성격별 `refetchInterval`과 `placeholderData: keepPreviousData`를 적용했습니다. 갱신 주기는 피드 45초, 상단 요약·브리핑(overview)·에이전트 파이프라인 60초, 토픽 맵·이벤트 상세·토픽 상세/추이/근거/민감도/관계망/시나리오/설명 5분, 투자자 수급·자금 흐름 전망·캘린더 30분으로 스펙 §6.4 가이드를 따릅니다.

신선도 표시를 위해 `src/shared/lib/format`에 `formatRelativeTime(updatedAtMs, now?)`(방금 전·N분 전·N시간 전·N일 전, 미래·NaN 방어)을, `src/shared/ui`에 `PanelFreshness`(props `updatedAt?`)를 신설했습니다. `PanelFreshness`는 `<time dateTime>`과 aria-label로 접근성을 확보하고 60초마다 라벨을 자체 갱신하며 유효 타임스탬프가 없으면 렌더하지 않습니다.

17개 라이브 패널이 각자 query의 `dataUpdatedAt` 기준으로 개별 신선도를 표시합니다. 자기 query를 내부 호출하는 위젯(InvestorFlowPanel·FundFlowOutlookPanel·FundFlowScenarioPanel·InsightExplanationPanel·TopicKeywordGraph·TopicSymbolSensitivity·MarketEventTimeline·AgentPipelinePanel)은 직접 읽고, page가 query를 소유하는 위젯(InsightSummaryCards·RealtimeEventFeed·AgentBriefing·TopicMap·TopicSummaryHeader·TopicInsightSummary·TopicTrendChart·TopicEvidenceList·CounterViewPanel)은 `NewsInsightsOverviewPage`·`TopicInsightDetailPage`에서 `updatedAt` prop으로 내려받습니다.

이번 리뷰는 주기 차등의 중앙화, 패널별 신선도(단일 동기화 표시 금지) 준수, keepPreviousData 점멸 최소화, 다수 위젯 prop 추가에 따른 회귀를 축으로 봤습니다.

## Blocking

None.

## Suggestions

**S1. 피드의 "최신 {시각}"과 "N분 전" 병존 — 의미가 달라 허용, 라벨 명확화 여지.** `RealtimeEventFeed`는 최신 이벤트의 발행 시각("최신 09:42", 콘텐츠)과 데이터 신선도("N분 전", `PanelFreshness`)를 함께 표시합니다. 전자는 데이터 내용, 후자는 fetch 시점으로 의미가 다르며 스펙이 금지한 전 화면 단일 동기화 표시가 아닙니다. 다만 사용자에게 두 시각의 차이가 헷갈릴 수 있어, 필요하면 라벨을 "최신 이벤트"·"갱신"으로 더 명확히 하는 후속을 고려할 수 있습니다. 병합을 막지 않습니다.

**S2. overview query가 요약·브리핑을 공유해 60초로 통일 — 계약 구조상 합리.** 스펙은 요약 60초·브리핑 5~15분을 제시하나 둘은 같은 `/overview` 응답이라 한 query로 묶여 60초로 갱신됩니다. 브리핑이 필요보다 자주 갱신되지만 무해하며, 분리하려면 BE 계약 분할이 필요합니다. 현재 구조에서 합리적 선택입니다.

## Questions

**Q1. keepPreviousData와 부분 실패 격리.** 전 query에 `placeholderData: keepPreviousData`를 적용했습니다. 백그라운드 refetch가 실패해도 이전 데이터가 유지되어 점멸이 줄지만, 각 위젯의 `isError` 분기와 충돌하지 않는지 확인했습니다. react-query v5에서 refetch 실패 시 `isError`가 서고 `data`는 이전 값을 유지하므로, 위젯은 기존 error 상태 처리를 그대로 따르고 초기 로드 실패와 백그라운드 실패가 각각 적절히 표현됩니다. 부분 실패 격리가 유지됩니다.

## Final Recommendation

머지 가능합니다. 핸드오프 요구사항을 항목별로 확인했습니다. 15개 query의 중앙 상수 기반 차등 `refetchInterval`(전 패널 동일 주기 아님), 17개 라이브 패널의 `dataUpdatedAt` 기준 개별 "N분 전" 표기(전 화면 단일 동기화 표시 없음), `keepPreviousData`를 통한 점멸 최소화, 신규 `formatRelativeTime`·`PanelFreshness`의 접근성 처리가 모두 확인됩니다.

범위는 지켜졌습니다. SSE 스트림 연결·갱신 주기 조절 UI에는 손대지 않았고 BE 계약·신규 query 추가도 없습니다. Protected Files는 없으며 신규 npm 의존성 추가도 없습니다. 자기 query 위젯과 prop-driven 위젯 모두에 신선도를 배선하면서 다수 위젯의 prop 추가에 맞춰 기존 테스트 mock을 동기화했고, 전체 837 tests가 통과합니다. 추가된 테스트는 `formatRelativeTime` 경계, `PanelFreshness` 렌더, query 설정, 페이지 신선도 노출을 덮습니다.

Blocking은 없습니다. S1·S2는 라벨 명확화·계약 구조 사항으로 병합을 막지 않으며, Q1은 keepPreviousData와 부분 실패 격리의 양립을 확인해 해소했습니다.

최종 머지 권한은 개발자에게 있습니다.
