# PR #297 로컬 리뷰 — 뉴스 인사이트 패널 밀도를 설계에 맞춤 (#296)

## Review Summary

뉴스 인사이트 위젯이 공통으로 달고 있던 장식을 걷어내 설계 이미지의 밀도에 맞춘 PR입니다.
단일 커밋(`뉴스 인사이트 패널 밀도를 설계에 맞춘다`)이며, 위젯 19개와 공용 컴포넌트 1개,
페이지 2개, 테스트를 건드립니다. diff는 420줄 삭제·281줄 추가로 순 139줄이 줄었습니다.

문제의 성격이 개별 패널 결함이 아니라는 점이 이번 작업의 전제입니다. 뉴스 인사이트 위젯
19개가 예외 없이 `영문 eyebrow + 제목 + 설명 문장` 3줄 머리말을 달고 있었고, 목록 항목은
`rounded-control border border-app-border bg-app-surface-muted/40 p-3` 박스로 감싸여 패널
카드 안에 항목 카드가 들어가는 구조였습니다. 설계 패널에는 제목 한 줄과 우상단 컨트롤
하나뿐이고 항목은 구분선으로 나뉩니다. 위젯 골격을 처음 정할 때의 형태가 그대로 복제된
결과이므로 공통 규칙으로 고쳤습니다.

수정은 세 갈래입니다. 첫째, `src/shared/ui/PanelHeader.tsx`를 새로 만들어 머리말 규칙을 한
곳에 뒀습니다. 제목 `id`와 우상단 컨트롤 슬롯을 갖고, 설명 문장은 선택 슬롯이되 기본은
없습니다. 둘째, 위젯 19개의 머리말을 이 컴포넌트로 교체하며 eyebrow와 설명 문장을
제거했습니다. 셋째, 목록 항목의 테두리 박스를 `divide-y` 구분선으로 평탄화했습니다.

이번 리뷰는 정보 손실 여부, 접근성 연결 유지, 리팩터링이 남긴 죽은 코드, 예외 처리의
타당성을 축으로 봤습니다.

## Suggestions

**S1. 설명 문장을 남긴 패널이 하나도 없다 — 결과적으로 타당, 근거를 남겨 둠.** 핸드오프는
"제목만으로 뜻이 서지 않는 패널에만 남기라"고 했고 결과는 전부 제거입니다. 전수 확인한 결과
제목이 이미 충분히 구체적이었습니다(`투자자 동향`·`예상 자금 흐름`·`관련 종목 민감도` 등).
설명 문장이 담고 있던 내용은 대부분 제목의 부연이거나 패널이 이미 보여 주는 값의 서술이었고,
`시장 전체의 투자 주체별 순매수·순매도와 뉴스 내러티브의 방향을 비교합니다` 같은 문장은
아래 표와 정렬 배지가 그대로 보여 줍니다. 정보 손실이 아니라 중복 제거입니다. 다만 향후 뜻이
서지 않는 패널이 생기면 `PanelHeader`의 `description` 슬롯을 쓰면 됩니다. 슬롯은 남겨 뒀습니다.

**S2. `NewsEventHeader`가 정리 대상에서 빠졌다 — 범위 밖, 후속 정리 여지.** 이벤트 상세
화면의 `NewsEventHeader`는 핸드오프 목록에 없어 항목 테두리 박스가 하나 남았습니다. 같은
화면의 다른 세 위젯(`NewsEventAffectedSymbols`·`NewsEventEvidenceList`·
`NewsEventRelatedTopics`)은 정리됐으므로 그 화면 안에서 표현이 어긋납니다. eyebrow는 없어
크게 튀지는 않습니다. 다음 밀도 작업에 묶어 정리하면 됩니다.

**S3. `PanelHeader`가 `h2`로 고정돼 있다 — 현 사용처에서는 문제없음.** 모든 패널이 카드 안의
최상위 제목이라 `h2`가 맞습니다. 다만 중첩 구조에서 `h3`가 필요해지면 태그를 열어야 합니다.
지금 필요하지 않은 유연성이므로 추가하지 않는 편이 맞습니다.

## Questions

**Q1. 표시되던 정보가 사라졌는가.** 확인해 해소했습니다. 지워진 것은 영문 eyebrow, 패널 설명
문장, 항목을 감싼 테두리·배경뿐입니다. 근거 서술·가정·위험 요인·반대 관점의 본문, 제목,
배지, 수치는 모두 남아 있습니다. `ErrorState`·`EmptyState`의 설명 문구도 유지됐습니다.
전수 검색으로 확인한 결과, 남아 있는 `description=` 사용처는 전부 오류·빈 상태의 설명이고
패널 머리말 설명은 0건입니다. 테스트 845건이 모두 통과하며, 본문 텍스트를 단언하던 기존
테스트가 그대로 통과한다는 점도 정보 손실이 없다는 근거입니다.

**Q2. 접근성 연결이 끊기지 않았는가.** 확인해 해소했습니다. `PanelHeader`가 `titleId`를 받아
`h2`에 그대로 붙이므로 각 `Card`의 `aria-labelledby`가 유지됩니다. 로딩 상태의
`role="status"`, `sr-only` 안내, 오류 상태의 재시도 버튼도 그대로입니다. `PanelHeader` 자체
테스트가 제목과 패널의 연결, 컨트롤 렌더, 설명 없는 기본 동작을 덮습니다.

**Q3. 리팩터링이 죽은 코드를 남기지 않았는가.** 확인했고 두 건을 찾아 리뷰어가 직접
정리했습니다. `InvestorFlowPanel.context`와 `TopicActionChecklist.topicId`는 **제거된 설명
문장에서만 쓰이던 prop**이었습니다. Codex는 컴포넌트 본문에서 사용을 지웠지만 인터페이스와
호출부에는 그대로 남겨 두어, 두 페이지가 여전히 긴 문자열을 넘기지만 아무 데도 쓰이지 않는
상태였습니다. 타입 검사로는 잡히지 않는 종류입니다. 인터페이스·호출부·테스트에서 모두
제거했습니다.

**Q4. 브라우저에서 실제 밀도가 어떻게 보이는지.** 해소하지 못했습니다. 이 환경에는 렌더링을
확인할 수단이 없어 마크업과 diff 규모로 판단했습니다. 세로 길이가 실제로 얼마나 줄었는지는
개발자가 화면에서 확인해 주시는 편이 확실합니다.

## Final Recommendation

머지 가능합니다. 핸드오프의 요구를 항목별로 확인했습니다. 뉴스 인사이트 위젯에 영문 eyebrow가
0건 남았고, 목록 항목이 구분선으로 나뉘며, 접근성 속성과 로딩·오류·빈 상태·`PanelFreshness`·
패널 단위 부분 실패 격리가 모두 유지됩니다.

범위는 지켜졌습니다. `TopicSummaryHeader`는 #295가 다루므로 건드리지 않았고, 뉴스 인사이트
밖의 위젯과 `AlertsPage`·`SettingsPage`의 eyebrow도 그대로입니다. 배치·그리드, 데이터
바인딩, 계약, 시각화 형태는 변경되지 않았습니다. Protected Files는 없습니다.

테스트는 `PanelHeader`의 제목 연결과 컨트롤 렌더를 새로 덮고, 기존 위젯 테스트는 새 구조에서
그대로 통과합니다. 셀렉터가 깨졌다는 이유로 삭제된 단언은 없습니다. 테스트에서 제거된 것은
죽은 prop을 넘기던 인자 세 개뿐이며, 이는 단언이 아니라 렌더 인자입니다.

Blocking은 없습니다. S1은 전수 확인으로 타당함을 확인했고, S2는 다음 밀도 작업에 묶을 후속
사항이며, S3은 지금 필요하지 않은 유연성입니다. Q1·Q2는 확인해 해소했고, Q3은 리뷰 중 직접
정리했으며, Q4는 렌더 확인 수단이 없어 개발자 확인이 필요한 항목으로 남깁니다.
